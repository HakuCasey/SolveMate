# 本地数据备份与恢复设计

## 数据与职责

本机备份服务读取现有业务存储，通过 SQLite backup API 生成一致的数据库副本，再打包资料文件。ZIP 中的 manifest.json 保存格式版本、创建时间、文件长度与 SHA-256；归档只允许 app.sqlite3、ai/state.sqlite3、ai/workspace、uploads、community 这些相对路径。备份目录不递归收入归档。

备份与恢复共用维护锁。普通请求仍可并发；进入维护前等待已有请求结束，维护期间拒绝新业务请求。后台问答、连接检测、资料转换未完成时提示稍后重试，不中断这些操作。

恢复先解包校验，用户确认后自动保存当前完整 ZIP。关闭现有存储，按现有配置路径替换文件，重新打开业务服务。替换记录写入 user/backups，失败或进程中断按记录恢复原文件。恢复完成后保留当前存储身份并提高保存版本，避免其他窗口以旧版本覆盖；对象编号与第三方会话编号保持原值。

网页复用导出窗口的文件名、保存位置、进度和结果反馈。恢复窗口显示备份时间和覆盖说明，确认后统一刷新各模块；不在页面分别修改各模块的数据。

## 发布数据目录

当前默认位置继续为项目根目录的 user。SOLVEMATE_USER_DIR 已支持将运行数据保存到其他目录；归档条目使用相对路径，恢复时写入目标实例配置的数据目录。AI 配置与绑定中保存的路径信息仍保留，程序是否可用、能否恢复原生会话由适配器在使用时确认。面向最终用户的默认位置、目录选择以及发布包与个人数据的分离仍需在发版前确定。
