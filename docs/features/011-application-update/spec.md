# 011 应用更新提示与重载保护

## 背景与目标

页面使用本地缓存打开，更新检测和下载在后台进行。用户需要随时知道是否发现新版、是否已准备完成，也需要主动检查和明确的失败反馈。

## 行为与验收

- 正式网页右下角状态栏的应用更新列保留“检查更新”入口，点击后显示更新气泡。打开页面时检查，恢复网络时重查；返回页面时至少间隔一分钟再查，持续打开时每小时检查一次。
- 状态栏按实际进度显示“正在检查…”“正在下载…”“新版就绪”“正在更新…”或“更新失败”。没有新版时常驻“检查更新”，气泡内显示“已是最新版本”；检测和下载过程中不重复发起操作。
- 只有服务端检查成功且没有新版本等待或下载时，才显示已是最新版本。离线、服务不可达、错误响应、下载失败或超时分别显示错误，允许重试，保留已有离线版本。
- 新版准备好后轻提示一次，右下角自动高亮“新版就绪”，无需打开气泡或手动检查才能看到。气泡中的“更新应用”按钮用于启用新版；其他窗口启用新版时，本页仅提示，不自动重载。
- 重新加载前保存当前窗口的输入草稿、已添加引用、阅读滚动、PDF 缩放、答案展开和最后阅读位置。更新后仍进入对话页；打开原资料或返回对话时恢复这些记录。
- 本地记录正在保存、保存失败，或机器人配置尚未保存时，明确提示并保留当前页面。临时状态写入失败时停止重载，不丢弃草稿。
- 更新不主动停止 AI 执行。已保存的运行编号由现有恢复流程重新订阅，本机服务继续处理原请求。
- “安装应用”仅在浏览器提供安装提示时出现在应用更新气泡中，不另占状态栏。安装不与检查更新或课程内容更新混用。普通刷新或关闭后的全面现场持久化不在本特性范围内。

更新被记录保存失败阻止时，应用更新气泡显示具体保存错误及“重试保存”，成功后清除过期提示，允许继续更新；存在修改冲突时直接提供“处理修改冲突”入口，打开现有冲突核对窗口。不得只提示用户重试而不提供入口，也不能因重试保存而自动重载网页。

用户点击“更新应用”后，等待新版实际接管当前页面再刷新一次，不以 Service Worker 的 activated 事件单独判定接管完成。其他窗口只提示新版就绪，不自动刷新。一次代码修改完成后集中构建，避免连续发布中间结果而要求用户重复更新。
