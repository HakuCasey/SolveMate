# 009 主题配色集中管理

## 背景与目标

应用提供日间、夜间模式。公共颜色已有 CSS 变量，聊天气泡、错误提示、纸页装饰和弹窗阴影还存在组件内定义。主题配色需要统一管理，使后续增加主题时可以覆盖相应区域。

本特性属于共用界面实现，覆盖资料阅读、对话、笔记、机器人和设置，不改变各业务模块的职责。

## 当前范围

- 将界面颜色集中到默认主题，组件使用按用途命名的 CSS 变量。默认主题提供完整的日间和夜间配色。
- 配置范围包括背景、文字、边框、强调色、状态提示、两类聊天气泡、代码区域、阅读选区、笔记纸页及装饰、遮罩与阴影颜色。热图继续依据强调色生成深浅。
- 明暗模式与主题编号分别表达。当前界面使用默认主题，仍通过原有显示设置切换明暗；保存字段和旧数据读取方式保持兼容。
- 定义可供后续使用的主题格式和应用函数：缺少颜色使用相同明暗模式的默认值；非法值不进入页面样式，返回具体校验结果并记录英文日志；切换时不残留上一主题的颜色。
- 首屏、个人设置恢复和后续明暗切换使用同一个应用函数。PWA 安装清单从默认主题取色，页面的浏览器栏颜色随实际背景更新。
- 原始图片、PDF 页面内容和第三方内容的固定颜色不由主题重着色；原件所需的白底集中定义。

## 后续扩展边界

主题格式和应用函数已经提供，主题选择、文件导入、保存主题编号、主题安装与更新尚未开放。布局、字号、圆角、间距、字体、图标和代码语法高亮规则不在本次颜色配置中；扩展这些项目时再确定格式与兼容规则。

## 验收

1. 日间、夜间模式都能覆盖阅读、聊天、笔记、机器人、设置及弹出菜单，保留现有的主配色、气泡与纸页层次。错误文字和危险按钮、同类浮层阴影统一按各自用途取色。
2. “新建学科”仍使用强调色；示例输入提示维持浅色，实际输入使用正文颜色。
3. 通过配置函数使用一份局部配色时，指定颜色生效，其余使用所选模式默认值；切回默认主题后不残留自定义颜色。
4. 覆盖不支持的格式版本、错误元数据、缺少配色、非法颜色和未知字段，保留完整可用的默认颜色及校验结果。
5. 自动核对组件样式不再定义颜色字面值，所有 `--sm-` 变量均有来源；正式构建验证明暗切换与刷新后已保存模式的恢复。
