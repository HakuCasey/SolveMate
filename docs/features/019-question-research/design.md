# 教研工具实现

## 数据与职责

`TeachingTool` 由共享 AI Schema 定义，前后端使用相同字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 工具的稳定编号，另存时生成新编号 |
| `title`、`description` | 发布或创建时的名称与简介 |
| `customTitle` | 可选的本地名称，重命名时保存；社区更新保留 |
| `skill`、`template` | 各自的编号、名称与正文 |
| `source` | 社区或用户自定义 |
| `version` | 社区工具发布文件的 SHA-256 |
| `updatedAt` | 工具更新日期 |
| `suggestions` | 可选的两条任务示例 |

`AppData.questionResearch.tools` 是本地工具目录，随学习记录保存在 `user/app.sqlite3`。`selectedToolId`、`source`、`conversationId` 分别指向当前工具、资料位置和对话。编辑、重命名、安装、选择和删除集中在 `research/state.ts`，`useTeachingTools` 负责下载、校验与统一保存。页面不另外维护安装状态。

为保留现有记录，早期模板目录先转换为工具记录；首次加载时，`initializeTeachingTools` 将完整匹配旧预置内容的条目替换为讲义研发、试题研发、试题精讲，用户修改过的内容保留。首次使用也初始化这三个工具。预置内容与社区发布读取同一组 JSON，使用相同的序列化和 SHA-256 计算版本；已有新版不覆盖，用户删除后的条目不自动补回。工作区 `context` 保留结构兼容，展示与新请求均从已选工具取得内容。对话、用户消息及后端执行中的 `QuestionResearchContext` 则记录发送时的内容，用于历史与重试，不能因工具编辑而回写。

资料继续使用公共阅读位置和读取接口。`QuestionResearchPanel` 管理资料和工具下拉框，`ToolChoiceDialog` 统一处理选择确认、新建和另存，复用资料列表、上传、PDF 阅读器和公共对话栏。社区内容页与工具选择共用 `useTeachingTools`，删除后两处同步。

## 选择与另存

打开工具确认窗口时只建立内存副本，不修改当前选择。教研室与社区内容页复用同一个确认组件。未修改时确认调用 `selectTool`，同时核对用户看到的工具与当前目录一致；修改或新建时先填写名称，再调用 `saveTool`，在同一次提交中添加用户工具并更新 `selectedToolId`。从社区或用户工具另存都由 `customTool` 生成新的工具及 Skill、模板编号，原记录和已发送消息的配置保持不变。取消不提交，失败保留当前输入并允许重试。`saveTool` 只添加新工具；同一编号与内容的重复提交可安全确认，不覆盖已有工具的其他内容。阅读器始终保留在窗口后方，不再切换为工具编辑页面。

## 重命名

资料与工具共用 `RenameDialog`，仅提交名称。工具的 `renameTool` 按编号修改 `customTitle`，`toolTitle` 统一读取本地名称或原名称；当前教研配置同步，已发送消息中的内容保持不变。社区下载的 `installTool` 保留该字段。旧记录缺少字段时沿用原名称，无需迁移。保存前检查名称是否已被另一处修改，失败保留窗口输入；不更改来源、版本和内容更新日期。

## 社区发布

三个预置工具的 Skill 和输出模板统一维护在 `data/tools/`，网页首次初始化与社区发布读取同一份内容。正文调整后重新计算发布版本，已安装的社区工具通过内容更新取得新版；不覆盖用户自定义工具或历史消息中发送时的配置。

`data/tools/<工具编号>.json` 保存社区工具定义，`data/catalog.json` 的 `tools` 列表控制发布。服务先校验所有源文件，再生成不可变版本文件，最后原子替换发布目录。工具和课程各有独立版本，旧版本文件保留。

- `GET /api/v1/tools`：工具目录与版本。
- `GET /api/v1/tools/{id}/versions/{version}/download`：固定版本 JSON。

前端校验 SHA-256、结构与编号后一次提交本地工具目录；请求、校验或保存失败不会先移除已安装工具。用户修改社区工具时生成新的用户工具编号，后续社区更新不会覆盖这份自定义内容。

## Prompt 与会话接收记录

Skill 和输出模板使用简练、明确的语言，优先说明完成任务的方法与结果要求。规则写清适用条件，格式写清章节与条目的排列关系；仅对必要行为设置禁止要求，保留合理的内容组织与创作空间。公共 Prompt、Skill 与输出模板按各自职责维护，避免重复或冲突。

预置 Skill 将编写、出题或讲解的要求放在一组，将核对与修改的要求放在另一组，组内编号，不逐条增加标题。编号用于区分要求，便于核对遗漏，不规定回复顺序；结果仍按所选输出模板及用户本次明确要求组织。

统一 Prompt 位于 `apps/local/src/solvemate_local/prompting.py`，版本 `learning-discussion-v6`。用户问题位于开头，角色要求、关联资料、补充引用及必要历史沿用公共模板；教研工具要求放在历史之后。历史只补发讨论内容，不重新发送历史消息里的旧 Skill、旧模板。

本轮任务以用户明确要求为准。用户提供选段时，选段是任务对象，关联整页只补充术语、代码和前后文，不自动扩大范围；继续修改时沿用已确定的范围，用户明确要求整页或其他内容时按新要求执行。范围说明每轮发送，不受正文接收记录影响；资料、历史、Skill 和模板仍按目标原生会话的接收记录补发。公共模板要求回答说明必要内容，题目和练习须包含独立作答所需的条件、代码和数据，不能仅以资料编号或“见原文”代替；来源标注保留，正常追问继续使用已有上下文，缺失条件不得编造。

固定说明：

> 技能要求和输出模板分别以最近一次提供的内容为准。本轮没有提供的部分，继续沿用此前的内容。

按需附上 `【技能要求】` 和 `【输出模板】`。首次及更新使用同一种结构，不为每种切换情形增加提示模板。

对 Skill、模板正文分别计算摘要，写入本次 `TurnDispatch.instructionKeys`。沿用 `session_receipts`，按原生会话和内容类型各保存最后确认收到的一份摘要；不能按“曾经发过”判断。确认消息接收时，在同一事务内更新接收记录和本次执行状态。无接收确认的失败不会更新摘要。

恢复原生会话后读取它自己的记录；新建原生会话时两项完整发送。各适配器继续只负责各自的通信、恢复和停止，共同的工具发送规则不进入适配器。

## 验证范围

2026-11-17 三个预置工具实测：DSH 与 Hermes 均使用 GLM 5.3、Medium，独立存储与新建专用原生会话。共 3 轮、16 次请求，第三轮仅复测调整过的讲义研发和试题精讲，达到本次场景要求后停止。讲义包含独立代码且按要求省略练习；试题包含两道单选与一道多选，题干可独立作答，题目与答案分区对应；精讲解释局部疑问并纠正错误参考答案。讲义 Skill 明确简化表达保持原意，精讲 Skill 明确延伸范围和操作表述的依据。首轮发现的 Hermes 完成正文重复已在适配层修正，处理约定见 [004](../004-hermes-harness-adapter/design.md#最终正文与流式正文)。55 项本机服务、12 项网页与 2 项社区发布针对性测试通过，已安装 Hermes 的完成处理代码四项重放通过。实测限于 C 语言按值传递场景，不代表全部学科与长会话均已验证；原始请求、工具快照、回复和原生编号保存在私有工作区。

2026-11-17 Prompt 范围验证：使用独立数据目录，分别新建 DSH、Hermes 专用会话，均选择 GLM 5.3。输入 C 语言 PDF 第 5 页、按值传递选段、当前 Skill 和逐题显示答案的模板，要求生成三道选择题。两边均围绕选段出题，使用关联页中的相关代码，没有引入同页的递归内容；达到本次目标后在第 1 轮停止，共 2 次模型请求。18 项 Prompt、教研工具及会话接收记录测试通过。本轮真实测试限于新会话首轮，不代表恢复、停止或上下文压缩已重新实测；请求与完整回复保存在私有工作区。
