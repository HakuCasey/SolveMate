# 020 桌面安装版设计

## 组成

- `apps/desktop/` 使用 Electron 管理窗口、单实例、本机服务和安装包。
- `apps/web/` 继续生成唯一一份界面代码。桌面构建使用 `VITE_DESKTOP=1`，不生成或注册 PWA Service Worker，并把客户端类型记录为 `desktop`。
- `apps/local/` 增加桌面启动入口，由 PyInstaller 按操作系统生成独立目录。桌面程序启动该程序，不调用系统 Python。
- 本机服务从 `SOLVEMATE_WEB_DIR` 提供网页文件，从 `SOLVEMATE_BUNDLED_DATA` 读取随应用提供的基础内容，以 `SOLVEMATE_USER_DIR` 为默认用户目录，按已保存的路径设置打开用户数据。
- `apps/server/` 保持社区内容发布和下载职责，不进入桌面安装包。

桌面程序只加载本机服务提供的页面。页面与 `/local-api/` 使用同一个来源，继续使用现有请求边界，不增加第二套前端数据接口。

## 进程与错误处理

1. Electron 打开随应用打包的本地启动页，检查本机服务端口。
2. 使用操作系统数据目录启动打包后的本机服务。
3. `/healthz` 返回正确的服务标识后，窗口载入学习界面。
4. 启动等待上限为 90 秒，复制数据目录期间收到进度通知会延长等待。启动超时、进程提前退出或端口占用时，可重试或退出。
5. 本机服务直接监控桌面主进程；应用正常退出或异常结束后，本机服务完成收尾并退出。
6. 运行中的本机服务意外退出时允许重新启动，并重新载入原窗口地址。

桌面程序只停止自己启动的本机服务。本机服务仍按现有适配器规则管理每轮 Harness 进程，不结束用户独立启动的 Harness 桌面应用或 Gateway。

## 数据目录

Electron 通过系统 `userData` 目录取得应用数据位置，并将其中的 `data/` 作为本机服务的默认用户目录。安装目录只保存程序、网页、Python 运行环境和基础内容，更新或重新安装不能覆盖个人数据。

源码版与桌面版默认使用同一个系统应用数据目录，并共用[用户数据路径设置](../018-data-backup/spec.md#用户数据路径)。安装包只带预置机器人、社区资料和教研工具；仓库 `user/` 仅保留清空后的开发数据文件组织，不作为运行目录。

## 构建

`npm run desktop:package` 依次构建桌面网页、使用 PyInstaller 生成本机服务，再生成未压缩的桌面应用目录。`npm run desktop:make` 在此基础上生成当前操作系统的安装包。

构建环境需要额外安装 `apps/desktop/requirements-build.lock` 中的 PyInstaller。macOS 和 Windows 必须在各自系统中生成本机服务和安装包，不能在一个系统中交叉生成另一系统的 Python 程序。

macOS 构建以 ad hoc 方式签名，GitHub 发布任务把校验过的 DMG 上传到对应版本。

### macOS 应用更新

界面沿用「应用更新」气泡。Electron 主进程通过 GitHub Releases 查询正式版标签，对比实际安装版本，再下载固定版本与架构的 DMG。点击后才开始检查和下载，由用户选择保存位置。下载完成后由用户打开安装包，覆盖安装后继续读取原数据目录。

## 当前验证

- PyInstaller 生成的 macOS Apple Silicon 本机服务使用独立临时数据目录启动成功。
- 打包后的服务能够提供现有网页、健康检查和个人记录接口；桌面主进程结束后，本机服务完成收尾并退出。
- macOS Apple Silicon 应用已安装到“应用程序”，通过签名完整性检查。在独立空目录启动后，实测 0 个对话、0 篇笔记、4 项社区资料及 3 个教研工具。通过界面保存新目录并重启后，数据从所选目录读取。
- Windows 配置、路径选择和纯代码检查已加入工程；Setup.exe 和干净 Windows 安装仍需 Windows 环境验证。
