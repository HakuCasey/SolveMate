# 014 状态栏与资料上传进度设计

应用更新气泡左侧用正文显示状态，右侧放操作按钮。“更新应用”使用主题色实心按钮，“再次检查”使用描边按钮。新版就绪时，侧栏的更新图标高亮。

## 状态来源

`operations/store.ts` 统一接收业务操作的开始、完成和失败结果。每次操作有独立编号，相同业务操作使用稳定键匹配重试；较早请求的完成结果不能覆盖后一次尝试。状态优先级为当前失败、进行中、最近成功、就绪。无关操作成功不清除其他失败，同一操作重试成功才清除对应失败，重试过程中仍保留未解决条目。表单输入、AI 轮询和模型生成不计为这些业务操作。一次刷新及其并发读取共用一条操作记录：用户主动刷新显示“加载用户数据”，后台触发显示“自动刷新数据”。子项不分别生成失败记录，展开后列出仍刷新失败的内容和对应原因。

每项操作由执行该操作的业务方法报告名称、对象名称和结果。刷新协调器汇总各项读取结果，保留失败范围及原错误代码，共用同一轮读取的调用者只产生一条结果；界面不根据错误文字补造“提交更改”记录。

`RefreshControls` 嵌入备份与恢复，显示操作记录、重试与冲突处理入口。诊断日志的订阅和窗口自动刷新随工作区启动。

AI 状态按对话最后一次执行编号和修订号比较已保存记录与实时结果。已删除的对话不进入列表；正在执行的所有对话都显示，旧失败仅在当前对话或本窗口已经收到该执行结果时提示。连接中断保留原任务，不假装任务已经结束。状态气泡复用原有返回对话操作。

`StatusBar` 排列应用更新和对话状态两个入口，共用 `StatusPopover`。系统设置按钮、备份与恢复菜单项和操作记录共用工作区的异常判断，查看记录后继续保留提示，直到对应问题解决。

各模块继续调用存储控制器、更新控制器和会话管理接口。状态栏横排显示图标，以主题颜色区分状态，文字通过悬停提示和气泡呈现，处理中图标明暗渐变，系统减少动态效果时停止动画。气泡中的多个对话共用同一字号，单个对话不重复显示与上方相同的生成状态。

`applicationStatus` 将更新控制器状态映射为图标提示、气泡状态与按钮文案。“新版就绪”是状态，“更新应用”是操作，分别显示。注册对象的后台下载事件直接更新状态栏，不以气泡展开作为检测或显示条件。“已是最新版本”的检查结果保留到下次检测，气泡关闭后仍可查看。

## 失败诊断

`operations/diagnostics.ts` 将最近 50 次失败的操作名称、对象名称、编号、对象编号、时间、错误代码、错误类型及 HTTP 状态缓存在当前浏览器。导出文件为 `operation-errors_<日期>.json`，不含正文、配置值、凭据或原始异常文本。当前窗口可显示本次失败的具体原因，刷新后只恢复诊断字段，不将历史失败重新置为当前失败。成功操作不加入诊断历史。读取历史时只清理操作缓存中的无效记录：旧版 `application:pending` 和 `application:read` 由错误文字补造，无法对应具体动作，不予保留；整轮刷新记录必须包含失败内容列表。其他能说明具体操作的记录保留，清理不访问对话、笔记或配置。

“操作详情”只读取当前未解决的失败，显示具体操作、时间、对象名称及失败原因，并按操作提供重试或处理指引。重试成功立即移除该项，无关操作成功不影响其他失败。历史失败不进入这个列表；操作编号、错误代码等诊断字段留在日志中，提供独立的“导出诊断日志”操作。操作记录在备份与恢复的内容区内展开。没有当前失败时显示“当前没有未解决的失败操作”；即使当前失败已经解决，仍可导出保留的历史诊断日志。同字段冲突也在此窗口比较，用户完成选择后再重试。已提交但保存失败的记录由存储控制器保护，具体规则见 [013](../013-data-refresh/design.md)。

## 上传与处理

`upload-request.ts` 仅负责传输与实际字节进度，响应继续由资料 API 统一校验。传输完成、服务确认保存、解析或转换结束分别处理。网络错误、超时和中止明确提示；不自动重传，避免重复提交。

`upload-progress.ts` 保存本次窗口中的 File 与传输状态。已保存资料按稳定编号从现有资料列表取最新处理结果，初始返回记录只作读取前的补充。转换进度沿用已有轮询，不增加独立处理任务。处理失败复用资料重试接口，文件与版本保持原关联。

上传窗口按文件显示结果，保留成功项，只为传输失败项重新上传。全部网络请求结束后才能关闭窗口；关闭不取消已保存资料的后台处理。

## 验证记录

以下为 2026-11-12 的验证记录。测试覆盖保存状态优先级、多个回复和权限状态、删除记录过滤、表单备份与当前修改区分、实际上传字节和等待响应、超时与网络错误、资料处理结果与重试状态。271 项网页测试、19 项脚本测试通过；共享 Schema 检查、TypeScript、ESLint、Prettier、依赖许可检查和生产构建通过。

macOS Chrome 使用独立本机目录和模拟 Harness，验证切到笔记后仍显示回复状态、返回原对话、停止生成和权限确认；另验证保存失败保留输入、连接恢复后取消修改、应用更新与日间和夜间气泡。PDF 与 PPTX 完成上传及 43 页解析或转换；模拟转换故障后，从窗口重试原资料并恢复。没有调用真实 Codex 或其他模型。Windows 真机与其他浏览器仍待实际验收。

使用两个生产构建验证后台更新：另一窗口触发自动检查和下载，当前窗口未打开更新气泡，应用更新图标也会高亮并提示“新版就绪”。另验证更新失败与重试、三个状态气泡在日间和夜间的显示、生成中切换页面及从任务卡片返回对话。
