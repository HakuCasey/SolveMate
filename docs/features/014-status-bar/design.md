# 014 状态栏与资料上传进度设计

## 状态来源

`status/state.ts` 从已有保存结果、冲突、服务可达性、当前表单草稿与 AI 执行记录生成显示状态，不新建一份业务记录。保存失败和未保存表单优先于成功提示；已卸载的表单备份仍可查看，但不计为当前编辑。

AI 状态按对话最后一次执行编号和修订号比较已保存记录与实时结果。已删除的对话不进入列表；正在执行的所有对话都显示，旧失败仅在当前对话或本窗口已经收到该执行结果时提示。连接中断保留原任务，不假装任务已经结束。状态气泡复用原有返回对话操作。

`StatusBar` 负责三列容器，`StatusPopover` 统一入口、分类标题、当前状态、关闭按钮及操作区域。标题与正文统一使用 13px，仅分类标题加粗；正常状态只显示标题和状态，不附加解释或空白操作区。记录保存正常时显示“已保存”，对话空闲时显示“AI 空闲”。错误原因与重试、刷新或处理冲突的操作按实际情况提供；未保存表单不额外显示刷新按钮。

各模块继续调用存储控制器、更新控制器和会话管理接口。状态栏保留图标、文字和主题颜色，处理中使用旋转图标，系统减少动态效果时停止动画。气泡中的多个对话共用同一字号，单个对话不重复显示与上方相同的生成状态。

`applicationStatus` 将更新控制器状态映射为常驻文字、气泡状态与按钮文案。“新版就绪”是状态，“更新应用”是操作，分别显示。注册对象的后台下载事件直接更新状态栏，不以气泡展开作为检测或显示条件。“已是最新版本”的检查结果保留到下次检测，气泡关闭后仍可查看。

## 上传与处理

`upload-request.ts` 仅负责传输与实际字节进度，响应继续由资料 API 统一校验。传输完成、服务确认保存、解析或转换结束分别处理。网络错误、超时和中止明确提示；不自动重传，避免重复提交。

`upload-progress.ts` 保存本次窗口中的 File 与传输状态。已保存资料按稳定编号从现有资料列表取最新处理结果，初始返回记录只作读取前的补充。转换进度沿用已有轮询，不增加独立处理任务。处理失败复用资料重试接口，文件与版本保持原关联。

上传窗口按文件显示结果，保留成功项，只为传输失败项重新上传。全部网络请求结束后才能关闭窗口；关闭不取消已保存资料的后台处理。

## 验证记录

自动测试覆盖保存状态优先级、多个回复和权限状态、删除记录过滤、表单备份与当前修改区分、实际上传字节和等待响应、超时与网络错误、资料处理结果与重试状态。2026-11-12：271 项网页测试、19 项脚本测试通过；共享 Schema 检查、TypeScript、ESLint、Prettier、依赖许可检查和生产构建通过。

macOS Chrome 使用独立本机目录和模拟 Harness，验证切到笔记后仍显示回复状态、返回原对话、停止生成和权限确认；另验证保存失败保留输入、连接恢复后取消修改、应用更新与日间和夜间气泡。PDF 与 PPTX 完成上传及 43 页解析或转换；模拟转换故障后，从窗口重试原资料并恢复。没有调用真实 Codex 或其他模型。Windows 真机与其他浏览器仍待实际验收。

使用两个生产构建验证后台更新：另一窗口触发自动检查和下载，当前窗口未打开更新气泡，状态栏也会从“检查更新”变为“新版就绪”并高亮。另验证更新失败与重试、三列气泡在日间和夜间的显示、生成中切换页面及从任务卡片返回对话。
