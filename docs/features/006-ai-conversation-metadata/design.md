# AI 配置与对话元数据实现

## 共享约定

`packages/contracts/ai-metadata.schema.json` 是共享字段的定义来源。`npm run contracts:generate` 生成 TypeScript 类型和 Python wheel 使用的 Schema 副本；`npm run contracts:check` 校验同步，已接入 `npm run check`。

网页用 Ajv 2020 校验，Python 用 jsonschema 的 Draft202012Validator 校验；两端使用 `packages/contracts/fixtures/ai-metadata.json` 中相同的有效与无效输入。FastAPI OpenAPI 中包含这些共享对象，HTTP 返回与新增请求元数据引用同一结构。

现有课程内容接口保持原约定。共用定义覆盖教师默认、会话配置、模型目录、连接、会话元数据、绑定、请求与执行快照，不批量创建其他模块的数据结构。

## 连接管理与内部选择

- 外部连接管理使用 `services` 接入目录和 `connections` 已保存连接。目录中的服务不自动进入内部可选范围；各连接独立记录 `enabled` 与 `check`。
- `PUT /settings` 检测并保存指定连接。新版明确传入 `makeDefault`，通常为 `false`；首次配置可设为默认。旧客户端未传时保留原接口行为。
- `PATCH /connections/{id}` 单独启用或停用连接，使用连接版本检查。`PUT /default-connection` 单独指定全局默认，使用偏好版本检查。操作不调用模型，也不改写教师、对话或原生绑定。
- `DELETE /connections/{id}` 同时检查连接与偏好版本，在事务中删除配置，并在需要时清空默认引用。`deleted_connections` 仅保留编号、递增版本及删除时间，不保存删除后的安装位置或模型目录；重新配置从保留版本继续递增。接口允许同次删除重试，旧请求不能删除重新配置的连接。
- 删除不会清除教师、对话、原生绑定、执行或专用检测会话。存在删除记录时，`AiSettings.deletedConnectionIds` 提供只读状态；重新配置后不再列为已删除。内部选择保留原值并显示原因，不回退到全局默认。弹窗说明删除影响；失败保留确认框与错误，结果不明时重新读取状态确认是否完成。
- 最近检测失败时保留配置、模型目录与选择；本机执行入口拒绝停用或检测失败的连接。检测未知与已失败分别表达，不把旧记录缺少检测时间解释成失败。
- `Robot.aiDefaults` 只保存完整选择或 `null`。`Conversation.aiConfig` 保存明确的连接与模型。`configuredConnections` 统一提供内部可选范围，`connectionFor` 仍能读取失效的原选择，供所有界面解释原因。
- 网页个人记录、教师、对话及连接管理使用格式 3。执行快照仍为格式 2，保留其历史含义；旧 `ModelSelection` 不再参与当前选择。

## 原生会话恢复

恢复的判断依据是当前适配器能否找到并恢复原生会话。`AiService` 保留连接、教师与会话编号的归属检查，把原编号及建立时的工作目录交给适配器；不比较建立时与当前的程序路径或配置目录。路径字段继续保留为历史运行信息，不变更共享结构或迁移已有绑定。

- 已在当前进程加载的会话直接使用；程序或配置目录改变时重启对应进程、清空加载缓存，再恢复原编号。缓存不决定会话是否存在。
- DSH 通过 `session/resume` 恢复。原生返回“不可恢复”时显示未找到可恢复会话；工作目录不匹配、其他连接占用分别提示。连接断开、超时和账号错误不解释成会话不存在。
- Hermes 使用严格的 `session/load`。空结果表示未找到；结果不完整与返回其他编号分别报错，不能将它们当成恢复成功。其 `session/resume` 在旧版本中可能另建会话，因此不作为失败后的备用入口。
- 恢复失败保留原生编号、历史消息和执行记录，不调用创建接口。用户恢复原生记录或修正连接后可再次尝试。
- 专用检测会话未找到时提示确认后重建，保留已保存连接的检测状态，不阻止其他正式会话。连接中断、超时等故障保留实际错误并记录检测失败，避免用“测试会话丢失”掩盖连接故障。

DSH 原生接口要求恢复参数中的工作目录与其持久化记录匹配。SolveMate 传入绑定保存的工作目录；该目录不可用或原生记录不同仍可能恢复失败，错误不会触发会话替换。

## 写入与展示

- `ai/robot-config.ts` 统一解析教师默认和会话选择；已有连接从会话 `aiConfig` 读取，模型不通过教师对象覆盖。
- `state/conversations.ts` 统一创建、修改、删除与配置联动。名称、标签、归档等改变记录版本，聊天活动时间独立保存。
- `storage/controller.ts` 管理写入顺序。配置和会话操作等待持久化成功后发布新值；保存过程中接收的执行结果随后合并。保存失败保留旧配置，允许明确重试。
- 聊天气泡只保留本次草稿，取消不提交；确认框携带待执行操作，持久化失败时保留错误提示。机器人页面的角色草稿独立保留。
- 提问先保存问题、资料引用、执行编号及待提交状态，再提交本机。请求携带会话元数据与连接版本；本机核对教师、服务、模型、归档状态和绑定。旧调用可省略新增字段，仍执行原有绑定与教师检查。
- 本机执行保存请求快照、提交信息、已确认绑定和结果版本；网页只合并执行结果，不能借历史回放改写当前模型。没有原生确认的实际模型保持 `null`。

教师默认的同服务模型变更由业务操作更新相应会话，历史执行不变。不同服务的旧会话保留原配置。删除教师后保留对话身份，继续选择另一位教师时按已有规则新建对话。

保存反馈由应用外层的 `SaveFeedbackProvider` 统一显示，各入口在持久化成功后触发。配置气泡关闭不影响成功提示；需要切换服务确认时，只有确认后的保存操作会触发提示。提示在 2 秒后、点击其他位置、点击关闭按钮或按 Escape 时关闭，不抢占焦点，也不阻止其他控件的操作。

## 迁移与恢复

浏览器读取完整旧对象后先转换与校验，再在同一 IndexedDB 事务中保存原 `legacyBackup`、按格式编号的 `metadataBackups`、新值与保存版本。后续保存保留备份；失败回滚。现有课程包数据库不迁移。

SQLite 使用 `PRAGMA user_version=3` 标记格式。在一个事务中保存 `metadata_backups`、升级连接的启用状态与检测记录、保存全局默认引用；执行内容和快照不重写。绑定保留原生编号，补充协议、保存版本与状态。执行中断仍保留正文，重启后记录为中断，不重新请求模型。

旧记录无法确认的创建版本、实际模型与请求参数保持未知。无法确定连接的旧自选模型仅在迁移结果中允许连接为空，实际请求必须重新明确连接；不按相同模型编号匹配另一服务。互相冲突的绑定阻止迁移，错误可见，旧值不被覆盖。
