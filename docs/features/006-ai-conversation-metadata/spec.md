# 006 AI 配置与对话元数据

## 目标与背景

AI 配置和对话使用统一的数据定义。标题栏、配置表单、请求、本机处理和历史恢复遵循相同的对象关系，取消选择、修改默认服务或恢复旧记录时，不产生互相矛盾的配置。

涉及 AI 管理和数据管理，落实[模块元数据设计](../../architecture/metadata.md)与[对话元数据设计](../../architecture/conversation-metadata.md)中当前 AI 配置和对话管理的范围。资料导入、文件引用、Skill、RAG 与学习记忆仍按后续特性实施。

## 范围

- 一份 JSON Schema 定义共享对象，生成 TypeScript 类型；网页与 Python 使用同一份结构约束校验。生成结果及 Python 包内的 Schema 副本可检查是否同步。
- 连接配置由左下角统一管理，每项连接分别记录启用状态和检测结果；全局默认仅保存连接编号，保存连接不会顺便切换全局默认；连接和偏好均有保存版本，拒绝旧窗口覆盖新配置。
- 已配置连接支持确认后删除。删除默认连接时清空默认选择，不自动改用其他服务；其他连接继续保留。教师和对话保留原连接、模型、消息及原生绑定，显示连接已删除。重新配置后保存版本递增，旧窗口不能误删新配置。删除期间禁止重复提交，生成期间拒绝删除。
- 教师默认与会话当前配置分开保存，选择内容为连接编号与模型编号。教师没有独立配置时使用全局默认；独立配置不会因全局默认变化而改变，新对话保存明确选择。
- 机器人和对话只选择已经配置且启用的连接与模型，共用可选范围；失效选择保留并说明原因。界面只显示“AI 服务”和“模型”，不显示“模型来源”“跟随全局配置”等下拉选项，恢复全局默认通过“使用全局配置”完成。
- 会话保存身份、名称来源、标签、生命周期、教师身份、阅读关联、创建原因及运行版本。切换教师或服务产生新对话，取消保留原值。
- 每轮保存请求配置、教师指令、客户端版本、连接版本和实际提交参数；Harness 未返回的实际模型保持未知。
- 本机保存正式绑定及创建、绑定、结果不明和恢复失败状态。前端读取已确认结果，不根据历史数组的第一项猜测当前服务。
- 原生会话恢复由适配器负责。程序位置或 Harness 配置目录变化、删除后重新配置同一服务，都不直接使旧会话失效；仍查找并恢复原编号。恢复失败显示具体原因，保留原记录，不创建替代会话。专用检测会话丢失不影响其他正式会话的可用性。
- 配置保存失败时保留草稿和已保存配置；AI 结果在配置事务期间排队，避免互相覆盖。历史回放不能替换当前模型选择，旧执行版本不能覆盖新正文。
- 全局 AI 配置、对话栏 AI 配置及机器人配置共用保存反馈：按钮在保存时显示“保存中…”，持久化成功后显示“配置已保存”，2 秒后自动消失，点击其他位置或关闭按钮也可收起。失败时不显示成功提示，保留修改并说明原因；服务切换需要确认时，确认并保存成功后才显示提示。
- 删除教师保留旧会话关联和作者信息，不自动替换成默认教师。归档仍隐藏提问入口，恢复后可继续。

## 兼容

浏览器个人记录从格式 1 或 2 升至格式 3，保留旧值备份；SQLite 在事务中保存分版本迁移备份并升级至格式 3。对话、消息、连接、原生会话和请求编号保持原值。来源不明的历史版本与返回模型不补造；无法确认连接的旧自选模型保留编号，并提示重新选择所属服务。

旧接口的全局 `config`、`detection` 等字段仅作为根据默认连接生成的兼容返回值，不另存一份配置。旧格式转换集中在读入边界，教师、对话及连接管理使用格式 3，已保存执行与快照保持格式 2。冲突绑定或不支持的数据版本明确报错，原记录不被示例或默认配置覆盖。

## 验收

- 共享契约、类型生成检查、Python 与 TypeScript 的相同校验案例通过。
- 覆盖旧记录迁移、备份保留、重复打开、冲突和未来版本；原编号、正文、指令和原生绑定保持不变。
- 验证服务切换确认与取消、同服务模型保存、归档恢复、重命名、刷新及本机服务重启后继续原会话。
- 验证程序与配置目录变化、连接删除再配置后的原生恢复；未找到、返回其他编号和连接故障时不替换绑定。检测会话丢失不阻止正式会话恢复。
- 验证保存失败、并发配置、保存期间收到回复，以及乱序和重复执行快照。
- 普通测试不调用模型；真实验证使用独立数据库与测试会话，结果见设计文档。
