# 002 社区内容服务技术设计

> 当前状态：后端与 Web/PWA 下载更新已实现并完成基本验证。

## 模块协作

[模块架构](../../architecture/overview.md#模块架构)中的知识维护负责课程内容规则、版本发布与下载更新；数据管理负责内容校验后的本地保存、版本记录与读取。资料阅读和 AI 管理使用本地课程及其固定版本；本特性不改变个人会话、机器人配置或 AI 连接规则。

代码中的发布、读取和 HTTP 接口属于工程内部组成，分别承接上述职责。本特性只覆盖现有课程包格式，其他内容类型的接口与存储方案仍待设计。

界面与文档统一称为“社区内容”。社区资料使用统一的 `Material` 记录，来源值为 `community`；内容服务的接口标识继续沿用。资料编号和已下载版本保持不变。

社区资料的 `OfficialMaterialMetadata.customTitle` 保存本地名称，缺少时沿用发布名称。`OfficialLibrary.rename` 与 `OfficialLibraryService.rename` 统一处理改名和冲突检查；下载、删除及重新添加保留该字段。列表、阅读标题和资料来源从同一元数据读取名称，资料编号与历史引用保持不变。

## 设计目标

代码位于 `apps/server/src/solvemate_server/`。使用 FastAPI 路由、Pydantic 数据校验和 Uvicorn 运行服务；以文件保存发布目录、不可变课程 ZIP 及教研工具 JSON。当前内容规模小，不引入账号数据库或个人数据存储。

模块分别负责配置、模型、源内容发布、已发布内容读取及 HTTP 接口。启动与接口列表见 [后端 README](../../../apps/server/README.md)。

## 逻辑流程

1. 维护者在 `data/catalog.json` 声明课程与允许发布的四类原文件，内容继续保存在各课程目录中。
2. 发布工具校验课程 JSON、题目与记忆编号、来源题号和教材章节引用，读取文件原字节并生成清单。
3. 每门课程生成确定顺序、固定 ZIP 时间信息的内容包。版本等于包 SHA-256，包内 `course.json` 列出原文件校验值；包外清单提供包校验值，避免哈希相互依赖。
4. 新版本目录写入完成后，通过同目录临时文件和 `os.replace` 提交完整的 `catalog.json`。写入或校验失败不替换原目录；发布锁防止同时提交。
5. API 每次读取已提交目录；先由目录确认课程和版本，再读取、校验相应内容包。旧版本在目录与存储中保留，更新不需要重启 API。
6. 客户端依次查询、下载固定版本、校验并完整保存，最后切换使用版本。客户端已按下述流程实现。

## 责任边界

- `data/`：社区内容原文件与发布源目录，不包含个人长期记忆。
- 发布工具：仅服务端维护者运行，检查内容、生成课程 ZIP 或工具 JSON、提交目录；不提供公开写入 API。
- FastAPI：只读目录、版本、更新状态和下载，不接收会话、机器人配置或 AI 凭据。
- 客户端：负责下载、校验、解包、本地事务和失败回退；未下载时使用随应用提供的基础内容，下载后读取本地保存版本。
- 部署：持久保留完整发布目录，API 和发布进程使用相同位置。wheel 不携带仓库原内容，独立安装时显式配置目录。

## 接口与数据

以 Pydantic 模型和路由生成的 [OpenAPI](../../../packages/contracts/content-api.openapi.json) 为接口约定。

- 源目录记录课程 `id`、`title`、`description`、便于阅读的 `release` 及文件白名单。`release` 不表示可排序版本，不能用来判断更新。
- 发布目录记录每门课程的最新版本与可查询历史版本；API 只允许访问这个目录中已提交的版本。
- 版本清单记录课程信息、包版本、包大小、SHA-256、文件列表与固定下载路径。文件列表保留教材编号 B001／CB001、相对路径、类型、大小和 SHA-256。
- `updates` 对已知历史版本返回可更新，对未知版本返回 `unknown_version`，不按哈希字符串推断版本先后。
- 目录与 `latest` 使用 `no-cache`，固定哈希资源允许不可变缓存；课程 JSON 与 ZIP 下载支持 ETag 条件请求，课程下载由 `FileResponse` 提供 HEAD、Range、If-Range；工具 JSON 下载的缓存行为单独说明如下。
- 单个课程版本包含一本教材、一份题库、记忆点和讨论点。后续多教材、图片与更大资源需另行扩展包格式和发布策略。

## Web 客户端实现

- `apps/web/src/content/` 分别实现接口类型与运行时校验、网络请求、ZIP 读取、本机内容保存及浏览器缓存和下载状态。fflate 用于解压，Web Crypto 用于 SHA-256；实现参考 [fflate](https://github.com/101arrowz/fflate) 和 [Dexie 事务](<https://dexie.org/docs/Dexie/Dexie.transaction()>)。
- 内容管理从“系统设置 → 社区内容”进入，不调整主菜单布局。联网后查询课程目录与每门课程的更新状态；下载前重新查询，使用该次清单对应的固定版本地址。
- 请求不发送 Cookie 或个人记录。网页和桌面版使用同一套完整服务地址；本地启动程序按实际端口写入地址，正式发布通过 `VITE_CONTENT_API_URL` 指定。桌面安装包不包含社区内容服务，在“系统设置 → 社区内容”保存服务地址后，资料与工具目录共用该地址并立即重新读取；配置保存在用户数据中。PWA 不为 API 提供 HTML 导航回退，也不缓存 API 来假装离线联网成功。
- 首版文本包限制压缩后 10 MiB、原文件总和 20 MiB，清单 JSON 512 KiB；ZIP 只允许白名单声明文件与 `course.json`；旧包包含四份源文件，新包增加成对的 PDF 和逐页索引，拒绝未知、重复、越界或过大文件。校验包与逐文件大小和哈希、内部清单、JSON 字段、编号、教材章节及记忆引用后才进入保存流程。
- 本机 `user/community/` 按课程和版本保存清单与原始 ZIP；`user/app.sqlite3` 的 `versions` 保存版本索引和安装时间，`heads` 保存当前下载版本。网络、解压、哈希和文件写入在事务外完成，完整文件落盘后，版本索引与指针在同一事务中提交。浏览器缓存只用于加快读取和缓存阅读，原 `solvemate-content` 数据库保留供迁移；详见 [012](../012-local-user-storage/design.md)。
- 下载开始时记下原指针；提交时再次比较，其他窗口已经更新则拒绝覆盖，提示刷新。保存失败会回滚整个事务，保留旧指针和内容。
- 启动时无需联网，读取并验证保存的内容包，重建当前课程与历史版本。已有内置课程始终保留作基础内容；新课程下载完成后出现在统一的学科与资料选择页面。
- 阅读位置必须带明确的资料编号与版本，PDF 使用实际页码，题目使用题号。不再按默认版本或旧章节推断引用；不支持的记录在读取边界报错。历史固定版本继续保留，下载不改写历史消息。
- 点击“阅读”时按当前已保存版本打开卡片对应的学习资料；再次进入同一份资料时使用保存的页码或题号。查看历史版本时展示相应提示。

## 教研工具发布与下载

`data/catalog.json.tools` 列出允许发布的工具编号，源定义位于 `data/tools/`。发布器先校验工具定义，再按 JSON 字节的 SHA-256 写入 `tools/<id>/<version>.json`，最后与课程目录一起提交发布目录。不同工具与课程分别计算版本，修改一项不改变其他项的版本。

`GET /api/v1/tools` 返回工具目录；`GET /api/v1/tools/{tool_id}/versions/{version}/download` 返回固定版本或 `latest` 对应的 JSON。下载前核对发布白名单、文件结构和摘要，响应带 ETag、`X-Content-SHA256` 与 `no-cache`。当前工具下载不提供课程 ZIP 的 Range 或条件请求处理。

前端 `ContentApi` 复用既有请求超时及错误处理；工具文件限制 256 KiB，`research/catalog.ts` 核对摘要、Schema、编号与名称。校验成功后由 `useTeachingTools` 一次提交本地工具目录，失败不替换已安装版本。工具正文保存到 `user/app.sqlite3` 的应用记录，浏览器仅缓存社区目录。教研室和社区内容页共用该目录的安装与删除状态；元数据和自定义规则见 [019](../019-question-research/design.md)。

## 资料卡片与按钮

`courseState` 读取当前版本指针和有效保存记录，只判断课程包与更新状态。`OfficialMaterial` 结合这些记录、学科目录及条目元数据，统一决定当前资料的可用状态。主按钮以正式保存记录为依据，不以应用内置内容是否存在为依据。更新查询所用版本须与当前指针一致；旧查询不会为另一窗口已保存的新版本生成更新按钮。

`contentEntries` 将当前课程包展开为学习资料和题目卡片，使用课程编号、内容类型与资料编号区分条目。学习资料显示文档标题与简介；题目集合显示学科名称及实际题数，学科和内容类型单独作为标签。两种卡片复用课程文件，各自读取 `Material` 的当前版本、删除状态与文件可用状态；课程包的当前指针不直接决定另一张卡片是否已下载或需要更新。`parseTextbook` 从文档标题和章节前的简介段落提取显示信息；旧版内容包通过同一解析流程读取，无需修改原始文件或历史记录。课程包的下载、完整校验、事务保存与历史版本规则保持一致。

阅读操作传递完整的 `ReadingSelection`，区分学习资料与题目，使用当前本地版本。资料打开对应文档，题目默认打开第一题；同一课程和类型已有阅读位置时，保留原页码或题号。用户上传资料与社区学习资料继续共用学科列表的同一层级。

检查更新先读取本机课程，完成后同时提交目录和查询结果。读取或请求失败保留当前可读内容，过期查询不覆盖下载期间的新状态。资料尚未保存时卡片不显示更新日期；正式保存后显示完整年月日，日期不依赖检查更新的时间。

卡片按页面容器宽度排列为四、三、二或一列，不因资料数量较少而拉宽。图标和标题位于首行左侧，操作按钮靠右且不收缩；长标题按可用空间换行。简介、标签及更新日期分行排列，卡片底部不再单独放置阅读或下载按钮。技术版本信息继续用于校验和历史恢复，不混入卡片正文。

## 资料对象与管理服务

社区目录中的 `CommunityCatalogEntry` 组合发布信息与本机 `Material` 记录，只负责目录展示。所有资料的名称、学科、删除标记和当前版本统一保存在 `user/app.sqlite3`，由 `MaterialRepository` 修改，社区下载不另建本地资料模型。

现有稳定编号继续保留，例如 `calculus:textbooks:B001` 和 `calculus:questions`。本地名称和学科是可修改属性，发布编号通过 `publisher` 保留，用于匹配更新。名称和学科变化不修改历史引用。

`OfficialLibraryService` 只协调社区文件获取与所选版本启用；重命名、移动和删除与上传资料共用本机资料接口及 `MaterialActions`。下载完成不代表更新成功：版本文件登记后，仍需通过修订检查才能切换所选资料。失败时继续使用原版本，完整包可供重试复用。

删除后的历史文件仍可用于既有引用。重新添加使用相同资料编号；原学科已删除时归入未分类，不按名称复活学科。

## 异常处理

- 404：未发布的课程或版本；422：路径或查询参数格式无效。
- 503：发布目录、清单或内容包缺失、损坏，拒绝返回损坏字节。
- 启动前完整校验发布目录和包；首次未发布或存储损坏时拒绝启动，不以空目录冒充成功。
- 源内容校验失败、文件写入失败或另一个发布进程持有锁时，本次发布失败，旧目录保持不变。
- 进程被强制终止可能留下发布锁，维护者确认没有发布进程后再移除；未进入目录的完整包不对 API 暴露。

## 安全与隐私

课程编号、版本格式受约束；源内容白名单限制相对路径，解析符号链接后的实际路径必须位于对应课程目录。读取已发布文件时再次限制真实路径，不提供任意文件下载。网页来源由环境变量明确指定，不使用凭据跨域。

日志使用英文；HTTP 错误不暴露服务器路径、原文件内容或异常堆栈。正式服务只需要对发布目录的读取权限；维护者的发布进程才需要写权限。

## 测试方案

使用 FastAPI / Starlette `TestClient`、pytest 和真实课程资产副本，覆盖目录、版本、字节与哈希一致性、缓存、Range、CORS、更新发布、历史版本、重启恢复、无效路径、损坏包、引用错误和发布失败。Ruff 使用工具默认检查与格式化，不新增项目专属编码规则。

另用实际 Uvicorn 进程验证 HTTP 目录、OpenAPI、ZIP 下载、条件缓存和分段续传，构建 Python wheel。客户端使用 Vitest 验证包校验、本地事务、版本选择、网络失败与取消，并通过浏览器验证实际下载更新与离线重开。

实现参考 [FastAPI 文件响应](https://fastapi.tiangolo.com/advanced/custom-response/)、[Lifespan](https://fastapi.tiangolo.com/advanced/events/)、[CORS](https://fastapi.tiangolo.com/tutorial/cors/) 和 [Starlette TestClient](https://github.com/Kludex/starlette/blob/main/docs/testclient.md)。当前 Starlette 的测试客户端使用 httpx2，依赖按实际安装版本锁定。

## 社区 PDF 与版本提示

发布目录新增 `textbook-pdf` 和 `textbook-pages`，两者成对出现。PDF 使用 `application/pdf`；索引记录逐页文字、章节首页、原文 SHA-256 和 PDF SHA-256。发布工具与客户端都核对来源编号、校验值、页码范围及章节数量，拒绝缺少配对文件或未同步的索引。原 Markdown 和记忆锚点保留，旧的四文件包无需迁移。

`Textbook.pdf` 只记录 PDF 路径、逐页文字与章节页码。新版 PDF 从已校验的固定版本 ZIP 读取；只有原文的 SHA-256 匹配时，旧包才使用随应用提供的同源 PDF。内置示例也使用该 PDF，资产随 PWA 缓存，读取时再次核对 PDF 的校验值。章节式 Markdown 阅读界面和样式已移除。`PdfPage` 与 `PdfControls` 同时服务社区资料和上传资料，不为社区资料再建一套渲染器或复制到上传目录。通用 `ReadingSelection.pageNumber` 在题目记录中可省略，社区 PDF 的读取与引用则必须包含实际页码；不再把旧章节位置转换为首页。滚动以页码区分，缩放按资料版本保存，翻页不重载 PDF。同一社区 PDF 可连续讨论，查看旧引用仍使用原版本。

检查更新仅查询本地版本与社区目录，不改变当前版本指针。检查成功显示结果，发现新版时在页面和卡片中明确提示；“阅读”与“更新”可同时出现。只有用户更新并完成校验和保存后，所选资料才切换版本。

## 每份社区资料的版本

每份资料的 `currentVersion` 独立保存。下载课程包只登记版本文件，不切换其他资料；所选资料通过统一版本接口更新指针。页面从该资料记录读取标题、学科与日期，课程包指针只用于获取发布文件。下载、校验或保存失败保留当前版本。

学习资料按 PDF 及其发布文件的校验值判断更新，题目集按题目文件判断更新。同包其他资料变化不产生该资料的更新提示。
