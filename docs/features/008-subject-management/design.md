# 008 技术设计

## 对象与数据归属

| 对象 | 内容与职责 | 保存位置 |
| --- | --- | --- |
| `Subject` | 稳定编号、名称、删除状态，以及删除时是否同时移除上传资料条目 | `AppData.subjects`，与个人记录一起在 IndexedDB 中保存 |
| `Material` | 独立资料编号、文件版本、所属学科编号、处理状态 | 本机资料记录；浏览器保存副本与文件缓存 |
| `MaterialLocation` / `ReadingReference` | 固定资料编号、版本、页码及提问时的文字 | 阅读位置与历史消息，不随学科改名或删除重写 |
| `SubjectDirectory` | 从学科记录生成完整目录、可用选项和按编号查询的索引 | 不另行保存 |
| `MaterialImportResult` | 本次上传中已保存的记录，以及每个失败文件和原因 | 当前上传操作，不作为正式资料或历史记录保存 |

学科名称仅用于显示，资料始终通过编号关联学科。用户学科使用 `subject-UUID`；新建学科不生成空的官方课程包。未分类使用空学科编号，不将“新建学科”等表单选项写入资料记录。

官方课程包继续管理教材、题目和内容版本。学科改名只覆盖界面名称，不修改官方文件、课程编号或历史引用。

## 共用查询规则

`state/subjects.ts` 建立唯一的学科目录。侧栏显示、列表标题、上传选项和资料归类使用该目录；不由页面各自拼接或保存可选学科。

资料列表与返回导航通过 `reading/library.ts` 的同一项查询区分三种状态：

- 已归类：关联到一个可用学科。
- 未分类：没有学科，或关联到缺失分类、仅删除分类的旧记录。
- 已移除：学科的 `deleted` 和 `materialsDeleted` 均为真；不出现在资料列表中，也不进入未分类。

删除标记与是否移除资料在同一次个人数据事务中保存，不逐个删除文件或改写历史。提前转移到其他学科的资料不受影响。旧记录缺少 `materialsDeleted` 时保留原有的仅删除分类含义，新下载的官方内容不会重新添加已经删除的分类。

## 操作与保存顺序

| 操作 | 处理顺序 |
| --- | --- |
| 新建学科 | 校验名称和重名 → 生成固定编号 → 保存成功 → 返回该编号并更新目录 |
| 重命名 | 按编号确认学科仍可用 → 保存名称 → 所有使用目录的界面显示新名称 |
| 删除学科 | 用户确认 → 同时保存两项删除状态 → 列表按共用规则移除该学科及其资料条目 |
| 上传资料 | 选择文件和目标 → 必要时先保存新学科 → 每个文件提交前读取最新目录 → 保存文件 → 检查目标状态 → 返回逐文件结果 |
| 转移资料 | 确认目标学科可用 → 带资料修订号提交 → 更新资料记录 → 重新读取列表 |

`materials/operations.ts` 负责上传、归类的业务判断与请求顺序，独立于 React。上传表单只保留文件、选中的编号和当前步骤，不判断正式保存是否成功，也不从名称反推编号。

异步操作通过个人数据控制器读取当前学科记录，不使用打开窗口时的旧闭包。新学科保存完成后，即使页面还没有重新渲染，随后的上传也能取得该编号。修改失败或保存冲突时，不发布新的学科目录、不关闭确认框，也不显示成功。

`materials/useMaterials.ts` 将请求结果更新到同一份资料状态。`materials/query.ts` 按请求顺序决定哪些查询结果可以发布：新的查询或资料写入发生后，较早的列表响应、缓存读取和错误均不能覆盖新状态。刷新失败保留已有记录。

## 失败与重试

- 新学科创建失败时不上传文件；创建成功后记录其编号，上传失败后重试沿用该编号。
- 批量上传返回逐文件结果。部分成功时保留窗口，只留下失败文件供重试，并说明已保存的数量；不重复提交成功文件。
- 提交前发现学科不可用，不发送文件。文件已经保存后发现学科被删除，保留原件和记录并说明情况，让用户重新选择目标。
- 转移请求携带原资料修订号。本机服务拒绝旧修订号，页面显示具体原因，不能用旧值覆盖新归属。
- 本机保存成功但浏览器缓存或列表刷新失败，分别说明保存结果和刷新结果，不将已保存的原件当作丢失。

当前学科目录属于本浏览器的个人记录，本机资料服务管理文件与资料元数据。上述流程不迁移现有存储，也不声称已提供跨浏览器的统一事务；若需多个浏览器共同管理一套学科，须先确定共享元数据的保存位置和并发规则。

## 验证

自动测试覆盖目录删除与旧记录、提前转移、IndexedDB 重新打开、上传前与上传中的目标变化、学科改名、部分上传失败及只重试失败文件，以及保存完成后立即上传。延迟请求测试覆盖列表响应倒序、写入后的旧响应、旧错误、浏览器缓存晚于写入返回和当前请求失败。

网页验证使用独立测试目录及工作区提供的文件。测试不调用真实 AI，也不删除用户学科或原始文件。当前检查和测试结果随本特性实现更新。

检查结果：网页 167 项测试、启动及许可证等 12 项测试通过，TypeScript、ESLint、Prettier 与发布构建通过。独立网页实测新建学科后立即批量上传：首个文件成功、第二个文件返回 503，窗口仅保留失败文件；重试只再次发送第二个文件，沿用同一学科编号。改名后标题和归类菜单同步，转移后源列表从 2 份变为 1 份、目标列表从 3 份变为 4 份。测试不调用 AI。
