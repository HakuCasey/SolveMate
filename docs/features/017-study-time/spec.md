# 017 学习时长统计

## 背景与目标

通过学习事件之间的时间差估算学习时长，替换头像下方和学习足迹中的示例统计。阅读、提问、AI 回复与笔记使用同一套计时规则，不要求用户手动开始或结束。

## 计时事件

| 类别 | 事件 |
| --- | --- |
| 阅读 | 打开或切换学习资料、题目，翻页、跳转、滚动、缩放、选择内容和展开答案 |
| 对话 | 打开历史对话、输入问题、添加或查看引用、发送问题 |
| AI 回复 | 开始回复、正文更新、回复结束；重复快照与连接心跳不续时 |
| 笔记 | 打开、编辑、保存笔记，以及添加摘录 |
| 暂停 | 离开学习页面、页面隐藏或关闭、连续 5 分钟没有计时事件 |

白名单在代码中集中维护。资料列表、官方内容管理、机器人配置、教研室占位页面和设置不单独计时。管理页面中若仍有实际 AI 回复，则由回复事件计时。后台页面不累计时间。

## 规则与保存

- 首个事件开始计时，后续事件结算间隔并续时。5 分钟内没有下一次事件时，在上次事件后第 5 分钟结算并暂停；之后再次发生事件重新计时，不包含中间空闲。
- AI 开始、正文更新与结束使用同一事件规则。AI 没有新进展时最多延续 5 分钟；AI 请求本身的超时规则独立维护。
- 一个人同时阅读、聊天或打开多个窗口，重叠时间只计一次。重复提交同一时间段不增加统计。
- 时间段跨午夜时按本机日期拆分；时钟异常跳变或长时间休眠不补算。
- 按分钟批量保存，暂停时补保存；事件只修改内存，不逐事件写数据库。保存失败保留未确认时间段和可见错误，允许重试，重新打开后继续提交。
- 正式统计保存在 `user/app.sqlite3`，浏览器只保留统计缓存和未确认时间段，不修改已有对话、笔记或机器人。
- 单日累计超过 24 小时时拒绝本次保存，保留原记录并记录错误。统一日志文件的设计见 `PLANS.md` 中的问题定位日志待办。

## 展示

头像下方提供累计学习和连续学习两排勋章。点击任意勋章显示同一个学习时长气泡，保留今日、本周、连续学习天数和累计时长；本周从周一开始。学习足迹按近 12 个自然周显示，未来日期置灰。今日尚未学习时，连续天数保留到昨日；不足一分钟明确显示“不足 1 分钟”。勋章依据真实统计显示，不将已有示例时长作为真实历史导入。

累计学习依次为炼气、筑基、结丹、元婴、化神、炼虚、大乘，分别在 1、8、16、32、64、128、256 小时点亮。连续学习使用火焰、炼丹炉与天数标记，分别在 1、3、7、14、30、60、100 天点亮，以历史最长连续天数判断，中断后保留已获得的勋章。1、3、7 天使用逐步增大的火焰；14、30、60、100 天使用从简到繁的炼丹炉，共用直颈、鼓腹、三足的鼎形，通过向上的双耳、颈部饰带、腹部纹样和炉足区分阶段。侧栏和统计气泡共用同一组图形。

图标使用主题色矢量图形，不带金属外框或光晕。已点亮时增加主体色块和浅色底；未点亮时为灰色空心轮廓。气泡内选中某枚勋章时显示按钮内侧描边，下方显示名称、点亮状态与条件。两处图标及状态读取同一份配置，不显示保存频率说明。

## 验收标准

- [x] 阅读、对话、笔记和 AI 回复使用相同事件规则，管理操作不会单独续时。
- [x] 5 分钟无事件、切换后台、休眠和跨午夜结果符合上述规则。
- [x] 多窗口重叠、重复提交和保存响应丢失不会重复累计。
- [x] 刷新、重新打开和保存失败后恢复均保留已确认记录及未确认时间段。
- [x] 统计展示不再使用示例数据，旧对话、笔记、机器人和配置不受影响。
- [x] 只在活动期间安排低频计时保存；暂停后没有持续的计时轮询。
