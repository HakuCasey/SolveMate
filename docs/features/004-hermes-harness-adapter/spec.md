# 004 Hermes 接入与多服务会话管理

## 背景与目标

SolveMate 通过现成 Harness 使用用户配置的模型、工具和原生会话。DSH 与 Hermes 的启动和模型接口不同；两项服务需要分别适配，并遵守相同的对话规则。

本特性接入本机 Hermes CLI 的 ACP 模式，同时整理 DSH 适配器、连接配置与会话绑定。不包含用户文件导入、Skill 安装、RAG 配置或外部会话目录导入。

## 用户行为

- 在“设置 → AI 配置”中选择 DSH 或 Hermes，检测连接、选择模型并保存。两项已保存的连接分别保留；最近保存的一项作为新对话的全局默认。
- 教师可以跟随全局服务，也可以选择一项已经配置的服务。教师页面与对话中的 AI 配置使用相同的选项与解析逻辑。
- 已开始的对话固定绑定教师与 Harness 连接；更改全局默认不会把旧对话转交给另一项服务。
- 在对话中切换教师时，提示“切换教师后对话重新开始，请确认是否切换？”；切换服务并保存时，提示“当前操作会切换 Harness 服务，对话将重新开始，请确认是否切换？”。确认后开始新对话，保留阅读关联、原对话及外部绑定；取消不提交这次切换。
- 同一服务内更换模型继续使用原生会话，不显示上述确认框。
- 连接检测、保存前复检及重启后的检测复用同一个专用会话。恢复失败不自动另建；创建结果不明时停止自动重试。用户确认原检测会话不可用后，可以明确重建。

连接检测显示已等待秒数；超过 5 秒时明确提示正在等待服务返回结果。整次协议检测最多等待 25 秒，之后清理本次进程并显示超时原因，不删除配置或自动重建会话。同一服务重复检测直接提示等待，不同服务分别检测。

## 验收范围

1. Hermes 模型列表来自 ACP，保留原始模型编号；自定义模型可选择并实际回答。
2. 首次提问、追问与本机服务重启后的继续提问使用同一原生会话；恢复过程中回放的历史不会重复进入新回复。
3. DSH 和 Hermes 分别保存连接及进程；一项服务的会话、停止与权限响应不会发给另一项服务。
4. 旧 DSH 数据迁移后保留原生会话编号、配置与执行记录。绑定不一致、原会话缺失、配置变化或程序不可用时明确报错，不替换原记录。
5. 页面验证确认和取消两种切换行为；原对话仍能打开与继续提问。归档对话保持只读。
6. 运行代码检查、单元测试和构建；macOS 进行真实 Harness 调用。Windows 通过自动测试检查启动参数、路径和进程管理，真实安装与账号调用另待实机验收。

## 当前边界

连接检测验证协议与模型目录，不验证每个模型的账号权限和额度。Hermes 必须已配置模型服务并具备 ACP 依赖。原生批处理入口与跨 WSL 调用不在本特性范围内。

本地重命名、标签、归档和删除尚未与 Harness 的管理接口同步。DSH 原生标题同步与外部会话变更处理仍是后续事项。
