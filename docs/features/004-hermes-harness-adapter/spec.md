# 004 Hermes 接入与多服务会话管理

## 背景与目标

SolveMate 通过现成 Harness 使用用户配置的模型、工具和原生会话。DSH 与 Hermes 的启动和模型接口不同；两项服务需要分别适配，并遵守相同的对话规则。

本特性接入本机 Hermes CLI 的 ACP 模式，同时整理 DSH 适配器、连接配置与会话绑定。不包含用户文件导入、Skill 安装、RAG 配置或外部会话目录导入。

## 用户行为

- 在“设置 → AI 配置”中选择 DSH 或 Hermes，检测连接、选择模型并保存。两项已连接的配置分别保留；通过“设为默认”选择新对话使用的全局默认模型。
- 机器人可以使用全局默认模型，也可以选择一项已连接的服务。机器人页面与对话中的“AI 选择”使用相同的服务、模型、推理等级选项及解析逻辑，连接管理由“设置 → AI 配置”负责。
- 对话保留机器人身份，各服务分别保存原生会话关联；更改全局默认不改写已有对话的选择。
- 切换机器人建立新对话；切换服务保留当前对话与各服务关联，确认和取消规则见 [003 对话切换规则](../003-ai-harness-connection/spec.md#多服务接入中的对话切换规则)。
- 同一服务内更换模型继续使用原生会话，不显示上述确认框。
- Hermes 检测只读取自身模型目录，不创建、加载或命名检测会话。正式会话通过原生 Gateway 接口在创建时指定所选模型，再由 ACP 加载同一编号；不先初始化全局默认模型。创建结果不明时停止自动重试；已取得编号后加载失败，保留编号供恢复。

连接检测显示已等待秒数；超过 5 秒时明确提示正在等待服务返回结果。整次协议检测最多等待 25 秒，之后清理本次进程并显示超时原因，不删除配置或自动重建会话。同一服务重复检测直接提示等待，不同服务分别检测。

## 验收范围

1. Hermes 模型列表通过安装内的原生目录 SDK 获取，保留与 ACP 相同的原始模型编号；自定义模型可选择并实际回答。
2. 首次提问、追问与本机服务重启后的继续提问使用同一原生会话；恢复过程中回放的历史不会重复进入新回复。
3. DSH 和 Hermes 分别保存连接及进程；一项服务的会话、停止与权限响应不会发给另一项服务。
4. 旧 DSH 数据迁移后保留原生会话编号、配置与执行记录。绑定不一致、原会话缺失、配置变化或程序不可用时明确报错，不替换原记录。
5. 页面验证确认和取消两种切换行为；原对话仍能打开与继续提问。归档对话保持只读。
6. 推理等级来自 ACP 配置选项；旧版通过 Hermes 原生会话控制接口获取。提问前应用所选等级，设置后核对返回值；会话恢复不丢失此配置，失败时保留原绑定并说明原因。
7. 运行代码检查、单元测试和构建；macOS 进行真实 Harness 调用。Windows 通过自动测试检查启动参数、路径和进程管理，真实安装与账号调用另待实机验收。

## 当前边界

连接检测验证协议与模型目录，不验证每个模型的账号权限和额度。Hermes 必须已配置模型服务，具备 ACP 严格加载能力及支持指定模型创建会话的 Gateway SDK。接口不可用时提示更新，不回退到默认模型或改写全局配置。原生批处理入口与跨 WSL 调用不在本特性范围内。

Hermes 支持按原生编号同步会话名称；标签、归档和本地删除不改变第三方会话。DSH 原生标题同步与外部会话变更处理仍是后续事项。
