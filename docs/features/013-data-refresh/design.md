# 013 数据刷新与冲突处理设计

## 职责

`refresh/coordinator.ts` 集中登记记录、资料、课程和 AI 连接的读取函数，合并并发读取，并统一处理窗口重新获得焦点、恢复可见、恢复网络和手动刷新。同一秒内的窗口事件合并，不周期读取全部业务记录。写入使旧查询失效时，最多补读一次；读取失败不递归刷新。业务写入不由调度器重放。资料转换进度和 AI 流式回复仍使用原有任务编号及进度读取。

HTTP 错误统一包含 `code` 和 `status`。404、409 触发相关记录刷新；字段校验、服务中断与格式错误分别说明，不按报错文字猜测冲突类型。

## 已确认记录与本页修改

`LocalDataController` 分别维护上次确认的记录、本页工作副本与刚读取的正式记录，按稳定编号进行三方比较：

- 一方未改变的字段采用另一方值；不同对象或不同字段的修改合并。
- 同一字段两方都有不同修改时保留本页内容，记录字段位置与双方值，等待用户选择。后续刷新更新比较值，不能把尚未选择的冲突视为已确认。
- AI 配置、原生绑定及执行快照作为整体比较，不能混合连接与模型、原生编号等关联字段。AI 回复按执行编号和结果修订号采用匹配的结果与正文。
- 已删除的会话以正式删除状态为准。物理删除的其他对象若含本页修改，则保留备份并要求移除失效对象，不自动重建。

刷新与配置提交串行，期间到达的回复暂存，读取结束后处理；不关闭流式连接。窗口的阅读入口保留在本窗口。合并后有未确认修改时不自动写回，避免重做删除或覆盖已变更的内容。

## 未保存内容

`refresh/drafts.ts` 提供同一套表单草稿保存接口。草稿有独立编号、名称、值与时间，放在浏览器缓存，不能当作已经保存到 `user/` 的正式配置。显式取消或成功保存时清除；组件因数据变化而卸载时不清除。当前仍在编辑的表单计入状态栏的“有未保存修改”，保留的历史草稿单独列出，避免把已有备份误报为当前未保存。缓存写入按草稿编号排队，取消操作不能被先前的慢写入撤销。

保存失败的完整候选记录由存储控制器另外保留，包含当时的基线与候选值；失败的事务尚未发布到页面也有副本。提问草稿继续按对话或阅读范围编号保存。状态栏的记录保存气泡提供“未保存内容”，统一查看、冲突选择及 JSON 导出；恢复旧草稿不自动覆盖正式记录。

需要修订号的编辑使用共用检查。读到更新后的记录不会重置输入，保存时先提示核对，再由用户重新确认保存。

## 文件变化

资料服务在列表和单条读取时计算 `availability`，不修改资料编号、版本或正式修订号。原件与阅读文件分别判断；记录损坏以 422 返回，缺失以 404 返回。部分列表无法读取时保留已有缓存条目并标记不可用，不能把损坏误认为删除。

课程索引返回版本文件是否存在。缺失时继续保留正式索引；有校验通过的缓存时仍可阅读，并提示恢复或重新下载。单份课程无法读取不阻止其他课程、笔记和对话打开。缓存只能在服务不可达或服务故障时作为读取副本，不掩盖位置不符或格式错误。

## 验证

自动测试覆盖并发读取合并、递归刷新防护、独立修改合并、同字段冲突与再次刷新、删除后的草稿、缓存慢写取消、保存失败副本、刷新期间回复接收及文件缺失恢复。2026-11-12：251 项网页测试、19 项脚本测试、200 项本机服务测试与 24 项官方内容服务测试通过，另有 2 项按条件跳过。TypeScript、ESLint、Prettier、Ruff、依赖一致性、共享 Schema 检查及网页构建通过。

Chrome 使用独立本机目录和两个不同站点缓存，验证另一处保存后的表单保留与过期提示、断线期间的输入、同字段草稿冲突比较及选择、应用更新后的草稿恢复、资料文件删除与恢复、原笔记删除后的保存拦截，以及日间和夜间的提示窗口。后台执行与刷新交错通过自动测试验证，未调用真实 Codex 或其他模型。正式服务重启前确认没有运行中的 AI 请求或资料转换，重启后核对个人记录及原生 AI 数据库内容未变。

本次浏览器操作在 macOS Chrome 完成，Windows 真机和其他浏览器的实际操作尚未验收；自动检查不能替代这些环境的实际操作。
