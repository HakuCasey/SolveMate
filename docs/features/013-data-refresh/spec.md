# 013 数据刷新与冲突处理

## 背景与目标

多个窗口或浏览器读取同一份本机数据，页面中的记录可能落后于实际数据；用户也可能在文件管理器中移动或删除文件。刷新应重新核对实际记录，保留尚未保存的输入，不能要求用户先重载整个网页。

## 操作与判断

- “设置”提供“刷新数据”。窗口重新获得焦点、恢复可见或恢复网络时，通过同一机制读取对话、笔记、机器人、学科、资料和 AI 连接；相邻事件合并，不固定每 15 秒读取。
- 版本冲突或记录不存在时，读取有关数据并说明原因，不自动重复保存、删除、上传或提交 AI 问题。
- 不同字段的修改可合并；同一字段存在不同修改时保留本页值，在“未保存内容”中比较并选择。选择完成后，由用户确认并重试保存。
- 对方已删除的记录不自动重建。尚未保存的修改保留副本；对话收到迟到回复也不能撤销删除。
- 数据刷新保留当前页面、表单输入、提问草稿、选段和阅读位置。表单对应条目被删除、导致编辑界面关闭时，仍可从“未保存内容”查看并导出草稿。用户明确取消的表单修改不再保留。
- 原文件或阅读文件缺失时显示具体情况。原件仍在时可重试处理；文件恢复后刷新可重新打开。课程文件缺失时保留历史索引和已校验缓存，不影响其他记录。
- 服务不可达、数据格式无效或缓存备份失败时说明原因。未保存内容仍留在当前窗口；缓存写入失败时提示保留页面并导出，不能声称已经备份成功。

“刷新数据”读取业务记录；“更新应用”启用新版程序，两者分别处理。

## 验收

1. 两处修改不同字段，刷新后可见两份修改，刷新本身不重新执行保存。
2. 两处修改同一字段，重复刷新仍须确认，比较区显示最新值；选择后可明确保存。
3. 编辑期间原记录被删除，输入不丢失，不能通过保存旧表单重新创建原条目。
4. 后台回复与刷新同时发生，已到达的文字、执行编号和对应版本保留，不另建请求。
5. 文件缺失、记录损坏或服务中断时，保留可用记录与输入；恢复后可重试刷新。
6. 日间、夜间模式下提示与草稿窗口均可读。测试使用独立目录和缓存，不调用真实 Codex。

记录保存气泡仅在当前存在保存失败或未提交表单时使用“处理未保存内容”，冲突直接提供“处理修改冲突”。已保存的提问草稿不作为未保存内容重复展示；历史表单草稿与失败备份从“恢复记录”查看。每份失败备份提供“重新保存这份记录”，按原基线与最新记录合并，冲突需确认；成功后移出待恢复列表，失败保留备份和原因。
