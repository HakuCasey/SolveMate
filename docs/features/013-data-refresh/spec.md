# 013 数据刷新与冲突处理

## 背景与目标

多个窗口或浏览器读取同一份本机数据，页面中的记录可能落后于实际数据；用户也可能在文件管理器中移动或删除文件。刷新应重新核对实际记录，保留尚未保存的输入，不能要求用户先重载整个网页。

## 操作与判断

- “设置”提供“刷新数据”。窗口重新获得焦点、恢复可见或恢复网络时，通过同一机制读取对话、笔记、机器人、学科、资料和 AI 连接；相邻事件合并，不固定每 15 秒读取。
- 版本冲突或记录不存在时，读取有关数据并说明原因，不自动重复保存、删除、上传或提交 AI 问题。
- 不同字段的修改可合并；同一字段存在不同修改时保留本页值，在“操作状态 → 处理修改冲突”中比较并选择。选择完成后，由用户确认并重试保存。
- 对方已删除的记录不自动重建。已提交但保存失败的修改由存储控制器保留；对话收到迟到回复也不能撤销删除。
- 数据刷新保留当前页面、仍打开的表单输入、尚未发送的提问、选段和阅读位置。未提交的表单只在当前窗口编辑，不另存历史副本，也不提供关闭后的恢复入口。保存时检查原条目是否仍有效，不能通过旧表单重建已删除条目。
- 原文件或阅读文件缺失时显示具体情况。原件仍在时可重试处理；文件恢复后刷新可重新打开。课程文件缺失时保留历史索引和已校验缓存，不影响其他记录。
- 服务不可达、数据格式无效或缓存备份失败时，在“操作状态”中说明原因。仍打开的表单保留输入；保存失败和读取失败分别提供重试或重新读取，不能声称已经保存或备份成功。

“刷新数据”读取业务记录；“更新应用”启用新版程序，两者分别处理。

## 验收

1. 两处修改不同字段，刷新后可见两份修改，刷新本身不重新执行保存。
2. 两处修改同一字段，重复刷新仍须确认，比较区显示最新值；选择后可明确保存。
3. 编辑期间原记录被删除，仍打开的编辑窗口保留输入并拒绝保存，不能通过旧表单重新创建原条目。
4. 后台回复与刷新同时发生，已到达的文字、执行编号和对应版本保留，不另建请求。
5. 文件缺失、记录损坏或服务中断时，保留可用记录与输入；恢复后可重试刷新。
6. 日间、夜间模式下提示与操作详情窗口均可读。测试使用独立目录和缓存，不调用真实 Codex。

“操作状态”始终提供“查看详情”，没有失败记录时显示“暂无失败记录”。详情用于查看和导出失败诊断，不列出表单输入或保存备份。当前记录保存失败时提供“重试”，按原基线与最新记录核对后再保存；存在冲突时先选择要保留的内容。完整数据备份和恢复由 [018](../018-data-backup/spec.md) 提供。
