# 010 技术设计

## 数据归属

`AppData.noteLibrary` 保存笔记本、笔记和自定义标签，通过统一个人记录接口保存到 `user/app.sqlite3`，浏览器保存缓存。共享类型位于 `packages/contracts/src/index.ts`，校验及变更规则集中在 `state/notes.ts`，页面通过已有 `saveChanges` 提交。

| 对象       | 关键字段与关联                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------- |
| `Notebook` | `id`、`title`、`revision`；固定编号 `notebook-unclassified` 表示“未分类”                          |
| `Note`     | `id`、`notebookId`、`title`、`content`、`tagIds`、`revision`、`createdAt`、`updatedAt`、`origins` |
| `NoteTag`  | 自定义标签的 `id` 与 `title`，统一保存于 `customTags`，笔记通过编号引用                           |
| 学科标签   | 标签编号为 `subject:<学科编号>`，名称从统一目录读取。笔记本身不保存学科编号，已有标签保留         |

笔记正文使用 Markdown，预览从正文首个非空行生成，不保存 `summary`。资料与对话关联统一由 `origins` 表达，不保留顶层 `courseId`、`questionId`、`source`、`excerpt`。

### 来源集合

每项来源通过 `kind` 区分位置，资料与对话名称从当前记录读取，不重复维护名称：

| `kind`         | 定位字段                              | 含义                                                            |
| -------------- | ------------------------------------- | --------------------------------------------------------------- |
| `document`     | `materialId`、`version`、`pageNumber` | PDF 或 PPT；上传资料使用现有 UUID，官方资料使用现有目录条目编号 |
| `question`     | `materialId`、`version`、`questionId` | 题集编号、固定版本和题号                                        |
| `conversation` | `conversationId`、`messageIds`        | SolveMate 对话和原消息编号，不使用第三方 Harness 编号           |

来源只保存编号、版本和页码或题号，或对话与消息编号，不保存引用原文及选段起止位置。查看资料来源时打开固定版本的页面或题目，查看对话来源时打开原对话并定位消息。笔记正文独立保存，编辑正文不改写来源。手写笔记的 `origins` 可以为空；来源不可用时保留定位信息，不转向同名对象。

### 笔记标题

笔记标题最多 24 个 Unicode 字符，选段生成、新建、编辑与重命名共用截断函数，超出直接截断，正文保持完整。限制由共享应用 Schema 定义，前后端读取同一值；已有记录备份后转换，保留编号、正文和来源。

### 时间与修订

时间使用 Unix 毫秒。新建时 `createdAt` 与 `updatedAt` 相同；正文编辑、重命名、改标签、移动、删除笔记本后转移及合并，均通过同一修改函数提高修订号并更新 `updatedAt`，保留创建时间。修订号用于保存冲突检查，不表示保留历史版本。现有列表顺序不改变，不增加排序字段。

学科标签与自定义标签各自保留身份。删除学科后，已有标签通过保留的学科记录显示原名称，新选择只列出有效学科和该笔记已应用的标签。创建同名标签复用当前已有项，不复制定义。

## 保存与兼容

旧记录缺少 `noteLibrary` 时，由初始化函数复制示例和固定笔记本并保存。已经存在的空笔记集合必须保留，不能按“空”重新初始化。笔记结构不改变 AI 元数据格式或原有对话。

删除笔记本时，在同一个 `AppData` 变更中移除笔记本，并按选择删除笔记或修改其 `notebookId`。修改关系时递增笔记修订号；笔记的编号、正文、标签、来源和创建时间不改变，转移时更新修订号与更新时间。单条笔记删除不会删除其他笔记或公共标签。

窗口打开时保存目标编号及修订号。提交使用当前完整状态，核对目标仍存在且修订号一致，再通过本机服务的整体保存版本检查写入 `user/app.sqlite3`。保存成功才更新页面和提示；失败保留原状态和窗口输入。

## 界面

`NotebookList` 展示目录和两行条目，`NoteManagementDialog` 处理输入、标签选择及确认，不直接写存储。列表、纸页与导出共用自定义标签显示规则，不显示学科标签，已有标签编号保持原样。标签管理继续使用统一目录解析名称。预览由正文首行去除简单 Markdown 标记后截取，不调用 AI。

`PaneHeader` 只负责共用的标题栏布局，供对话列表、笔记列表和笔记正文使用：高度为 52 像素，图标、标题与数量同排，操作靠右。笔记本名称按当前笔记的 `notebookId` 读取，来源继续由 `LearningRelations` 解析，不另存一份展示数据。来源入口位于每篇笔记条目的标题后，统一显示“查看来源（数量）”，点击展开各条来源；来源不可用时在列表中显示并禁用对应项。笔记本标题栏仅保留笔记本名称和编辑操作，纸页独立滚动。

当前笔记转移后展开实际所属笔记本；删除当前笔记后选取仍存在的笔记，空集合显示空状态。右键菜单和窗口使用现有主题变量，不新增独立配色。

`moveNote` 使用目标笔记本编号，或新笔记本名称，检查笔记修订号、目标存在性与重名后一次返回更新后的笔记库。新建失败不会留下空笔记本；保存成功后列表选中该笔记并展开目标笔记本，顶部名称继续按 `notebookId` 解析。编辑正文只更新标题与正文，列表预览从正文读取，不接收笔记本归属变更；两项操作沿用现有冲突检查与草稿备份。

## 选段记录与 PDF 导出

`NotebookDestinationSelect` 统一提供已有笔记本与新建笔记本选项，供新建笔记、选段记录和更换笔记本使用。`NoteDestination` 表示已有编号或新名称；状态层一次校验、创建笔记本并保存笔记，取消或保存失败不留下空笔记本。打开选择窗口后使用稳定编号，列表刷新不覆盖用户输入，目标删除时要求重新选择。

`Note.origins` 统一保存资料与对话来源，按编号及位置建立关联。阅读来源保留固定版本与页码或题号，对话来源保留对话及消息编号；选段写入笔记正文后可独立编辑，来源中不保存原文副本。共用的选区操作通过应用层调用添加引用或记录笔记，加入对话仍遵循最多四条的限制。

笔记本右键导出 PDF，按当前笔记顺序生成标题、目录和各篇正文。前端复用 Markdown 与 KaTeX 排版，内嵌导出需要的字体；本机服务使用独立临时目录和 Chrome／Edge 的无界面打印生成 PDF，不使用用户的浏览器配置，不访问外部资源。正常、失败、超时及取消后清理本次进程和临时文件，不修改原笔记。缺少打印程序时说明安装要求，允许重试。

笔记本复用 [016 的统一导出窗口](../016-configuration-import-export/design.md)，文件名为 `<笔记本名称>_<YYYY-MM-DD>.pdf`。默认由本机服务写入系统下载目录；自选目录通过浏览器授权。按钮显示实际导出用时，成功后保留结果 3 秒再关闭，失败保留输入；同名文件添加数字后缀。

### PDF 文档标题

PDF 内部标题使用已保存的笔记本名称，与正文标题读取同一对象。本机服务核对笔记本编号、修订号及笔记集合后，将名称转义写入打印页面的 title；网页不另传一份名称，正文片段不能覆盖文档标题。临时排版文件名 notebook.html 不作为 PDF 标题。

2026-11-14：23 项 PDF 及文件导出相关测试通过，覆盖标题来源、特殊字符转义、正文不能覆盖标题、保存版本与来源检查、超时清理及文件保存。Chrome 实际生成的 PDF 内部标题为“C 语言笔记”；既有 4 页验收文件的标题修正版通过逐页文字和渲染对比，正文与排版保持一致。未调用 AI 服务。

## 同一笔记本内合并

`mergeNotes` 接收笔记本编号及所选笔记的编号、修订号，核对归属与修订后按 `noteLibrary.notes` 的显示顺序合并。第一篇保留编号、标题及所在位置，修订号递增；各篇标题、正文以 Markdown 分隔拼接，标签按编号去重，其余所选条目从同一次保存中移除。未选条目保持不变。正文超过现有的 100000 字符上限时拒绝合并。

合并以 `origins` 保存全部资料和对话来源，按来源编号、版本及位置去重，不复制原笔记全文。保留第一篇的编号、创建时间与列表位置，更新时间为本次修改时间；再次合并继续汇总来源。资料关联、原文跳转与 PDF 导出均读取同一集合，展示名称由 `LearningRelations.describeOrigin` 解析。共享 Schema 同步到本机服务，保存及重新读取使用同一结构校验。

`NotebookList` 仅保存当前笔记本的多选状态与修订号。合并确认复用 `NoteManagementDialog`，成功持久化后退出多选并打开合并笔记；失败保留选择和确认窗口。每篇笔记的来源入口复用现有气泡组件，按原位置或原消息打开，不额外维护来源展示数据。

## 现有记录转换

浏览器缓存及导入记录通过共享的 `migrateNoteMetadata` 转换；本机 SQLite 在启动时转换。前后端使用同一组 JSON 样例核对结果。已有资料位置、单一选段及合并来源汇总到 `origins`，保留原对话与消息编号；缺少新版来源字段的题目笔记从已有课程、题号建立题集来源。来源中的 `quote` 不写入转换结果，相同编号与位置的来源合并为一项；原始记录通过已有备份流程保留。完成后移除旧字段，保留笔记编号、所属笔记本、标题、正文、标签、修订号和列表顺序。

旧记录有可靠时间时沿用；没有时间时保存 `null`，不以转换时间冒充创建或修改时间。后续修改记录实际更新时间。转换不修改输入，不重建示例，不修改对话或其他模块记录。

本机转换先完整校验，再将原始应用记录写入 `user/backups/notes-<sha256>.json`，最后在 SQLite 事务中替换并提高整体保存版本。备份或写入失败均保留原记录；重复启动不重复转换。浏览器缓存转换前保留原始记录，失败保存的整份记录在恢复前也转换为同一结构；浏览器导入保留原始迁移备份。完整 ZIP 备份在恢复暂存目录中转换，原 ZIP 和恢复前备份均保留。正常保存只接受当前结构，旧页面不能把笔记改回旧格式。
