# 015 资料与学习记录关联设计

## 整体检视

| 部分     | 核对结果与本次处理                                                                                                       |
| -------- | ------------------------------------------------------------------------------------------------------------------------ |
| 资料管理 | 官方内容和上传资料已有稳定编号、版本和删除记录，继续复用，不移动文件或另建资料表。学科作为可调整的分类，不作为资料身份。 |
| 对话管理 | 已记录主要资料及逐条消息引用，已有原生会话绑定。关联查询同时读取两者，不增加第三方会话字段，不按资料重建会话。           |
| 笔记管理 | 原来源仅有课程与题号，不能表达 PDF 页码和教材章节。增加可选来源，提供正文创建、编辑和返回原文。                          |
| 阅读界面 | 保留当前三栏布局，在阅读栏提供按需展开的相关内容入口，复用现有对话恢复和笔记页面。                                       |
| 数据保存 | 关联查询从正式记录生成，不新增持久化关联表、计数或文件目录；新字段由共享 Schema 和现有保存版本检查保护。                 |

## 资料身份与来源位置

共享类型 `LearningLocation` 复用 `ReadingSelection | MaterialLocation`。用户资料使用原 UUID，官方学习资料使用课程、类型和文档编号，题目使用课程、类型与题号。`learningMaterialId` 生成比较用的编号，不包含分类、名称、版本、章节或页码。

资料身份用于汇总相关内容，来源位置用于恢复原文；汇总不同版本不代表合并这些版本的对话。`Conversation.selection`、`Conversation.material` 与消息引用继续按原格式保存，每个会话仍按自己的原生绑定运行。

`Note.origins` 统一保存 PDF/PPT 页码、题集题号及 SolveMate 对话消息。资料来源使用稳定资料编号、固定版本及位置；对话来源保存对话与消息编号。来源不保存引用原文或选段范围；笔记不另存学科编号。`locationForOrigin` 将资料来源转换为现有阅读器位置，原文跳转、相关内容与导出共用同一记录及名称解析。来源字段与现有记录转换规则见 [010](../010-notebook-management/design.md)。

## 业务职责

- `reading/relations.ts` 中的 `LearningMaterial` 统一解析资料名称、当前位置、分类、移除及可用状态。当前名称来自原资料对象，来源位置继续使用记录中的版本。
- `LearningRelations` 从对话主要资料、消息引用和笔记来源构造内存查询索引；按会话编号去重，过滤删除记录，保留归档记录。记录刷新后重新生成，不保存第二套关联数据。
- `state/notes.ts` 集中处理创建和编辑，校验来源、笔记本及修订号；标题、正文、预览和笔记本在一次变更中提交，保留标签与来源。
- `RelatedLearning` 只展示查询结果并调用打开或创建操作。官方内容和 PDF 阅读器使用同一个组件；`ConversationList` 复用资料对象解析来源，不另外拼接一套资料信息。
- `NoteEditorDialog` 创建时可选择笔记本，编辑时仅显示标题和正文，归属调整通过条目右键的“更换笔记本”完成。编辑窗口保留打开时的来源与编辑基线，沿用表单草稿和冲突检查。保存失败不关闭窗口；原笔记被删除时不允许以编辑操作重新创建。

个人记录继续保存到 `user/app.sqlite3`，文件继续在原目录。可选字段由前后端共享的应用 Schema 校验，不需要重建数据库。旧记录仍可读取；旧版程序不认识新字段时不会被用来写入新记录。

## 失败与历史处理

资料删除仅影响当前列表，相关记录仍保留原编号；查看笔记不会重新添加资料。来源文件或版本不可用时保留笔记正文与位置，阅读器按实际读取结果提示，不重定向到同名资料或最新版本。资料在编辑期间移动，不改变已捕获来源；保存时重新核对笔记和目标笔记本。

已有 AI 流式执行由应用层管理，查看关联内容或切换到笔记不取消生成。应用更新前检查现有表单草稿，未保存时保持当前页面。
