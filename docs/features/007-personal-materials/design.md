# 007 技术设计

## 职责与对象

资料文件由 `apps/local` 管理。新增独立的资料存取与 PPTX 转换文件，不将上传、转换分支堆进 AI 适配器。阅读器负责 PDF 显示和选区，AI 管理继续使用共用的文字请求、流式回复和原生会话恢复。

共享 JSON Schema 增加资料、固定版本、页面位置与引用字段，生成 TypeScript 与 Python 校验源。现有 `ReadingSelection` 继续描述官方教材和题目；用户资料使用 `MaterialLocation`，不伪装成课程题号。会话可选的 `material` 字段指向最近提问的位置，消息引用是独立快照。旧记录没有这些字段时继续按原含义读取。

`user/uploads/<资料编号>/<版本>/` 保存原件和转换结果；`record.json` 保存元数据，先写临时文件再原子替换。编号使用 UUID，版本使用原件 SHA-256；用户文件名只作显示，不参与目录拼接。首次导入的源文件固定，同一科目重复导入同一文件复用原记录。页面文字按固定阅读文件提取，按需缓存。目录和数据库职责不作无关调整。

## 资料条目管理

上传资料的右键菜单集中提供重命名、移动和删除。三个操作通过本机资料接口更新同一份元数据，使用 `expectedRevision` 检查并发修改；名称只作显示，不修改文件路径、资料编号和内容版本。

`Material.deletedAt` 为可选删除时间，旧记录缺少该字段时视为未删除。删除后仍保留元数据、原件和阅读文件；本机列表返回保留记录，前端统一通过 `materialMembership` 排除删除条目，历史对话按固定编号与版本读取。重新导入相同文件创建新条目，不恢复原删除记录。后台处理只合并版本处理结果，不覆盖标题、归属和删除标记。

修改成功后立即更新页面和浏览器缓存。旧查询不得覆盖新记录；刷新失败时保留保存结果并显示提示。失败或修订冲突不显示成功，读取最新记录后允许用户重新操作。

## 导入与恢复

浏览器以带本机客户端标识和 Origin 的文件流上传。服务限制实际接收字节数，拒绝不支持的扩展名，校验格式，原子保存原件后返回记录，异步完成解析或转换。任务有超时；转换使用独立 LibreOffice profile，避免占用用户已打开的办公文档。程序通过 PATH、macOS 应用路径、Windows Program Files 或显式环境变量查找，不执行 shell 拼接命令。

服务重启时将未完成的处理标记为可重试，不自动重复上传。转换输出先在临时目录完成并验证，成功后才发布可读文件。转换器缺失、输出为空、超时或文件损坏分别报告；已有原件保留。处理状态由本机记录提供，网页不自行宣布成功。

## 阅读与 AI 引用

PDF.js 使用与应用一起分发的 worker、字符映射和字体资源，不依赖 CDN。每次只渲染当前页，异步结果按资料和页码隔离，缩放不改变资料身份。

临时文字选区由浏览器管理，共用 Hook 在选区上方显示“添加到侧边对话”。确认后生成独立编号的引用草稿，保存资料编号、版本、页码与文字快照。输入框上沿逐条显示前 15 个字、全文展开和删除按钮；重复添加同一位置的相同文字不新增一条。选区与引用操作不请求 AI。

新消息、执行请求和执行结果使用 `references` 数组，兼容旧记录的单条 `reference`。每次提问固定引用列表，前后端按共享请求约定校验最多 4 条内容，总文字不超过 100,000 字符。超出数量时提示“为保证对话质量，当前最多支持 4 条内容。”已有草稿不截断，提问前需要移除超出的引用；历史消息与执行结果保留原引用。后端逐条验证资料位置，统一交给 Harness 适配器，保留各条资料名、页码和原文。资料内容作为学习材料，不作为工具执行指令。未添加片段时只提交问题，不自动附带整页文字。

PDF 与内置内容共用 `reading/` 中的应用层阅读状态，数据结构与恢复规则见 [001 统一阅读状态](../001-instant-question-answering/design.md#统一阅读状态)。PDF 缩放、最后页码和待发送引用按资料版本保存，双向滚动按页码保存；异步渲染完成后再恢复位置，切页不统一滚回顶部。内置章节和题目的引用分别按阅读位置保存。切换页面或重建 PDF 文字层不会清除已添加引用，临时选区不恢复高亮。提问保存成功后移除该轮已提交的片段，异步保存期间新添加的引用继续保留。

PDF 图片和图表可以显示，但首版文字请求不表示已传递图像。没有文字或引用过大时明确提示，不静默截断。完整资料检索、OCR、跨页选区和区域图片提问不纳入首版。

## 科目、列表与阅读

科目入口只决定列表范围，不修改持久化阅读位置或旧对话。`LibraryScope` 用科目编号和内容类型描述当前列表；空科目编号表示旧的未分类资料。官方内容继续使用 `ReadingSelection`，用户文件继续使用 `MaterialLocation`，统一列表中的条目通过类型区分来源，不把用户文件伪装成教材章节。

文件列表按 `Material.courseId` 过滤；未知或未指定科目的旧记录进入未分类列表。归属变更使用原资料编号与期望修订号进行校验，只修改科目和记录修订号。后台处理提交结果时重新读取最新元数据，只更新处理结果，避免覆盖处理期间发生的科目调整。重复导入以科目编号和文件校验值共同判断。

阅读器只负责已打开的条目与必要的章节、页面或题目导航。返回按钮依据当前阅读对象找到对应列表；从历史对话或引用直接返回阅读时，同样能够返回所属列表。列表页不把未打开的条目作为本次提问的资料，也不取消应用层正在生成的回复。
