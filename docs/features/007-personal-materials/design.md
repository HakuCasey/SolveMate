# 007 技术设计

## 职责与对象

资料文件由 `apps/local` 管理。新增独立的资料存取与 PPTX 转换文件，不将上传、转换分支堆进 AI 适配器。阅读器负责 PDF 显示和选区，AI 管理继续使用共用的文字请求、流式回复和原生会话恢复。

共享 JSON Schema 定义资料、固定版本、页面位置与引用字段，生成 TypeScript 与 Python 校验源。`ReadingSelection` 描述官方资料和题目；用户资料使用 `MaterialLocation`。会话可选的 `material` 字段指向最近提问的位置，消息引用是独立快照。已有记录原样保留，使用其中的引用时按当前格式校验。

`user/uploads/<资料编号>/<版本>/` 保存原件和转换结果；`record.json` 保存元数据，先写临时文件再原子替换。编号使用 UUID，版本使用原件 SHA-256；用户文件名只作显示，不参与目录拼接。首次导入的源文件固定，同一科目重复导入同一文件复用原记录。页面文字按固定阅读文件提取，按需缓存。目录和数据库职责不作无关调整。

## 资料条目管理

上传资料的右键菜单集中提供重命名、移动和删除。三个操作通过本机资料接口更新同一份元数据，使用 `expectedRevision` 检查并发修改；名称只作显示，不修改文件路径、资料编号和内容版本。

`Material.deletedAt` 为可选删除时间，旧记录缺少该字段时视为未删除。删除后仍保留元数据、原件和阅读文件；本机列表返回保留记录，前端统一通过 `materialMembership` 排除删除条目，历史对话按固定编号与版本读取。重新导入相同文件创建新条目，不恢复原删除记录。后台处理只合并版本处理结果，不覆盖标题、归属和删除标记。

修改成功后立即更新页面和浏览器缓存。旧查询不得覆盖新记录；刷新失败时保留保存结果并显示提示。失败或修订冲突不显示成功，读取最新记录后允许用户重新操作。

## 导入与恢复

浏览器以带本机客户端标识和 Origin 的文件流上传。服务限制实际接收字节数，拒绝不支持的扩展名，校验格式，原子保存原件后返回记录，异步完成解析或转换。任务有超时；转换使用独立 LibreOffice profile，避免占用用户已打开的办公文档。程序通过 PATH、macOS 应用路径、Windows Program Files 或显式环境变量查找，不执行 shell 拼接命令。

服务重启时将未完成的处理标记为可重试，不自动重复上传。转换输出先在临时目录完成并验证，成功后才发布可读文件。转换器缺失、输出为空、超时或文件损坏分别报告；已有原件保留。处理状态由本机记录提供，网页不自行宣布成功。上传窗口使用 XMLHttpRequest 的上传字节事件显示进度；传输达到 100% 后仍等待服务确认，不能当作处理完成。解析和转换显示持续进度条，不编造百分比；通过既有资料处理轮询读取真实结果。所有文件结束网络上传后允许关闭窗口，后台处理继续，列表保留进度。多文件重试只重新上传失败项，已保存原件的处理失败调用原记录的重试接口。

## 阅读与 AI 引用

PDF.js 使用与应用一起分发的 worker、字符映射和字体资源，不依赖 CDN。每次只渲染当前页，异步结果按资料和页码隔离，缩放不改变资料身份。

临时文字选区由浏览器管理，共用 Hook 在选区上方显示“添加到侧边对话”。确认后生成独立编号的引用草稿，保存资料编号、版本、页码与文字快照。输入框上沿逐条显示前 15 个字、全文展开和删除按钮；重复添加同一位置的相同文字不新增一条。选区与引用操作不请求 AI。

新消息、执行请求和执行结果使用 `references` 数组，兼容旧记录的单条 `reference`。每次提问固定引用列表，前后端按共享请求约定校验最多 4 条内容，总文字不超过 100,000 字符。超出数量时提示“为保证对话质量，当前最多支持 4 条内容。”已有草稿不截断，提问前需要移除超出的引用；历史消息与执行结果保留原引用。后端逐条验证资料位置，统一交给 Harness 适配器，保留各条资料名、页码和原文。资料内容作为学习材料，不作为工具执行指令。提问时自动附带当前关联页，手动片段作为补充引用，二者分别保存。

PDF 与内置内容共用 `reading/` 中的应用层阅读状态，数据结构与恢复规则见 [001 统一阅读状态](../001-instant-question-answering/design.md#统一阅读状态)。PDF 缩放、最后页码和待发送引用按资料版本保存，双向滚动按页码保存；异步渲染完成后再恢复位置，切页不统一滚回顶部。学习资料的补充引用按资料及版本保存，题目的补充引用按题目位置保存。切换页面或重建 PDF 文字层不会清除已添加引用，临时选区不恢复高亮。提问保存成功后移除该轮已提交的片段，异步保存期间新添加的引用继续保留。

PDF 图片和图表可以显示，但首版文字请求不表示已传递图像。没有文字或引用过大时明确提示，不静默截断。完整资料检索、OCR、跨页选区和区域图片提问不纳入首版。

### 关联内容与每轮提问

`LearningMaterial` 解析资料身份、固定版本、页码、显示标题和可发送正文。阅读位置必须符合当前引用格式，对话页、返回阅读和发送问题共用同一校验。缺少必需字段的记录直接提示“当前版本已不支持该引用方式”，不推断、不转换，也不补默认位置。对话页显示最后阅读的位置，发送后对话保存该位置，历史消息中的位置和正文保持不变。

当前引用位置的必需字段如下，字段含义由共享 Schema 校验：

| 对象                   | 必需元数据                                                         | 定位依据                            |
| ---------------------- | ------------------------------------------------------------------ | ----------------------------------- |
| 官方 PDF               | `courseId`、`version`、`kind: "textbooks"`、`itemId`、`pageNumber` | 明确版本的文件和 PDF 页码           |
| 上传 PDF／转换后的课件 | `materialId`、`contentVersion`、`pageNumber`                       | 原资料编号、固定内容版本和 PDF 页码 |
| 题目                   | `courseId`、`version`、`kind: "questions"`、`itemId`               | 明确版本的题目编号                  |
| 对话选段               | `conversationId`、`messageIds`                                     | 已保存的原消息编号                  |

`SupportedReadingReference` 在现有引用结构上规定当前定位条件；前端和请求服务读取同一份定义。`title` 用于显示，`content` 是提问时的正文快照。资料名、章节编号和文件路径都不代替稳定编号、版本或页码。无法按上述元数据定位的记录保持原样，使用时提示不支持，不推断或迁移。

消息、请求和执行结果增加可选的 `readingContext: ReadingReference`，保存本轮关联页的正文快照；`references` 继续保存用户确认的最多四条补充片段。自动关联页不占这四个名额，每页最多 100,000 字符；补充引用合计最多 100,000 字符。上传资料按原编号、固定版本和页码读取本机正文，官方资料从同版本 PDF 的逐页索引读取。普通对话没有关联内容，不继承后台停留的资料。

每次发送先固定位置、补充片段和问题，再读取关联正文并一起保存，之后提交 Harness。读取失败或该页无文字时仍保存问题、位置和失败原因，不调用模型，不把空正文当作已交付；重试按原位置补读。已有正文快照的重试不重新读取其他页面。缺少 `readingContext` 的旧消息按原含义保留，不补造过去发送过的内容。

本机 `prompting.py` 集中维护 `TURN_PROMPT_TEMPLATE`，各 Harness 适配器接收同一份组装结果。模板依次包含：

```text
{用户本轮问题，置于第一段}

本轮角色要求：
{机器人名称、角色指令和资料使用要求}

本轮关联的阅读内容（提问时的固定快照）：
{资料名 · 第 N 页}
资料页码：第 N 页
原文：{JSON 编码的正文字符串}

本轮问题引用的课程资料／对话内容：
{每条补充引用的名称、位置与正文}

当前会话尚未收到的历史消息：
{按消息编号过滤已确认收到的记录}
```

模板说明关联页和选段的用途，要求针对当前问题回答，不规定回复章节或固定讲解顺序。资料按数据处理；只有提取文字时，不声称已看到图片、图表或整份文件。每个原生会话分别记录已收到的消息编号与内容标记。关联页、补充引用和历史引用按固定来源及正文生成标记，只补发目标原生会话未收到的正文；已收到的内容保留位置与标记。切换服务或确认重建后，按目标会话的确认记录补充历史。模板版本为 `learning-discussion-v2`，每轮派发记录模板版本、原生编号、消息编号、内容标记及接收确认时间；只有收到回复、工具或权限事件，或调用正常返回，才登记已接收。完整引用快照仍保存在本地消息与执行中。

学习资料统一通过 PDF 阅读器展示，不再回退到 Markdown 章节正文。教材原文解析用于内容发布和目录，不参与阅读位置恢复；题目继续保留题干、答案与讲解。是否提示历史版本由官方资料对象比较实际 PDF 校验值或具体题目内容，课程包编号不同、同包其他内容更新均不单独触发该提示；无法确认内容差异时不作历史版本判断。

## 科目、列表与阅读

科目入口只决定列表范围，不修改持久化阅读位置或旧对话。`LibraryScope` 用科目编号和内容类型描述当前列表；空科目编号表示旧的未分类资料。官方内容继续使用 `ReadingSelection`，用户文件继续使用 `MaterialLocation`，统一列表中的条目通过类型区分来源，不把用户文件伪装成教材章节。

文件列表按 `Material.courseId` 过滤；未知或未指定科目的旧记录进入未分类列表。归属变更使用原资料编号与期望修订号进行校验，只修改科目和记录修订号。后台处理提交结果时重新读取最新元数据，只更新处理结果，避免覆盖处理期间发生的科目调整。重复导入以科目编号和文件校验值共同判断。

阅读器只负责已打开的条目与必要的章节、页面或题目导航。返回按钮依据当前阅读对象找到对应列表；从历史对话或引用直接返回阅读时，同样能够返回所属列表。列表页不把未打开的条目作为本次提问的资料，也不取消应用层正在生成的回复。

## PDF 连续阅读

阅读器使用已安装 PDF.js 的 `PDFViewer` 与 `ScrollMode.VERTICAL`、`ScrollMode.PAGE`，页面布局、文字层、可见页绘制及缓存由库管理，不一次绘制整本资料。实现依据见 [PDF.js 组件示例](https://github.com/mozilla/pdf.js/blob/master/examples/components/simpleviewer.mjs)与 [PDFViewer 实现](https://github.com/mozilla/pdf.js/blob/master/web/pdf_viewer.js)。官方和上传资料共用阅读器与 `PdfControls` 控件。底栏以左右等宽的三列排列，左侧为阅读设置图标，中间为翻页与页码，右侧为缩放。阅读设置复用 `PopoverPanel` 气泡，“页面连续”使用开关并直接读取已有的连续模式状态，默认开启，不另存一份设置。

单页模式在页底或页顶继续滚动时翻页，同一段触控板惯性滚动不会连续跳页。页码输入、按钮、键盘及滚动均更新原阅读位置，不创建新阅读现场。缩放与连续模式按资料版本保存，页内滚动相对视口顶部所在页记录；恢复布局期间不写入临时位置，滚动产生的页码回传不再次触发程序跳转。

引用从选区实际覆盖的 PDF 页面读取起止页码，不使用侧栏尚未更新的页码。跨页选段保留完整文字和页码范围，以起始页作为返回位置。退出阅读器时取消加载、渲染和事件观察，切换页面不影响正在生成的回复。

### PDF 文字层与画布对齐
