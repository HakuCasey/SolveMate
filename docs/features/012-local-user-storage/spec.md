# 012 本机用户数据保存

## 背景与目标

用户在同一台电脑换浏览器后，应能继续使用已有对话、笔记、机器人和资料。正式记录统一保存在项目的 `user/` 下，由本机服务读写，浏览器只保存缓存。现有浏览器记录和文件需要保留。

## 范围

- `app.sqlite3` 保存对话、消息、笔记本、笔记、机器人、学科、标签、设置、提问草稿与阅读进度。
- `uploads/` 保存用户上传的原件、处理记录、阅读 PDF 和按页文字。
- `community/` 保存获取的官方与社区资料及历史版本。当前下载入口仍是官方内容，不新增社区发布功能。
- `ai/` 保留现有连接、默认选择、原生会话绑定、执行与工作目录。
- `backups/` 保存浏览器迁移原值、迁移回执及替换前的本机数据库。

当前页面、菜单展开、弹窗与临时选区由窗口管理。普通刷新仍进入对话页；再次打开资料时恢复保存过的页码、滚动、缩放与答案状态。待发送引用沿用窗口内状态和 011 的更新恢复规则。

## 保存与读取

1. 同一电脑的不同浏览器连接同一本机服务，读取同一套正式记录。本机服务与官方内容服务分别运行，不连接官方服务器仍能保存和读取。
2. 本机事务成功且没有待保存表单时显示“更改已保存”；当前表单仍有修改时显示“有未保存修改”。失败说明原因，保留有效记录和未确认的修改。
3. 保存检查数据目录标识和记录版本。其他窗口已修改时，拒绝旧快照覆盖，保留本页修改，刷新后核对冲突再保存。
4. 页面获得焦点或处于可见状态时，定期读取最新记录。未保存修改通过 [013 的冲突规则](../013-data-refresh/spec.md)保留和比较，各窗口的阅读入口不随其他窗口跳转。
5. 本机服务不可达时可查看缓存；未能保存的修改明确显示失败并保留临时副本，不宣称已保存，也不自动合并多份离线记录。
6. 下载包完整校验并落盘后才提交版本指针。失败保留旧版，历史引用继续使用原版本。

## 迁移

- 原浏览器和原访问地址读取原始个人记录、旧格式备份和课程包；其他浏览器不能读取这份 IndexedDB。
- 正式导入前保存备份，通过校验后提交。对话、消息、教师、笔记、学科、资料及原生会话编号均保留，不调用 Harness 创建、改名或删除会话。
- 原浏览器数据库不删除，重复打开不重复导入。检测到来源记录变化时重新处理，不以时间新旧自动覆盖。
- 本机与浏览器都有不同记录时，由用户选择使用本机记录或导入浏览器记录；替换需要再次确认，先备份本机数据库。
- 默认旧资料目录 `user/materials/` 经完整复制与逐文件 SHA-256 核对后启用 `user/uploads/`，旧目录保留。显式指定的资料目录保持原位。
- 迁移失败保留旧数据，可重试；正式索引不能指向未写完整的课程包，复制未完成的目录不能启用。

## 验收

1. 旧浏览器的对话、笔记、教师配置和下载内容迁移后完整保留，原数据未被修改。
2. 独立浏览器存储能读取同一记录，保存修改后其他页面重新读取可见；旧页面写入被拒绝且修改保留。
3. 原生会话编号和历史资料引用不变，迁移不调用模型或 Harness 管理接口。
4. 服务断开、磁盘写入失败、迁移中断、缓存损坏和较新数据库格式均有处理，失败不覆盖旧记录。
5. 页面普通刷新与应用更新仍进入对话页，保存过的阅读位置与草稿可以恢复。

跨设备同步、自动定期备份以及用户目录与源码分离不在本特性范围。完整数据备份与恢复见 [018](../018-data-backup/spec.md)。`user/` 继续纳入 Git 管理。
