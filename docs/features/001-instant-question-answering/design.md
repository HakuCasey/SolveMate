# 001 高等数学题目阅读助手技术设计

> 当前状态：首个可运行版本已实现阅读、示例会话、笔记查看、机器人配置、本地保存与 PWA 离线使用，已完成基本验证。真实 AI 接入在后续阶段实现。

整体技术选择与多端职责见[整体架构](../../architecture/overview.md)。首版使用 React + TypeScript + Vite，以 Web/PWA 交付；客户端通过独立接口使用本地存储和用户配置的 AI 服务。

当前实施先完成不依赖真实 AI 的可运行版本，包括定稿页面、本地保存和离线使用。AI 配置与连接接口保留，实际 API / harness 的选择、连接和生成回复在后续阶段实现；下文 AI 流程描述该阶段的目标，不能据此认定已完成接入。

## 设计目标

- 将用户的文字询问关联到当前选中的内置题目。
- 在同一题目的连续追问中保留必要的对话上下文。
- 支持题干和回答中的数学公式展示。
- 左侧依次为“学科”“对话”“笔记”“机器人”，底部为“设置”；学科下树状展开课程、教材和题目。菜单负责切换整个工作区，而不是为对话、笔记、机器人弹出列表气泡。
- “学科”页面为中间阅读、右侧聊天；“对话”页面为中间会话列表、右侧记录与输入；“笔记”页面为中间标题列表、右侧笔记正文；“机器人”页面为机器人列表与独立配置面板。预览包含两门学科各 2 个示例会话与 2 篇笔记。
- 底部设置按钮点击后打开一级气泡，包含“官方内容”“显示设置”“模型设置”；官方内容进入管理页，其余两项打开对应二级气泡；不使用菜单内展开列表或阅读页顶栏面板。
- 阅读模式区分教材和题目；选择器标签分别为“教材选择”“题目选择”，下拉框和正文随模式切换。
- 左侧顶部为用户头像入口，点击显示三组气泡菜单：用户名；虚拟宠物与邀请好友；帮助与退出登录。头像和设置气泡统一使用锚点指示、圆角、柔和阴影及轻微弹出动效；点击外部或 Escape 可收起。入口展示与具体功能接入分别设计。
- 在题目栏控制答案显示，在聊天栏展示 AI 推荐问题并支持点击询问。
- 将本地内容读取、会话保存、上下文组织、AI 连接和官方内容更新的责任分别表达清楚，支持后续客户端复用。

## 已确认的输入与内容

- 用户输入为围绕当前题目的文字询问，不包含题目上传或附件处理。
- 当前题目通过稳定编号 M001–M024 识别，内容来源为 `data/calculus/questions/questions.json`。
- C 语言示例题通过 C001–C012 识别，来源为 `data/c-language/questions/questions.json`，配套教材与课程记忆分别位于该课程的 `textbooks/` 与 `memory/`。切换学科时同步更新内容选择器、正文、答案与聊天关联；代码按保留换行和缩进的代码块展示，本特性不提供在线运行程序。
- 题库提供题干、参考答案和讲解要点；回答上下文至少需要当前题干、用户询问及必要的当前对话内容。
- 参考答案和讲解要点如何进入模型上下文，需在具体方案中确定。
- 配套教材支持在教材模式中阅读；教材按二级标题切分为章节，使用固定锚点关联。教材如何用于题目回答，以及课程记忆的读取和检索方式，尚未确定。
- 课程记忆样例不代表已实现真实用户记忆采集、提炼或长期存储。

## 机器人配置参考

参考 Hermes 的 [Profiles](https://hermes-agent.nousresearch.com/docs/user-guide/profiles) 和 [Personality / SOUL.md](https://hermes-agent.nousresearch.com/docs/user-guide/features/personality)：机器人具有独立配置和角色指令，会话明确关联机器人。此处借鉴配置组织思路，不引入 Hermes 运行时作为已确定的技术选型。

官方预置为“全科教师”“高数教师”“C 语言教师”，用户可改名或创建自己的数学、英语等教师。全科教师使用用户确认的高级教师指令；高数教师补充数学论证、定理前提和定义域要求，C 语言教师补充语言标准、执行过程与未定义行为要求。正式指令保存在 `apps/web/src/data/seed-data.json`，不将人物标签作为专业能力的证明。

| 配置                 | 当前实现与后续职责                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| 名称、角色指令       | 每位教师独立保存；专业侧重直接写入角色指令，不单设简介或专业范围编辑项                                        |
| 模型、记忆偏好       | 每位教师独立配置；实际调用和记忆提炼尚未接入                                                                  |
| 题目／教材／笔记能力 | 当前 `skills` 字段仅保存这三个界面能力的选择，不代表已安装外部 Skill                                          |
| Skill 挂载           | 后续按教师保存 Skill 标识、版本与独立配置；安装状态和运行权限单独处理，不能仅靠教师名称或提示词宣称已具备能力 |
| RAG 库挂载           | 后续按教师保存知识库引用及检索配置；库资产通过独立目录管理，教师只引用，不将整库复制到机器人或 session 中     |

角色设定仅显示名称和角色指令，列表和面板标题不再附带简介。已有保存记录中的简介与专业范围保留兼容，不清除用户数据。角色指令中的专业侧重不作为访问限制。聊天选择器保留全部已配置机器人，创建会话不按学科过滤。用户选择英语教师讨论数学时，维持所选教师及配置；不自动更换模型、教师或知识库。未来检索只使用该教师明确挂载且可用的库，不预设跨学科提问都能获得可靠答案。

旧版数据通过一次性的 `robotCatalogVersion` 更新：只替换字段仍与旧初始配置一致的预置，用户改过的名称、指令、模型或能力均保留。旧预置退休后，会话改为关联相应的学科教师，消息中的历史作者名称不重写；已删除的旧预置和空机器人列表不会被默认数据补回。升级结果通过现有事务与保存版本检查写入，不清空数据库。旧配置样本只用于迁移识别，位于 `legacy-robots.json`。

机器人编辑草稿按机器人 ID 分别保留，切换机器人和页签不自动保存。列表与编辑区根据草稿和已保存字段的实际差异显示未保存状态，能力选择顺序不构成差异。右下角提供恢复默认、取消修改、保存配置：取消只清除当前草稿，恢复到上次保存内容；恢复默认只更新当前草稿，预置机器人取初始设定，自建和复制机器人保留已保存名称并载入通用默认配置；保存仍经过名称和角色指令校验。无差异时取消和保存按钮禁用。“使用此机器人”移至面板右上方，保留保存后新建对话的行为。

## 会话管理与外部 session

产品中的一条“对话”就是一个 AI session。代码沿用 `Conversation` 名称；本地 ID 在创建时生成，标签、归档、切换机器人或重新打开页面均不改变这个 ID。题目／章节引用描述会话关联的学习材料，不充当 session ID。

### 参考依据

- [Codex App Server](https://developers.openai.com/codex/app-server/) 将持久对话 thread、一次执行 turn 和执行中的 item 分开，并提供恢复、归档和取消执行接口。这里借鉴会话与执行分开的结构。
- [OpenCode Server](https://opencode.ai/docs/server/) 分别提供 session、message、abort 和 fork 等接口。这里将外部 session ID 与本地 ID 分开保存，连接适配器负责协议转换。
- [OpenClaw 会话管理](https://docs.openclaw.ai/concepts/session) 区分会话记录、生命周期与上下文压缩。这里保留本地聊天历史，后续单独设计送入模型的上下文，不把历史记录等同于每次完整发送的提示词。
- [Hermes Session Storage](https://hermes-agent.nousresearch.com/docs/developer-guide/session-storage) 持久保存会话信息、完整消息与模型配置。这里借鉴信息分类，不直接访问或修改 harness 自身数据库。

下面是 SolveMate 的设计，借鉴这些工具的思路不代表选定其中某个运行时，也不表示已经接入。

### 当前数据结构

| 对象                              | 字段与用途                                                                                                                               |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 本地会话 `Conversation`           | `id`、`title`、`createdAt`、`updatedAt`；以及关联内容 `selection`、当前机器人 `robotId`、消息 `messages`                                 |
| 管理信息                          | `label` 默认“无标签”；`archived` 默认 false；`archivedAt` 记录归档时间；`deletedAt` 记录本地删除时间                                     |
| 外部会话对应关系 `SessionBinding` | `connectionId` 引用连接配置，`protocol` 标识协议，`externalSessionId` 保存外部系统返回的 ID                                              |
| 执行记录 `SessionTurn`            | 本地 `id`、`connectionId`、可选外部 `externalTurnId`、状态 `status`、开始与结束时间                                                      |
| 消息 `Message`                    | 稳定 `id`、`role`、`content`、可选创建时间；真实接入后通过 `turnId` 关联执行，通过 `externalItemId` 对应外部条目；历史机器人作者独立保留 |

时间使用 Unix 毫秒。当前 `updatedAt` 表示最后消息活动时间，标签与归档不冒充新消息活动。旧数据缺少管理字段时按“无标签、未归档”展示；不为旧记录编造创建时间、外部 ID 或执行历史。

`bindings`、`turns` 是后续接入的类型预留，当前新会话为空数组。当前保存问题只追加用户消息，不创建虚假的 AI 执行或完成状态。连接凭据应由连接配置管理，不能放入这些记录或普通日志。

### 管理操作与页面

- 中间列表分为“进行中”和“已归档”两个可折叠分组。进入页面时前者展开、后者收起，展开的列表分别滚动，归档标题始终留在面板内。“进行中”表示未归档，与 AI 是否正在生成无关。
- 每条标题后显示一个标签。右键“标签”打开气泡，可选重要、一般、无标签，或输入 1–24 个字符的自定义标签；已有自定义标签可复用。
- 归档只移动本地分组，保留 ID、内容关联、机器人和消息。已归档会话仍能打开和续聊，可右键“移回进行中”；续聊不自动解除归档。
- 删除设置本地 `deletedAt` 并从列表隐藏；删除当前会话时清空右侧选中记录，下一次提问创建新会话。当前保留删除标记、消息及外部对应关系，不调用外部删除接口；这不是磁盘擦除，也尚未提供回收站。后续需明确恢复与彻底清除策略。

### 后续接入约束

1. 一个本地 session 可保存多个连接的对应关系；每个 `connectionId` 在同一会话中最多对应一个外部 session。适配器必须用连接 ID 和外部 session ID 共同定位，不能只凭外部 ID 合并记录。需要 fork 或重建时创建新的本地会话并记录来源，不能悄悄覆盖旧对应关系；来源字段随实际接入补充。
2. 恢复外部 session 前检查连接、模型与机器人配置是否兼容。切换机器人先改变本地后续交流配置；是否恢复、创建或 fork 外部 session 取决于该工具能力。不能假设所有 harness 都能原地切换。执行记录应保存当时实际使用的配置快照；快照字段、工具调用及审批条目随首个适配器补齐。
3. 接入时一次执行单独记录运行、完成、失败或取消；中断保留已收到内容。消息按本地 ID 和所属执行中的外部条目 ID 去重，流式增量更新同一条记录，不重复追加整条回复。断线后先查询真实执行状态，再决定恢复；不可直接重发造成重复执行。
4. 删除标记优先于后续导入；已经本地删除的外部 session 不自动重新出现。归档与删除默认只管理 SolveMate，本地删除不能隐式删除 harness 记录，也不等同于停止正在运行的任务；实际有执行时需先设计中断与删除的协调流程。
5. 当前使用 IndexedDB 中经过校验、事务和保存版本检查的应用快照。消息仍内嵌在会话中，并未实现独立消息表或增量事件库。接入真实流式回复前，再设计消息／执行分表、分页、逐条保存与数据库迁移，避免长会话每次改写全部历史。

## 逻辑流程

1. 用户从学科树选择教材或题目模式，再通过中间栏顶部的下拉框选择内容。题目模式展示题干、答案开关与上一题／下一题；教材模式展示教材正文。
2. 客户端通过本地存储接口读取当前题目，校验题目编号及内容是否可用。内容未完整下载时明确提示，避免将空内容送入对话。
3. 用户提交询问后，客户端根据当前题目、当前会话和机器人配置组织必要上下文，记录本次消息及请求状态。
4. AI 连接适配模块向用户配置的 API 或现成 harness 发送请求，接收回复、错误及结束状态。官方内容服务不作为这条流程的必经中转。
5. 客户端逐步展示回复并保存到本地会话，供用户继续询问。停止和失败时保留已发生的消息及对应状态。
6. 同会话追问沿用相关上下文；切换题目时，以新题编号确定新的当前题目。通过“对话”列表重新打开会话时，从本地恢复会话、关联内容和机器人选择，不混入其他会话的消息。

用户可在题目栏切换答案显示状态。AI 推荐问题根据当前题目及已有对话生成，聊天栏每次展示两条；点击后进入同一询问流程。生成与更新时机待定。聊天栏顶部使用机器人选择器，读取机器人配置列表；主动切换时更新当前会话的机器人关联，历史回复保留各自的机器人标识，后续回复使用新选择。不显示额外的阅读状态副标题。

会话保存和恢复以终端本地为主；AI 连接由独立模块适配，首版支持对象经实际连接验证后确定。本流程不包含答疑完成状态或学生理解程度评估。

### 会话关联的保存与恢复

`Conversation.selection` 为 `ReadingSelection | null`。null 明确表示普通对话，缺失字段或不完整的关联对象仍判为损坏数据。`AppData.selection` 继续保存有效阅读位置，两者各有用途，不相互填补。已有题目／章节会话仍按原有结构读取，无需清空或改写历史。

机器人页“使用此机器人”和对话列表“新建对话”显式使用 null；阅读页首次发送问题才复制当前阅读选择。打开普通对话只恢复会话 ID 与机器人，不修改阅读位置；打开有关联的会话才恢复阅读内容。在对话页续聊时以该会话自身的 selection 为准，不能使用后台停留的阅读位置。普通对话不展示阅读标记，推荐问题示例使用通用讨论文案；列表显示“普通对话”和机器人名称。

## 内容更新与离线

官方内容后端现已通过 [002](../002-official-content-service/design.md) 实现目录、版本与下载接口。Web/PWA 已接入内容下载、校验和本地事务保存，保留旧版与历史会话的版本关联；未下载时继续使用随应用构建的示例。

官方服务提供内容目录、版本信息和下载入口。客户端完成下载后，以本地保存的版本提供阅读和对话上下文。服务不可达时继续使用已有版本，恢复连接后可检查更新；下载与更新失败不覆盖原有可用内容。

应用程序、样式、字体和公式资源也需离线缓存，保证已经完成初次加载的应用在脱离官方服务后仍可重新打开。“离线”按 SolveMate 官方服务的可达性定义，AI 接口可达性单独判断；用户配置的 API 或本机 harness 可用时，仍可询问和追问。

内容编号与版本、本地数据库版本及导出格式分别管理。Web 阶段使用 IndexedDB / Dexie，本地读写通过统一接口调用；后续桌面端如采用 SQLite，需要配套数据迁移。

## 责任边界

- `apps/web/`：React + TypeScript 界面、Vite 开发构建，以及本地内容定位、会话与配置管理、上下文组织和推荐问题请求；存储与 AI 连接各自通过接口适配。PWA 负责应用资源缓存和安装行为。
- `apps/server/`：Python 官方内容服务，使用 FastAPI；负责内容目录、版本查询、下载等在线能力。本地阅读、会话保存和 AI 连接可脱离此服务运行。
- `packages/contracts/`：按接口设计需要定义内容、版本和消息等共享数据约定。TypeScript 客户端和 Python 服务遵循同一约定，HTTP 约定由 Python 生成 OpenAPI；客户端保留 TypeScript 类型与运行时校验。
- `data/calculus/`：维护内置教材、题库及课程记忆样例，资产格式见 `../../../data/README.md`。
- `data/c-language/`：按相同结构维护 C 语言教材、程序阅读题和课程记忆样例。
- 外部 API / harness：由用户配置。适配模块处理连接和消息转换，现成 harness 承担自身执行能力；首版不自研 harness。
- 共享代码在出现实际复用需求后提取，首版不预先新增桌面、手机或小程序工程。

## 质量要求

- 当前题目编号与实际读取的题干应一致。
- 同题追问应保留必要上下文；切题后不能继续把旧题作为当前题目。
- 题干和回答中的数学公式应正确展示。
- 用户可见的请求状态应与实际请求结果一致。
- 推荐问题应关联其生成时的题目和对话上下文，切题后不得展示错题的推荐结果。
- 不预设学习完成判定，也不依赖附件识别链路。
- 已保存会话在关闭并重新进入页面后可恢复；应用更新与内容更新不得无故清除个人记录。
- 官方服务不可达时，应用能重新打开并使用已下载内容；AI 请求只取决于相应 API / harness 的连接条件。
- 本地存储容量不足、保存失败、内容未完整下载时应有明确状态，不能提示保存或下载成功。
- 连接凭据不进入内容下载请求、常规日志或普通导出文件；在线 AI 只接收回答所需的材料与会话上下文。

## 当前实现与基本验证

应用代码位于 `apps/web/`，数据类型位于 `packages/contracts/`。教材按现有六章切分；题目答案默认隐藏，切换题目或章节时重置显示状态与正文滚动位置。示例笔记只读，新建或编辑笔记另行设计。

客户端将会话、机器人配置、显示设置和当前阅读选择保存到 IndexedDB。首次使用时写入示例记录，空机器人列表属于有效状态，不会被默认机器人覆盖。读取时校验数据结构和内容引用，遇到损坏或不兼容数据时提示错误并保留原记录。

保存按提交顺序排队，在事务中检查数据库记录的保存版本。其他页面已更新记录时，本页拒绝覆盖并提示重新读取；写入失败时保留上次成功记录。页面底部区分正在保存、已保存和失败状态。控制台日志使用英文，仅记录错误类别，不输出问题、笔记或凭据。

采用 TypeScript 严格检查、ESLint 推荐配置与 React Hooks 规则，以及 Prettier 默认格式。验证命令在仓库根目录执行：

```bash
npm run check
npm run format:check
npm test
npm run build
```

以上命令通过，网页单元测试共 57 个，另有 6 项构建补丁测试，覆盖内容、公式分隔符与代码保留、会话与机器人、本地读写、多个页面保存冲突、旧记录升级、错误数据保护及未接入 AI 的行为。

浏览器已验证题目导航、答案开关与重置、会话保存恢复、机器人复制／改名／设默认／删除、显示设置恢复、学科树收起和笔记切换。停止预览服务器并确认 HTTP 无法连接后，重新打开页面仍可读取题目、公式、答案和笔记。PWA 安装清单与图标已生成，系统级安装尚未实测。

## 验证方向

- 题目读取：编号能定位正确题目，无效编号得到明确处理。
- 上下文组织：包含当前题目和必要前文，切题后当前题目更新正确。
- 页面交互：学科树、教材／题目模式切换、对应选择器与正文、题目导航、公式、答案开关、设置中的显示项，以及原有聊天交互可用。
- 本地保存：关闭页面后能恢复内容、会话和机器人配置；存储失败有提示。导出与恢复流程设计后补充相应验证。
- 离线启动：完成应用与内容下载后，屏蔽官方服务并重新打开，仍可阅读本地教材、题目和历史记录。
- 独立 AI 连接：官方服务不可达但已配置 API / harness 可达时，仍可发起询问；连接失败与停止生成时消息状态正确。
- 内容更新：更新失败保留旧版，完整保存后才使用新版本；个人记录及内容关联保留。
- 推荐问题：接入 AI 生成结果，点击后进入当前题目的对话，切题时不混入旧题推荐。
- 端到端：选择题目、文字询问、连续追问和切换题目满足 `spec.md` 的验收标准。

### 正式构建中的外观切换验证
