# 016 技术设计

`ExportDialog` 统一管理文件名、位置、确认、用时、成功停留及失败重试。机器人和笔记本只提供导出格式、图标与生成文件的函数；文件保存集中在 `exports/files.ts`，不各自维护保存流程。

默认位置通过本机服务解析下载目录。Windows 使用 Known Folder API，支持系统重定向；macOS 使用用户下载目录。默认导出由本机服务写入并返回实际文件名，不能把浏览器收到下载请求当作文件已保存。自选目录使用浏览器 File System Access API；权限失败保留窗口，允许重新选择或返回下载目录。网页不能读取浏览器未授权的任意目录。

下载目录写入接口只接收 PDF 或 JSON 和单个合法文件名，限制体积，不接受目录参数。同名文件通过独占创建添加后缀；写入失败删除本次未完成文件，已有文件保留。浏览器选定目录时使用同样的同名处理规则。

机器人配置文件使用 `format: "solvemate.robot"`、`version: 1` 和 `robot` 字段。`robot` 复用共享 `Robot` 类型及 Schema 校验，不复制一套机器人字段。导入时生成 UUID、将修订号重置为 1，以同一保存操作新增记录。AI 选择保留引用，安装路径与凭据由外部连接记录管理，不写入导出文件。

交互参考 [Carbon 导出模式](https://carbondesignsystem.com/community/patterns/export-pattern/)；目录授权按 [File System Access API](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker) 实现。不引入新的 UI 框架或导出依赖。


## 验证

- 前端专项测试验证日期及格式、非法名称、配置往返、版本校验、重名新增、外部连接引用保留、写入权限失败后的清理。
- 本机服务专项测试覆盖 macOS、Windows 重定向目录、Linux 下载目录、来源限制、体积与内容校验、并发同名导出及写入失败清理；Windows 原生接口实机用例按环境跳过。
- 独立 Chrome 页面使用实际组件和隔离的本机服务，JSON 与 PDF 实际写入测试下载目录。PDF 为 3 页，包含两篇笔记正文。核对日间与夜间布局、导出用时、成功后 3 秒关闭、修改文件名、失败保留输入与重试。
- 重新导入实际导出的 JSON 后，机器人列表从 3 条增为 4 条，原默认和原记录保留。本次浏览器扩展没有本地文件上传权限，使用模拟文件选择事件验证实际导入处理，没有修改扩展权限；原生文件选择动作仍需手动验收。

所有数据及文件写入工作区内的独立验证目录，不调用 Harness，也不修改用户正式配置或学习记录。

数量上限在 `packages/contracts/robot-limits.json` 维护，由既有生成命令同步至 Python 包；列表计数、入口判断与保存校验读取同一值。名称校验集中在机器人状态函数，页面负责标红和提示；本机保存再次检查新增或改名是否产生重名，不因已有重名阻止读取记录。

机器人列表与名称／数量限制验证：25 项相关前端测试、2 项本机保存测试及 4 项生成脚本测试通过。Chrome 独立页面确认列表栏宽 250 像素、两侧标题栏均为 64 像素、名称重名后红框和行内提示保留；达到 9/9 时新建、复制和导入均不可用。日间、夜间均使用主题颜色，原有正式记录未修改。
