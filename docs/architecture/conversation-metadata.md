# 对话元数据设计

## 1. 对话需要说明什么

一条对话应能说明：它在 SolveMate 中是谁、如何创建、由哪位教师参与、关联什么资料、当前选择哪项服务和模型，以及每一轮实际提交和收到什么。原生 Harness 绑定是其中的一部分，本地名称、分类、状态、资料关联和配置仍由 SolveMate 管理。

本文细化[模块元数据与数据结构设计](metadata.md)中的会话、消息、执行和外部绑定。[006 特性](../features/006-ai-conversation-metadata/spec.md)已实现对话身份、当前配置、单一原生绑定、每轮配置快照及版本迁移。用户文件引用、原生管理信息同步、用量及扩展资源记录仍按后续特性实施；实际字段以 `packages/contracts/ai-metadata.schema.json` 为准。

## 2. 对象之间的关系

| 对象               | 保存的内容                                             | 与对话的关系                             |
| ------------------ | ------------------------------------------------------ | ---------------------------------------- |
| `Conversation`     | 身份、管理信息、教师关联、当前 AI 配置、创建来源与时间 | 一条对话一份记录                         |
| `SessionBinding`   | 连接、协议和原生会话编号及绑定状态                     | 首次真实提问时建立，正式对话最多一份     |
| `Message`          | 学生问题或教师回复、正文、引用和作者信息               | 一条对话有多条消息                       |
| `Turn`             | 一轮请求的配置快照、执行状态、回复和诊断依据           | 一条对话有多轮执行，同一时刻最多一轮运行 |
| `ContentReference` | 固定资料版本、位置与所引用内容                         | 由对应消息和执行引用                     |

消息与执行分别记录。尚未接入 AI 时保存的问题可以没有真实执行；有真实执行时，通过 `turnId` 关联问题、回复、工具和权限请求。连接检测记录不放进正式对话列表。

## 3. 对话自身的元数据

### 身份、创建来源与时间

| 字段                   | 含义与约束                                                                       |
| ---------------------- | -------------------------------------------------------------------------------- |
| `id`                   | SolveMate 对话编号，稳定且独立于原生会话编号                                     |
| `schemaVersion`        | 对话数据格式版本，供迁移使用                                                     |
| `revision`             | 已保存记录的修改版本，防止旧草稿覆盖新数据                                       |
| `origin`               | 本地创建、示例或导入；导入时记录来源，示例不冒充真实模型结果                     |
| `creationReason`       | 普通新建、切换教师、切换服务；导入另记明确原因                                   |
| `sourceConversationId` | 因切换操作产生新对话时关联原对话；普通新建为空，不表示复制了旧消息               |
| `createdAt`            | 创建时间；新建记录必填，旧记录无法确认时为空                                     |
| `updatedAt`            | 名称、标签、配置等记录内容最近一次保存时间                                       |
| `lastActivityAt`       | 最近一次问题或回复活动时间；列表按聊天活动排序时使用它，不以修改标签代替聊天活动 |
| `createdWith`          | 创建时的 SolveMate 版本、可取得的构建编号与客户端类型；缺失值不补造成当前版本    |

`sourceConversationId` 只记录创建原因。切换教师或服务后的新对话不自动继承原消息，也不复用原生 session。原对话删除后，这条关联仍可作为来源记录保留。

### 名称、分类与状态

| 字段                      | 含义与约束                                                                |
| ------------------------- | ------------------------------------------------------------------------- |
| `title`                   | SolveMate 中显示的名称，按当前规则校验长度                                |
| `titleSource`             | 默认、首条问题、手动、Harness 或未知；手动名称不能被后续首条问题规则覆盖  |
| `label`                   | 当前单个标签；无标签存 `null`，界面显示“无标签”，不以这段显示文字充当空值 |
| `status`                  | `active`、`archived` 或 `deleted`，是列表分类与输入限制的依据             |
| `archivedAt`、`deletedAt` | 对应管理动作的时间；当前状态由 `status` 判断，不通过几个时间字段分别推测  |

保留当前“进行中”和“已归档”的界面文案。删除继续表示本地删除标记，不等于彻底删除原生 Harness 会话。恢复和彻底清除的交互按后续特性安排。

原生会话名称与归档状态保存在适配结果中，需带获取时间及同步结果；本地操作与原生操作的成功分别判断。未完成原生同步时，不用本地状态冒充原生已确认结果。

### 教师、阅读与扩展资源关联

| 字段或关联            | 含义与约束                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `robotId`             | 对话关联的教师编号，建立后切换教师需要新对话                                                         |
| 教师身份快照          | 创建或首次确定教师时的名称与图标，保证教师改名或删除后仍能解释历史身份；每轮指令单独保存在执行快照中 |
| `readingContext`      | 对话的资料关联，至少包含资料或课程内容编号、固定版本和初始位置；普通对话为 `null`                    |
| 消息的 `referenceIds` | 某次问题实际引用的内容，不以当前阅读位置重算                                                         |
| Skill、RAG、记忆关联  | 由每轮执行记录实际使用的资源及版本，配置了但没有调用的资源不能记成已使用                             |

阅读关联不替代消息引用：对话可以源于某个章节，但每次问题引用的选段仍须分别记录。笔记与对话的关联通过稳定编号表达，不把笔记正文复制到会话元数据中。

教师被删除时保留历史编号和身份快照，并说明该教师不可用。不能把旧对话静默改成默认教师；继续使用另一位教师应按既定规则建立新对话。

## 4. 服务与模型如何记录

### 服务、连接与模型提供方

| 对象         | 记录内容                           | 示例含义                                                 |
| ------------ | ---------------------------------- | -------------------------------------------------------- |
| Harness 服务 | `providerId` 与注册描述            | DeepSeek Harness、Hermes、Codex                          |
| 本机连接     | `connectionId` 与配置版本          | 当前已有 `deepseek-local`、`hermes-local`、`codex-local` |
| 模型提供方   | Harness 明确给出的提供方编号或名称 | 某 Harness 配置中的模型供应方；无法取得时为空            |
| 模型         | 对应连接内的模型编号与显示名       | 实际选中的模型，不根据 Harness 名称推测                  |

通过 DSH 使用 GLM 时，Harness 服务与模型分别记录。模型目录里的分组名称不一定是稳定的提供方编号，适配器不能将其任意当成模型提供方身份。

对话的当前配置保存 `connectionId` 与 `modelId`，类型见[教师默认与会话配置](metadata.md#教师默认与会话配置)。服务类型由该稳定连接确定，连接的服务类型不可原地改成另一种；新增服务产生另一项连接。

模型以连接编号与模型编号共同定位，新对话保存已经确定的选择。全局默认变化不改变已有对话的服务和模型；旧记录中无法确定的默认模型在实际提问前解析并保存。

服务和模型的显示名称可保存只读展示快照，带所对应的配置版本和获取时间，以便离线展示。调用和校验仍使用稳定编号；快照与当前配置不匹配时说明名称或配置尚未确认，不用显示名匹配模型。

### 当前选择与每轮记录

会话标题栏表达后续提问的当前选择。一轮回复的模型信息从该轮记录读取，不能用标题栏的当前选择覆盖历史。

| 信息                        | 记录时机             | 含义                                                                 |
| --------------------------- | -------------------- | -------------------------------------------------------------------- |
| 模型选择规则                | 保存会话配置时       | 当前对话确定的连接和模型，不根据新的全局默认重算                                   |
| 请求模型与参数              | 本机接受本轮请求时   | 解析后准备使用的模型编号、当时显示名与推理参数                       |
| 提交给 Harness 的模型与参数 | 适配器形成实际请求时 | 实际写入原生接口的值；接口沿用原生默认值时明确记录未显式指定         |
| Harness 返回的模型          | 原生接口返回时       | 能取得的实际模型信息；未返回时为空，不能直接复制请求模型并标成已核实 |

如果原生模型设置使用的是别名或自动路由，按原值记录。无法确认底层具体模型版本时，不自行展开或推断。

## 5. 每轮执行的元数据

一条对话中可以先用模型 A，再用模型 B，因此每轮执行独立保存配置。执行编号也用于应答丢失后的查询和恢复，不能仅依靠消息文本判断是否调用过。

| 分类       | 关键字段或内容                                                | 保存规则                                                               |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 编号关联   | `id`、`conversationId`、问题编号、回复编号                    | 本地执行编号稳定，关联同一轮消息和事件                                 |
| 配置依据   | 会话与教师的保存版本、连接编号与配置版本、模型目录版本        | 能说明这一轮依据哪版配置准备；后续设置变化不改写它                     |
| 教师快照   | 教师编号、名称、图标、角色指令                                | 保留本轮实际使用的值，不只记录可变的教师编号                           |
| 服务与模型 | Harness 类型、连接、请求与提交模型、返回模型及参数            | 区分请求信息和已确认结果，不编造返回值                                 |
| 学习内容   | 引用编号、固定内容版本、传递方式与结果                        | 能判断模型是否收到资料，只有不可访问的路径不算传递成功                 |
| 扩展资源   | 实际使用的 Skill、RAG、学习记忆编号与版本                     | 在相应能力实现后记录，不将开关开启等同于实际调用                       |
| 执行状态   | `status`、`phase`、结果版本或事件序号                         | 状态与阶段分开，旧事件不能覆盖新结果                                   |
| 原生关联   | 原生会话编号、原生执行编号、适用时的原生消息编号              | 始终与本轮连接关联，其他会话的通知不能混入                             |
| 时间       | 提交、服务接受、开始、首段正文、结束时间                      | 只记录可观测时间；由明确起止计算等待与响应耗时                         |
| 错误       | 稳定错误码、可读说明、发生阶段                                | 能判断是提交、连接、恢复、模型还是保存失败，不依靠解析错误文字判断     |
| 用量       | 原生返回的 token、费用及对应单位和来源                        | 仅在接口确实提供时记录；未知为空，不记为 0，不根据模型名估算成实际账单 |
| 运行版本   | 本轮的 SolveMate、客户端构建、本机服务、适配器及 Harness 版本 | 记录可取得的值，允许同一对话不同轮次来自不同运行版本                   |

请求快照固定后，原生应答与诊断结果可以逐步补充，但不覆盖已提交的请求信息。用量、版本或实际模型不可取得，不应导致普通提问无法执行。

SolveMate 版本、构建编号与数据格式版本分别表达：应用升级可以继续使用同一数据格式，数据库迁移也不能覆盖“创建时使用哪个版本”的记录。版本号沿用实际发布值；开发构建未提供构建编号时为空。

## 6. 原生绑定与软件自身信息的边界

`SessionBinding` 保存连接编号、协议、原生会话编号、绑定状态和已确认的原生管理结果。本机服务保留建立绑定时的程序位置、Harness 配置目录与工作目录；程序位置和配置目录用于说明当时的运行环境，不作为会话身份。继续对话时由适配器在当前连接中恢复原编号，使用保存的工作目录满足原生接口要求。找到并恢复成功就继续，失败保留原编号和记录并显示原因，不因路径变化直接拦截，也不创建替代会话。普通界面通过绑定编号和状态使用这些记录。

`Conversation` 管理 SolveMate 的名称、标签、状态、教师关联与当前配置。`Turn` 保存调用事实和运行依据。三者通过本地对话编号关联，不要求 Harness 理解 SolveMate 的课程、标签或教师元数据。

一个服务缺少重命名或归档接口时，适配器明确报告对应能力；不删除 SolveMate 的管理信息，也不把该服务的原始字段扩散到所有页面。

元数据与普通导出不包含密钥、令牌或 Harness 凭据。机器用户名、完整本机路径和完整浏览器标识不作为每条对话必需记录。诊断若确实需要额外环境信息，应说明用途，不能把用户材料和完整协议通知无差别写入日志。

## 7. 更新和读取规则

1. 标题栏、AI 配置初始值与请求准备读取同一会话配置解析结果；历史回复读取对应执行快照。
2. 保存同一服务的模型配置时，通过统一业务操作落实教师与会话的既定联动，原生 session 和历史执行不变。
3. 确认切换教师或服务时创建新对话并记录来源；取消不改变配置、消息和绑定。
4. 教师改名、删除或全局默认服务变化不改写历史身份和调用记录；无法继续使用时显示具体原因。
5. 修改标签、名称或归档状态更新管理信息，不改变最近聊天活动时间；新问题或回复更新聊天活动时间。
6. 消息数、最后一轮摘要和“是否正在生成”等信息由关联记录计算；需要缓存时带来源版本，不新增可独立修改的重复字段。

界面可以组合对话、绑定、模型目录和最后一轮结果用于展示。这个组合结果只读，不能反向作为一份完整会话记录覆盖原有对象。

## 8. 当前字段与迁移检查

| 当前字段或行为                                   | 目标处理                                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `Conversation.id`、标题、标签、时间              | 保留稳定编号和已有输入；补齐明确来源与状态；旧时间不明时不填当前时间                     |
| `connectionId`、`bindings[]`、`turns[]` 中的连接 | 核对一致后形成会话配置与单一正式绑定；冲突时报告，不能任选第一项                         |
| `aiModel`、教师 `modelSource/modelName`          | 明确默认选择与具体模型编号；历史记录仅能证明请求模型时，不写成已确认实际模型             |
| `archived`、`archivedAt`、`deletedAt`            | 迁移为明确状态，保留已知操作时间；不顺带清除原生会话                                     |
| 会话 `example` 与消息 `example`                  | 保留示例来源；真实追问不把已有示例回复改成真实调用记录                                   |
| 删除教师时替换旧会话的 `robotId`                 | 与固定教师规则冲突，实施时改为保留关联和身份；已有原始教师信息优先依据执行及作者记录核实 |
| 缺少创建版本、构建编号和实际模型信息             | 保持未知，不用当前运行环境或默认模型补造历史                                             |

迁移前验证无 AI 对话、示例混合真实追问、单服务多模型、跨服务新旧对话、教师被删除、配置失效和中断执行等记录。字段定义、请求校验、保存操作、读取解析与迁移必须配套交付；只有新增字段不能算完成一致性整理。
