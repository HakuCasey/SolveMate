# 对话元数据设计

## 1. 对话需要说明什么

一条对话应能说明：它在 SolveMate 中是谁、如何创建、由哪位教师参与、关联什么资料、当前选择哪项服务和模型，以及每一轮实际提交和收到什么。原生 Harness 绑定是其中的一部分，本地名称、分类、状态、资料关联和配置仍由 SolveMate 管理。

本文细化[模块元数据与数据结构设计](metadata.md)中的会话、消息、执行和外部绑定。[006 特性](../features/006-ai-conversation-metadata/spec.md)已实现对话身份、当前配置、各服务的原生绑定、每轮配置快照及版本迁移。用户文件引用、原生管理信息同步、用量及扩展资源记录仍按后续特性实施；实际字段以 `packages/contracts/ai-metadata.schema.json` 为准。

## 2. 对象之间的关系

| 对象               | 保存的内容                                             | 与对话的关系                             |
| ------------------ | ------------------------------------------------------ | ---------------------------------------- |
| `Conversation`     | 身份、管理信息、教师关联、当前 AI 配置、创建来源与时间 | 一条对话一份记录                         |
| `SessionBinding`   | 连接、协议和原生会话编号及绑定状态                     | 首次真实提问时建立，每项服务各一份       |
| `Message`          | 学生问题或教师回复、正文、引用和作者信息               | 一条对话有多条消息                       |
| `Turn`             | 一轮请求的配置快照、执行状态、回复和诊断依据           | 一条对话有多轮执行，同一时刻最多一轮运行 |
| `ContentReference` | 固定资料版本、位置与所引用内容                         | 由对应消息和执行引用                     |

消息与执行分别记录。AI 不可用时仍保存消息及引用，本地尝试记录未提交原因，不补造真实执行或连接编号。重试沿用原消息编号并新建尝试，消息的 `turnId` 指向最近一次尝试，各次执行通过 `userMessageId` 关联同一问题；回复、工具和权限请求仍按各自 `turnId` 保存。连接检测记录不放进正式对话列表。

## 3. 对话自身的元数据

### 身份、创建来源与时间

| 字段                   | 含义与约束                                                                       |
| ---------------------- | -------------------------------------------------------------------------------- |
| `id`                   | SolveMate 对话编号，稳定且独立于原生会话编号                                     |
| `schemaVersion`        | 对话数据格式版本，供迁移使用                                                     |
| `revision`             | 已保存记录的修改版本，防止旧草稿覆盖新数据                                       |
| `origin`               | 本地创建、示例或导入；导入时记录来源，示例不冒充真实模型结果                     |
| `creationReason`       | 普通新建、切换教师、切换服务；导入另记明确原因                                   |
| `sourceConversationId` | 因切换操作产生新对话时关联原对话；普通新建为空，不表示复制了旧消息               |
| `createdAt`            | 创建时间；新建记录必填，旧记录无法确认时为空                                     |
| `updatedAt`            | 名称、标签、配置等记录内容最近一次保存时间                                       |
| `lastActivityAt`       | 最近一次问题或回复活动时间；列表按聊天活动排序时使用它，不以修改标签代替聊天活动 |
| `createdWith`          | 创建时的 SolveMate 版本、可取得的构建编号与客户端类型；缺失值不补造成当前版本    |

`sourceConversationId` 只记录创建原因。切换教师后的新对话不自动继承原消息，也不复用原生 session。切换服务保留本地对话，各服务分别保存原生会话关联。原对话删除后，这条关联仍可作为来源记录保留。

### 名称、分类与状态

| 字段                      | 含义与约束                                                                |
| ------------------------- | ------------------------------------------------------------------------- |
| `title`                   | SolveMate 中显示的名称，按当前规则校验长度                                |
| `titleSource`             | 默认、首条问题、手动、Harness 或未知；手动名称不能被后续首条问题规则覆盖  |
| `label`                   | 当前单个标签；无标签存 `null`，界面显示“无标签”，不以这段显示文字充当空值 |
| `status`                  | `active`、`archived` 或 `deleted`，是列表分类与输入限制的依据             |
| `archivedAt`、`deletedAt` | 对应管理动作的时间；当前状态由 `status` 判断，不通过几个时间字段分别推测  |

保留当前“进行中”和“已归档”的界面文案。删除继续表示本地删除标记，不等于彻底删除原生 Harness 会话。恢复和彻底清除的交互按后续特性安排。

原生会话名称与归档状态保存在适配结果中，需带获取时间及同步结果；本地操作与原生操作的成功分别判断。未完成原生同步时，不用本地状态冒充原生已确认结果。

### 教师、阅读与扩展资源关联

| 字段或关联            | 含义与约束                                                                                           |
| --------------------- | ---------------------------------------------------------------------------------------------------- |
| `robotId`             | 对话关联的教师编号，建立后切换教师需要新对话                                                         |
| 教师身份快照          | 创建或首次确定教师时的名称与图标，保证教师改名或删除后仍能解释历史身份；每轮指令单独保存在执行快照中 |
| `readingContext`      | 对话的资料关联，至少包含资料或课程内容编号、固定版本和初始位置；普通对话为 `null`                    |
| 消息的 `referenceIds` | 某次问题实际引用的内容，不以当前阅读位置重算                                                         |
| Skill、RAG、记忆关联  | 由每轮执行记录实际使用的资源及版本，配置了但没有调用的资源不能记成已使用                             |

阅读关联不替代消息引用：对话可以源于某个章节，但每次问题引用的选段仍须分别记录。笔记与对话的关联通过稳定编号表达，不把笔记正文复制到会话元数据中。

教师被删除时保留历史编号和身份快照，并说明该教师不可用。不能把旧对话静默改成默认教师；继续使用另一位教师应按既定规则建立新对话。

## 4. 服务与模型如何记录

### 服务、连接与模型提供方

| 对象         | 记录内容                           | 示例含义                                                 |
| ------------ | ---------------------------------- | -------------------------------------------------------- |
| Harness 服务 | `providerId` 与注册描述            | DeepSeek Harness、Hermes、Codex                          |
| 本机连接     | `connectionId` 与配置版本          | 当前已有 `deepseek-local`、`hermes-local`、`codex-local` |
| 模型提供方   | Harness 明确给出的提供方编号或名称 | 某 Harness 配置中的模型供应方；无法取得时为空            |
| 模型         | 对应连接内的模型编号与显示名       | 实际选中的模型，不根据 Harness 名称推测                  |

通过 DSH 使用 GLM 时，Harness 服务与模型分别记录。模型目录里的分组名称不一定是稳定的提供方编号，适配器不能将其任意当成模型提供方身份。

对话的当前配置保存 `connectionId`、`modelId` 及可选的 `reasoningEffort`，类型见[教师默认与会话配置](metadata.md#教师默认与会话配置)。服务类型由该稳定连接确定，连接的服务类型不可原地改成另一种；新增服务产生另一项连接。

模型以连接编号与模型编号共同定位，新对话保存已经确定的选择。全局默认变化不改变已有对话的服务和模型；旧记录中无法确定的默认模型在实际提问前解析并保存。

服务和模型的显示名称可保存只读展示快照，带所对应的配置版本和获取时间，以便离线展示。调用和校验仍使用稳定编号；快照与当前配置不匹配时说明名称或配置尚未确认，不用显示名匹配模型。

### 当前选择与每轮记录

会话标题栏表达后续提问的当前选择。一轮回复的模型信息从该轮记录读取，不能用标题栏的当前选择覆盖历史。

| 信息                        | 记录时机             | 含义                                                                 |
| --------------------------- | -------------------- | -------------------------------------------------------------------- |
| 模型选择规则                | 保存会话配置时       | 当前对话确定的连接和模型，不根据新的全局默认重算                     |
| 请求模型与参数              | 本机接受本轮请求时   | 解析后准备使用的模型编号、当时显示名与推理参数                       |
| 提交给 Harness 的模型与参数 | 适配器形成实际请求时 | 实际写入原生接口的值；接口沿用原生默认值时明确记录未显式指定         |
| Harness 返回的模型          | 原生接口返回时       | 能取得的实际模型信息；未返回时为空，不能直接复制请求模型并标成已核实 |

如果原生模型设置使用的是别名或自动路由，按原值记录。无法确认底层具体模型版本时，不自行展开或推断。

## 5. 每轮执行的元数据

一条对话中可以先用模型 A，再用模型 B，因此每轮执行独立保存配置。执行编号也用于应答丢失后的查询和恢复，不能仅依靠消息文本判断是否调用过。

| 分类       | 关键字段或内容                                                | 保存规则                                                               |
| ---------- | ------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 编号关联   | `id`、`conversationId`、问题编号、回复编号                    | 本地执行编号稳定，关联同一轮消息和事件                                 |
| 配置依据   | 会话与教师的保存版本、连接编号与配置版本、模型目录版本        | 能说明这一轮依据哪版配置准备；后续设置变化不改写它                     |
| 教师快照   | 教师编号、名称、图标、角色指令                                | 保留本轮实际使用的值，不只记录可变的教师编号                           |
| 服务与模型 | Harness 类型、连接、请求与提交模型、返回模型及参数            | 区分请求信息和已确认结果，不编造返回值                                 |
| 学习内容   | 引用编号、固定内容版本、传递方式与结果                        | 能判断模型是否收到资料，只有不可访问的路径不算传递成功                 |
| 扩展资源   | 实际使用的 Skill、RAG、学习记忆编号与版本                     | 在相应能力实现后记录，不将开关开启等同于实际调用                       |
| 执行状态   | `status`、`phase`、结果版本或事件序号                         | 状态与阶段分开，旧事件不能覆盖新结果                                   |
| 原生关联   | 原生会话编号、原生执行编号、适用时的原生消息编号              | 始终与本轮连接关联，其他会话的通知不能混入                             |
| 时间       | 提交、服务接受、开始、首段正文、结束时间                      | 只记录可观测时间；由明确起止计算等待与响应耗时                         |
| 错误       | 稳定错误码、可读说明、发生阶段                                | 能判断是提交、连接、恢复、模型还是保存失败，不依靠解析错误文字判断     |
| 用量       | 原生返回的 token、费用及对应单位和来源                        | 仅在接口确实提供时记录；未知为空，不记为 0，不根据模型名估算成实际账单 |
| 运行版本   | 本轮的 SolveMate、客户端构建、本机服务、适配器及 Harness 版本 | 记录可取得的值，允许同一对话不同轮次来自不同运行版本                   |

请求快照固定后，原生应答与诊断结果可以逐步补充，但不覆盖已提交的请求信息。用量、版本或实际模型不可取得，不应导致普通提问无法执行。

SolveMate 版本、构建编号与数据格式版本分别表达：应用升级可以继续使用同一数据格式，数据库迁移也不能覆盖“创建时使用哪个版本”的记录。版本号沿用实际发布值；开发构建未提供构建编号时为空。

## 6. 原生绑定与软件自身信息的边界

`SessionBinding` 保存连接编号、协议、原生会话编号、绑定状态和已确认的原生管理结果。本机服务保留建立绑定时的程序位置、Harness 配置目录与工作目录；程序位置和配置目录用于说明当时的运行环境，不作为会话身份。继续对话时由适配器在当前连接中恢复原编号，使用保存的工作目录满足原生接口要求。找到并恢复成功就继续，失败保留原编号和记录并显示原因，不因路径变化直接拦截。适配器明确返回会话不存在时，询问用户是否重新发起；仅在确认后替换该服务的原生编号。普通界面通过绑定编号和状态使用这些记录。

`Conversation` 管理 SolveMate 的名称、标签、状态、教师关联与当前配置。`Turn` 保存调用事实和运行依据。三者通过本地对话编号关联，不要求 Harness 理解 SolveMate 的课程、标签或教师元数据。

一个服务缺少重命名或归档接口时，适配器明确报告对应能力；不删除 SolveMate 的管理信息，也不把该服务的原始字段扩散到所有页面。

元数据与普通导出不包含密钥、令牌或 Harness 凭据。机器用户名、完整本机路径和完整浏览器标识不作为每条对话必需记录。诊断若确实需要额外环境信息，应说明用途，不能把用户材料和完整协议通知无差别写入日志。

## 7. 更新和读取规则

1. 标题栏、AI 选择初始值与请求准备读取同一会话配置解析结果；历史回复读取对应执行快照。
2. 在对话中保存同一服务的模型或推理等级时，只更新当前对话及机器人默认选择，其他对话、原生 session 和历史执行不变。机器人页面修改默认选择只影响新对话。
3. 确认切换教师时创建新对话并记录来源。切换服务保留当前对话与消息，首次使用目标服务时建立原生会话，切回时恢复该服务原编号；取消不改变配置、消息和绑定。
4. 教师改名、删除或全局默认服务变化不改写历史身份和调用记录；无法继续使用时显示具体原因。
5. 修改标签、名称或归档状态更新管理信息，不改变最近聊天活动时间；新问题或回复更新聊天活动时间。
6. 消息数、最后一轮摘要和“是否正在生成”等信息由关联记录计算；需要缓存时带来源版本，不新增可独立修改的重复字段。

界面可以组合对话、绑定、模型目录和最后一轮结果用于展示。这个组合结果只读，不能反向作为一份完整会话记录覆盖原有对象。

## 8. 当前字段与迁移检查

| 当前字段或行为                                   | 目标处理                                                                                 |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `Conversation.id`、标题、标签、时间              | 保留稳定编号和已有输入；补齐明确来源与状态；旧时间不明时不填当前时间                     |
| `connectionId`、`bindings[]`、`turns[]` 中的连接 | 按连接编号保存各服务的绑定；同一连接的冲突记录须报告，不能任选第一项                     |
| `aiModel`、教师 `modelSource/modelName`          | 明确默认选择与具体模型编号；历史记录仅能证明请求模型时，不写成已确认实际模型             |
| `archived`、`archivedAt`、`deletedAt`            | 迁移为明确状态，保留已知操作时间；不顺带清除原生会话                                     |
| 会话 `example` 与消息 `example`                  | 保留示例来源；真实追问不把已有示例回复改成真实调用记录                                   |
| 删除教师时替换旧会话的 `robotId`                 | 与固定教师规则冲突，实施时改为保留关联和身份；已有原始教师信息优先依据执行及作者记录核实 |
| 缺少创建版本、构建编号和实际模型信息             | 保持未知，不用当前运行环境或默认模型补造历史                                             |

迁移前验证无 AI 对话、示例混合真实追问、单服务多模型、跨服务新旧对话、教师被删除、配置失效和中断执行等记录。字段定义、请求校验、保存操作、读取解析与迁移必须配套交付；只有新增字段不能算完成一致性整理。

## 9. 两端会话定位、管理与内容核对

本节确定会话定位与原生管理同步的设计。原编号恢复和检测会话占用处理已实现；会话信息界面、原生管理信息查询及外部历史读取按 `PLANS.md` 中的待办实施，不将下面的设计要求视为已交付功能。

### 会话身份与查询依据

一条正式对话通过连接编号和原生会话编号定位。标题、分组、时间和本机路径用于展示或诊断，不能据此认定两条记录是同一会话。重新配置同一服务仍查询原编号；不能因为标题相似而选择另一条会话，也不能在未找到时自动创建替代会话。

会话条目的“会话信息”提供服务名称、可复制的完整原生编号，以及能够查明的原生标题、归档状态、查询时间和具体错误。尚未建立绑定时显示“尚未建立第三方会话”。未知的信息留空并说明无法取得，不根据本地状态补造。读取结果只用于展示和相应操作，不再保存一套可独立修改的连接配置。

查询和恢复分别处理：

- 列表查询必须处理分页与筛选范围；列表可能省略正在加载或运行的会话，单次未命中不能证明原编号不存在。最终仍由适配器针对该编号尝试恢复。
- 查询标题、归档状态和历史使用已经核实的官方接口。接口缺失时说明限制，提供复制编号和人工定位的方法；“在 Harness 中打开”仅在有经过验证的打开方式时提供。
- 原生查询不可用、连接中断和会话被占用分别报告，不解释成会话丢失。服务返回其他编号时停止操作，保留原绑定。
- 用户反映两端内容不同时，先核对完整编号，再核对具体问题及对应回复。仅看见同名条目或记录文件，不能确认桌面端已显示正确内容。

### 名称、归档与外部修改

SolveMate 管理自己的名称、标签和进行中／已归档状态；适配器报告 Harness 已确认的管理结果。两端的名称和归档状态分别表达，外部修改不会静默覆盖本地记录。

| 情况                      | 处理规则                                                                                                                                       |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 两条原生会话同名          | 显示并复制原生编号，以编号定位；检测会话与正式会话不能混用                                                                                     |
| 在 SolveMate 中重命名     | 先保存本地名称，已绑定的会话通过适配器同步改名；只有原生操作成功才提示已同步。不支持时说明仅本地保存，失败时保留新名称和错误，允许再次保存重试 |
| 新对话的首条问题          | 用户问题作为提交文本的开头，教师要求与资料作为独立段落随本轮交付，避免固定指令前缀被用作原生标题；不能据此承诺之后的标题同步                   |
| 在 Harness 中归档         | 已查明时显示原生归档状态与查看办法；不当成删除，不因此另建会话，也不自动取消用户在 Harness 中的归档                                            |
| 本地进行中、原生已归档    | 分别显示两端状态；能否继续仍由原生接口确定，桌面端能否查看另行说明。恢复归档由用户明确操作                                                     |
| 在 SolveMate 中归档或恢复 | 本地操作沿用既定规则；原生操作有明确接口时记录各自结果，部分失败仍保留真实状态与重试入口                                                       |
| 原生会话被删除            | 保留本地历史与原编号，明确提示无法恢复；用户选择新建时才建立新对话                                                                             |
| 无法读取原生管理状态      | 保持未知，不能按本地状态推断原生是否归档、删除或改名                                                                                           |

当前 DSH ACP 的 `session/list` 返回编号和工作目录，会省略该 ACP 进程已加载的会话；没有返回桌面标题、归档状态或完整历史。桌面归档可以使条目隐藏或无法查看，与 ACP 是否能恢复该编号分别判断。人工诊断中读取 DSH 本地记录获得的事实，不作为产品已具备通用查询接口的依据；不直接修改其配置、索引或日志来实现管理同步。

### 原生会话改名

网页保存本地名称后，向 `PUT /local-api/v1/conversations/{id}/native-title` 提交名称、连接编号与原生会话编号。本机服务与已保存绑定核对后调用对应适配器；不按名称查找、不创建会话、不通过模型生成标题。不增加持久化字段，现有绑定与历史执行快照保持原值。

| 服务             | 当前适配方式                                                                                                                                                                                                             |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| DeepSeek Harness | 当前 ACP 没有会话改名接口，返回不支持，网页提示名称仅在本地保存                                                                                                                                                          |
| Hermes           | 调用[官方 CLI](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md#rename-a-session)的 `hermes sessions rename <id> -- <title>`；参数分别传递，沿用当前 `HERMES_HOME`，不发送消息 |
| Codex            | 调用[App Server](https://learn.chatgpt.com/docs/app-server)的 `thread/name/set`，参数为 `threadId` 和 `name`；仅初始化管理连接，不恢复、创建线程或发起模型请求                                                           |

无原生编号的本地对话只保存本地名称；首次提问前改名不因此创建原生会话，也不承诺之后自动同步。已绑定但本机绑定丢失或不一致时保留本地名称并提示失败，不猜测对应关系。连接停用、删除、程序不可用、原生接口拒绝、原会话不存在及超时均不能显示已同步。超时可能已生效，明确说明结果未确认，用户可查看原名称或重试同一名称。

同一会话生成期间或改名尚未完成时，拒绝并发原生改名；改名期间拒绝该会话的新提问及连接配置变更。管理操作有超时，取消或超时后关闭本次创建的进程。改名使用当前可用工作目录，不要求原工作目录仍存在。失败不改变绑定状态，不触发重新检测或创建替代会话。

2026-11-11：Hermes 专用测试会话完成真实改名并恢复原名，前后消息完全一致。Codex 使用模拟进程核对协议和失败清理，未运行本机 Codex；安装版本不支持该方法时会显示失败。

### 删除范围与原生接口

SolveMate 删除对话前统一提示：“当前操作仅删除本对话记录，原会话仍可在第三方 AI Harness 软件中查看。”用户确认后只将本地对话标记为已删除并移出列表，保留原生绑定，不调用第三方删除接口；取消不执行删除，保存失败时保留确认框与错误说明。

2026-11-11 核对的官方接口及本机源码如下，接口具备删除能力不表示 SolveMate 已接入：

| 服务             | 删除能力                                                                                                                                                                                     | 当前接入情况                                                                     |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| DeepSeek Harness | [ACP 官方说明](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.zh.md)明确不支持删除；`session/close` 只释放会话                                          | 当前 ACP 适配器不能删除原生会话                                                  |
| Hermes           | [官方 CLI](https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/sessions.md#delete-a-session)提供 `hermes sessions delete <id>`；本机 `sessions_cmd.py` 有对应实现 | 当前 ACP 适配器没有删除入口；后续可单独适配 CLI，不能将停止或结束会话当作删除    |

本次只核对能力，不执行真实删除。后续接入原生删除前，须核实安装版本、完整原生编号、运行或占用状态，以及对子会话的影响范围；由用户明确选择是否同时删除第三方会话，并分别报告两端结果。不能以归档代替删除，也不直接改写第三方数据文件。

### 占用、停用与检测

同一原生会话是否允许多个进程同时操作，由 Harness 决定。适配器只管理 SolveMate 创建的进程及其句柄，不能强制解锁、结束用户的 Harness 进程，或用新编号绕过占用。

- 停用连接关闭本服务持有的运行时，保留配置、原编号和记录；启用只恢复使用权限，不自动检测、不新建会话。与检测结果有关的使用限制继续依据实际错误处理。
- 正式会话被占用只影响该会话；检测会话被占用只影响该次检测。不能将它们扩散为其他会话或整项服务失效。
- 检测沿用已有专用编号。会话被占用时等待用户解除占用；会话未找到或创建结果不明时明确提示，只有用户确认后才重建检测会话。
- 一轮完成或停止后，在原生接口确认执行结束、记录已保存且支持释放时，释放对应会话的写入句柄，并更新本进程的加载记录。释放失败显示原因，不宣称已经释放，也不结束用户的其他进程。
- 超时和断线先恢复已有执行结果。无法确定提问是否已接受时保留未知结果，按原执行编号查询，不自动重发问题；明确查无记录或拒绝提交后才允许手动重试。

### 问题、回复与历史的对应

学生原问题、教师指令与资料引用分别保存。AI 管理组织本轮内容，适配器转换为对应服务的实际输入；共同的提问规则不在各适配器中重复实现。核对两端用户消息时，应能解释原问题与实际提交文本的对应关系，不能把附带指令和资料误认为另一条问题。

一轮执行可能包含多条教师消息和工具操作。服务能够提供稳定消息编号或明确边界时，保留消息顺序、正文与本轮执行的关联；服务只提供文字块时按顺序合并，不能把每个流式文字块当作独立消息。界面可以按统一规则呈现，但不能遗漏中间说明、重复拼接完整快照，或将工具结果和思考正文混入教师回答。

恢复原生会话与读取原生历史分别验收。用户在 Harness 中新增的消息，只有通过已验证的历史接口读取并去重后才合并到本地；不回传这些消息给原生服务。接口无法读取历史时，明确本地记录的范围，不宣称两端已完整同步，也不覆盖本地草稿、已完成回复或当前配置。

### 验收场景

| 场景                                       | 必须核对的结果                                                         |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| 新建、追问、换模型、刷新及重启             | 原生编号稳定；各轮问题、实际提交内容和回复可对应；不重复创建或回放问题 |
| 程序或配置目录变化、连接删除再配置         | 仍恢复原编号；原生条件不满足时保留记录并说明原因                       |
| 列表分页、工作目录筛选、已加载会话未列出   | 不因单次列表未命中宣告会话丢失，仍针对原编号恢复                       |
| 标题重复、原生改名或归档                   | 以编号定位，分别说明原生与本地状态，不误认同名测试会话                 |
| 桌面端与 SolveMate 交替使用同一会话        | 能释放时正确释放；被占用时提示；解除占用后继续原编号                   |
| 停用、启用后检测；检测会话被占用或丢失     | 不自动增建测试会话；保留其他正式会话的可用性；解除占用后复用原编号     |
| 原生接口没有提供管理或历史信息             | 显示未知与具体限制，不伪造已同步状态，不静默修改原生文件               |
| 一轮多段回答、工具前后说明、重复或乱序通知 | 正文顺序与内容完整，去重正确，不将协议分段误认为不同对话               |
| 外部新增消息、原生删除、读取失败           | 有接口时正确读取并去重；无接口或失败时保留已保存记录与原绑定           |
| 请求超时、停止与结果不明                   | 已收到内容保留，状态如实表达，不自动重复提问或更换会话                 |
| 测试与排查结束                             | 只操作显式登记的测试编号；用户正式会话、归档状态和记录保持原样         |

普通回归测试使用协议替身；真实验证只使用独立存储和专用测试编号，不调用 Codex。测试清理不按标题、分组、目录或时间批量处理第三方会话。一次协议恢复成功、界面出现同名条目或本地存在文件，均不能替代问题、回复和界面的对应核对。
