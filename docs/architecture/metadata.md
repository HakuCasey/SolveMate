# 模块元数据与数据结构设计

## 1. 目标与范围

SolveMate 的资料阅读、AI 管理、知识维护与数据管理使用统一的数据定义。界面从这些对象读取内容和状态，业务逻辑校验对象关系并执行操作，数据管理负责保存与读取。各模块不再为同一业务对象分别定义一套含义不同的字段。

元数据描述对象的身份、来源、版本、关联、配置与处理状态。资料正文、PDF 原件、图片和回复正文按各自内容类型保存，通过明确引用与元数据关联。文件无需全部转换成同一种格式，也不将所有数据装入一个任意扩展的 JSON 字段。页面布局与样式继续由组件实现，业务字段、状态和可用操作依据共享定义计算。

AI 配置与对话部分已通过 [006 特性](../features/006-ai-conversation-metadata/spec.md)实现共享定义、前后端校验和旧数据迁移。007 已增加上传资料、固定版本、页码位置和文字引用，002 与 007 已将社区和上传资料统一为同一种 `Material`。四个模块、工程目录、`data/` 与 `user/` 的职责保持现有安排，不在本次迁移中增加账户隔离。

## 2. 共用定义与更新规则

### 定义放在哪里

跨模块、跨前后端使用的数据定义由现有 `packages/contracts/` 承载。AI 配置与对话以 `ai-metadata.schema.json` 定义共享字段、类型、必填条件和结构版本。`npm run contracts:generate` 生成 TypeScript 类型和 Python 包使用的 Schema 副本，`npm run check` 检查同步；浏览器使用 Ajv，Python 使用 jsonschema 校验相同定义。

FastAPI 继续生成 HTTP 接口的 OpenAPI，本机 AI 接口直接引用上述共享对象。数据库行、HTTP 请求、页面展示结果可以有各自的结构，但转换关系必须明确，不能分别改变同一字段的含义。仅在模块内部使用的进程句柄、组件状态等对象保留在实现内部。

JSON Schema 支持结构定义与引用，不能代替跨记录关联校验、权限判断或业务事务。基础机制参考 [JSON Schema 结构与引用](https://json-schema.org/understanding-json-schema/structuring)及 [OpenAPI 3.1.1 Schema Object](https://spec.openapis.org/oas/v3.1.1.html#schema-object)。

### 标识、版本与空值

| 字段或规则               | 含义                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `id`                     | 稳定编号。名称、路径和排序变化不改变编号；现有有效编号继续保留        |
| `schemaVersion`          | 数据格式版本，用于判断是否需要迁移                                    |
| `revision`               | 可修改记录的保存版本，用于检查并发冲突；写入携带期望的旧版本          |
| `contentVersion`         | 资料或发布内容的固定版本；与普通记录的保存版本分开                    |
| `createdAt`、`updatedAt` | 使用 UTC Unix 毫秒时间戳；只在需要这些时间的对象上定义                |
| 外部编号                 | 与 `connectionId` 一起保存，不同 Harness 的原生编号不能直接比较或互换 |
| `null`                   | 已知没有值，例如普通对话没有阅读关联；必填可空字段使用 `null`         |
| 缺少字段                 | 用于明确允许的可选项或旧格式迁移，不能同时表示继承、未配置和读取失败  |

继承配置使用带 `kind` 的明确类型，避免通过空字符串猜测。内部共享结构使用现有 TypeScript 的 camelCase；社区内容服务现有的 snake_case 协议由边界转换保留，不批量改名。

### 身份、名称与来源

同类内容遵循[一致的交互原则](overview.md#同类内容采用一致的交互)：通过稳定 ID 建立关联和匹配更新，不使用名称识别对象，也不因社区或用户来源不同而提供不同的通用操作。

名称是可修改的展示属性。资料统一使用 `Material.title`；社区更新保留用户修改的名称。教研工具的本地名称仍使用 `customTitle`。各页面从同一对象读取显示名称，引用继续使用原 ID 与必要的版本、位置。来源用于判断下载、更新、发布等操作的实际条件，不作为禁止重命名等通用操作的依据。

### 数据的几种用途

| 用途       | 示例                                   | 修改原则                                         |
| ---------- | -------------------------------------- | ------------------------------------------------ |
| 已保存记录 | 机器人配置、会话配置、资料目录         | 通过所属业务模块的操作校验和保存                 |
| 编辑草稿   | 尚未确认的服务、未保存的角色指令       | 不参与实际请求；取消或关闭按该编辑流程的规则处理 |
| 历史快照   | 一轮提问使用的模型、机器人指令、资料引用 | 发起后不随当前配置改变                         |
| 运行状态   | 检测结果、回复阶段、下载进度           | 明确来源、更新时间与失败原因，不等同于已保存配置 |
| 展示结果   | 服务与模型标签、按钮是否可用、禁用原因 | 统一计算，不作为另一份可编辑配置保存             |

例如，对话标题栏、AI 选择气泡和提问请求使用同一份当前会话配置解析结果。展示名称来自该连接的模型目录，发送给 Harness 的仍是原始模型编号。

## 3. 模块与主要对象

业务模块负责字段的含义、约束和操作规则，数据管理提供相应的存取接口。数据管理的共享职责不意味着它统一决定所有业务行为。

| 模块     | 主要对象                                                                   | 提供给其他模块的内容                                     |
| -------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 数据管理 | 资料、资料版本、文件、派生内容、处理任务                                   | 资料查询、固定版本读取、文件访问、引用内容读取及记录保存 |
| 资料阅读 | 阅读状态、内容位置、提问引用                                               | 当前阅读对象、位置与用户确认的引用内容                   |
| AI 管理  | 服务描述、连接、模型目录、机器人、会话、原生绑定、消息、执行、工具及权限请求 | 可用配置、会话操作、真实执行结果和状态                 |
| 知识维护 | 内容目录、发布版本、安装记录、机器人模板、Skill 与 RAG 资源描述            | 可发现、校验、安装和更新的公开内容                       |

对象之间通过稳定编号关联。可发布内容与个人配置分别建模；安装机器人模板后产生独立的本地机器人编号，不能把远程模板直接作为用户的可编辑机器人对象。

## 4. 数据管理

### 资料、版本与文件

社区下载与用户上传生成同一种 `Material`。来源只影响如何取得文件、查询发布版本，不改变重命名、移动、删除、阅读和引用规则。

| 对象 | 字段 | 含义 |
| --- | --- | --- |
| `Material` | `id`、`title`、`subjectId`、`kind` | 稳定编号、显示名称、所属学科，以及学习资料或题目集；未分类为 `subjectId: null` |
| `Material` | `source`、可选的 `publisher` | `personal` 或 `community`；社区发布编号用于匹配下载更新，不受本地改名和移动影响 |
| `Material` | `currentVersion`、`revision`、`createdAt`、`updatedAt`、`deletedAt` | 当前阅读版本、并发保存版本、创建及修改时间、列表删除标记 |
| `MaterialVersion` | `contentVersion`、`mediaType`、`originalAssetId`、`readerAssetId`、`storagePath` | 固定内容版本、文件类型、原文件、按需生成的阅读文件及存储位置 |
| `MaterialVersion` | `filename`、`sizeBytes`、`sha256`、`pageCount` | 文件信息与页数；题目集没有页数 |
| `MaterialVersion` | `status`、`error`、`processor`、`processorVersion` | 文件处理结果；处理失败保留原件，允许重试 |

当前用户数据目录的 `app.sqlite3` 中，`materials` 表保存资料属性，`material_versions` 表以资料编号和版本为联合主键保存版本记录。接口返回资料及其所选版本，历史读取使用明确指定的版本。原文件位于同一数据目录下的 `uploads/` 或 `community/`，路径由本机服务处理。浏览器仅缓存接口返回的记录和已读取内容。

`MaterialRepository` 统一处理记录修改、修订检查和版本切换，`Materials` 负责文件读取、上传与转换。社区课程包登记可用版本后，用户的更新操作只修改所选资料的 `currentVersion`；同包其他资料、用户修改的名称和学科保持不变。社区目录读取这份资料记录生成按钮和名称，不另存一套本地状态。

资料删除保留记录与文件，供既有对话和笔记按原编号、版本读取。学科删除与所属资料的删除标记在同一数据库事务内提交。已经移到其他学科的资料不受影响。

### 现有记录转换

首次转换前使用 SQLite 备份接口保存数据库。上传目录中的 `record.json` 和应用记录中的 `officialMaterials` 转换为统一资料记录，保留已有编号、名称、归属、删除状态与版本。转换在事务中完成；成功后不再读写这两处元数据，原 JSON 文件仅作保留副本。

已知的课程位置转换为资料编号、固定版本和页码或题号，对话正文、原生会话绑定、笔记正文与来源不变。阅读进度的索引同步转换，缩放和滚动值保留。不能明确定位的记录继续提示不支持，不按名称猜测或替换为最新内容。备份恢复和浏览器记录导入复用同一转换规则。

## 5. 资料阅读

### 位置与阅读状态

阅读位置统一使用 `MaterialLocation`：`materialId`、`contentVersion`，再指定 `pageNumber` 或 `questionId`，二者只选其一。PDF 与 PPTX 的阅读 PDF 使用从 1 开始的页码，题目集使用题号。新对话和消息引用使用此结构；`ReadingSelection` 仅保留在社区目录转换和既有记录读取边界。

`reading/state.ts` 在应用层统一管理阅读状态：`documents` 按资料及版本保存缩放、连续阅读开关与最后位置，`positions` 按页码或题号保存滚动位置和答案展开状态。显示参数保存到应用记录的 `readingProgress`；临时选区和待发送片段只属于当前窗口。学科阅读、教研室和返回对话使用同一个资料阅读器。

### 提问引用

`ReadingReference` 保存引用标题、`material: MaterialLocation` 与发送所需内容。默认关联当前页时保存该页正文；用户指定多个页码时保存 `pageNumbers`，不重复保存逐页文字。`readingContext` 保存本轮参考范围，`references` 保存用户添加的片段，最多四条。引用随消息固定保存；翻页、资料改名或版本更新不会改写已经发送的范围和正文。

临时选区不写入正式记录。笔记来源只保存资料或对话的编号与位置，不复制引用原文。PDF/PPTX 和题目引用由同一本机资料接口校验和读取；无文字、文件缺失或版本不存在时说明原因，不替换为其他版本。文件附件、图片识别等能力不由文字引用推断。

## 6. AI 管理

### 服务、连接与模型目录

| 对象                           | 关键字段                                                                        | 约束                                               |
| ------------------------------ | ------------------------------------------------------------------------------- | -------------------------------------------------- |
| `ServiceDescriptor` 服务描述   | `providerId`、`name`、`shortName`、`adapterId`                                  | 由适配器注册，不由页面拼接判断                     |
| `Connection` 本机连接          | `id`、`providerId`、程序或端点配置、默认模型、`enabled`、`check`、`revision`    | 编号与服务名称分开；已有连接编号保留               |
| `ConnectionDetection` 检测结果 | `connectionId`、被检测配置版本、`detectedAt`、`status`、`capabilities`、`error` | 对应明确的一版配置；程序或配置改变后需重新确认     |
| `ModelCatalog` 模型目录        | `connectionId`、`catalogRevision`、模型条目、获取时间                           | 模型编号只在对应连接内解释，名称仅用于显示         |
| `ModelDescriptor` 模型条目     | `id`、`name`、分组、可选参数及支持值                                            | 来自实际运行时；不能补造推理选项等支持值           |
| `GlobalAiPreference` 全局偏好  | `defaultModel`、`revision`                                                      | 默认模型明确引用连接编号和模型编号，不复制整份配置 |

模型、恢复、流式、重命名和归档等能力分别记录 `supported`、`unsupported`、`unknown`。未知不等于支持，协议未暴露也不直接等于整个产品不支持。界面据此说明可用操作，后端执行时再次校验实际条件。

连接元数据可以描述程序位置和必要配置引用；凭据不进入普通共享对象、日志或导出。Harness 继续管理其已有凭据；后续接入 API 时单独设计密钥存储，不通过通用扩展字段传递密钥。

### 外部连接与内部选择

服务的已连接／未连接状态、检测、删除配置及全局默认模型的调整按 [003 连接管理规则](../features/003-ai-harness-connection/design.md#连接模型与进程状态机)实施。

左下角“设置 → AI 配置”展示适配器支持目录，每项服务只显示已连接或未连接。检测成功后保存连接及真实模型目录；删除配置时释放本应用持有的会话和进程，不移除支持目录中的服务，不删除历史对话和原生会话。

机器人与对话通过“AI 选择”（大脑图标）从已连接服务中选择模型及推理等级。“AI 配置”（CPU 图标）管理外部服务连接及全局默认，两者读取同一份连接记录和模型目录。原选择及历史绑定持续保留，服务未连接时显示原因。全局默认模型保存明确的 `defaultModel: { connectionId, modelId } | null`；连接最后选中的模型不能间接改写默认。连接失效或删除配置会清空相关全局默认，重连不自动恢复。

本机响应的 `AiConnection.state` 统一为 `connected` 或 `disconnected`；旧 `enabled` 与 `check` 在兼容读取时转换，不作为另一个启停开关。`AiSettings.enabled` 仅保留兼容用途。旧默认连接转换为模型引用时保留原编号，目录不足时说明不可用，不丢弃历史选择。

页面共用一份 AI 配置结果，按偏好版本和连接版本拒绝过期响应。表单仅保存未提交字段，背景刷新不覆盖这些输入；路径未编辑时，不能因刷新后的路径文本变化而要求重新检测。

### 机器人默认与会话配置

机器人沿用代码中的 `Robot` 名称。当前格式为 3：

```typescript
interface AiSelection {
  connectionId: string | null;
  modelId: string | null;
  reasoningEffort?: string | null;
}

type RobotAiDefaults = AiSelection | null;
type ConversationAiConfig = AiSelection;
```

- `Robot.aiDefaults` 为 `null` 时使用当前全局默认；有值时保存独立的连接、模型及可选推理等级。用户直接选择服务与模型，界面不再提供“模型来源”等中间选项。
- 即使独立选择与全局当前值相同，也保留其独立身份。点击“使用全局配置”并保存才清除独立选择。
- `Conversation.aiConfig` 使用同一 `AiSelection` 结构，保存当前对话确定的连接、模型及推理等级。旧记录缺少等级时兼容原有设置。新对话从机器人配置取得明确值，全局默认改变不重写已有对话。
- 尚未配置的对话可以没有连接或模型。迁移无法确定的旧默认模型保留 `modelId: null`，待原连接的模型目录可用后解析，在实际提问前保存明确编号；不能用当前模型补造历史执行信息。
- 自选模型只在所属连接中解释。旧记录无法确认连接时保留模型编号并提示重新选择，不能匹配另一服务的同名模型。
- 同一服务内变更模型保留原生会话；切换机器人经确认后建立新对话；切换服务经确认后保留当前对话，各服务分别保存原生会话关联。

聊天气泡与机器人页面共用字段和解析规则。在对话中保存同服务的模型或推理等级时，由同一个业务操作更新机器人默认与当前对话，不改写其他对话。机器人页面修改默认选择只影响新对话；历史执行快照保持原值。切换服务时确认后更新当前对话的 AI 选择和机器人默认，保留消息及各服务的原生会话关联；切回已有服务时恢复原编号。确认与取消规则见 [003 规格](../features/003-ai-harness-connection/spec.md#多服务接入中的对话切换规则)。

`ModelSelection` 仅用于兼容已保存的执行快照，不再作为机器人和会话当前选择的数据结构。

### 会话、绑定与执行

对话自身的身份、管理信息、服务与模型、单轮调用依据及运行版本详见[对话元数据设计](conversation-metadata.md)。本节说明主要对象与共同约束。

| 对象                | 关键字段                                                                                       | 数据含义                                           |
| ------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `Conversation`      | `id`、`robotId`、`aiConfig`、标题、标题来源、标签、归档或删除状态、`revision`                  | 本地对话及后续提问配置，阅读关联可空               |
| `SessionBinding`    | `conversationId`、`connectionId`、协议、原生会话编号、`state`、`revision`                      | 一条对话的一份正式外部绑定，首次实际提问时建立     |
| `Message`           | `id`、`conversationId`、`turnId`、角色、正文或内容引用、`referenceIds`、创建时间               | 问题或回复；助手消息保留当时的作者和模型信息       |
| `Turn`              | `id`、`conversationId`、问题编号、回复编号、配置快照、状态、阶段、结果、错误、时间、`revision` | 一轮执行；重试新问题使用新编号，结果恢复沿用原编号 |
| `ToolExecution`     | `id`、`turnId`、工具名称、状态、结果摘要                                                       | 工具过程，不冒充机器人正文                         |
| `PermissionRequest` | `id`、`turnId`、操作内容、可选决定、有效状态                                                   | 限定本次操作或本轮，过期与已处理请求不能再次批准   |
| `LegacyProbeRecord` | 旧版连接检测保存的配置标识和会话编号                                                           | 仅用于读取既有数据库；当前连接检测不写入或使用     |

正式绑定的 `state` 区分待建立、建立中、已绑定、创建结果不明、恢复失败和明确不存在（`missing`）。每条对话的 `bindings[]` 按 `connectionId` 保存各服务的原生编号、状态和修订号；`aiConfig.connectionId` 确定当前选择。旧单项 `binding` 在读写时转为集合，不同时维护两份绑定。创建结果不明时不能自动再建；仅在适配器明确返回会话不存在、用户确认后替换对应服务的绑定。占用、超时和不支持恢复均保留原编号。

程序路径和 Harness 配置目录不参与会话身份判断。适配器使用原生编号恢复会话；删除后重新配置同一服务，仍尝试恢复原编号。未找到会话、原生恢复条件不满足和连接故障分别报错，保留历史记录。当前 DSH、Hermes 与 Codex 的连接检测只读取程序状态、配置和模型目录，不创建或恢复第三方会话。

未创建原生 session 时，已选择的连接仍属于会话配置，不能通过是否存在 session 决定显示哪个服务。会话业务操作校验归档和删除状态，界面据此限制输入。本机执行入口独立校验绑定、机器人、并行执行和请求快照。若要由本机接口直接管理或限制归档后的提问，需同时接入会话状态的读取与更新，不能仅增加前端字段就认定本机已完成校验。

`Turn` 配置快照至少包含连接编号与配置版本、服务与协议、请求模型与提交参数、机器人编号及当时名称和指令、会话配置版本、本次交付的资料引用。Harness 返回的实际模型信息单独记录，未返回时保持未知。创建后请求信息固定，正文与执行状态继续按本轮结果更新。

执行状态沿用 `running`、`completed`、`failed`、`cancelled`、`interrupted`；连接中、等待、正文接收、工具与权限等属于阶段。停止请求不会直接伪造“已取消”；收到适配器确认或进程中断、错误结果后才记录实际状态。

统一事件携带本地执行编号、适用时的原生执行编号，以及单调增加的事件序号或结果版本。历史事件不能把已结束执行改回运行中，也不能覆盖较新的正文。原生通知由适配器转换，页面不解析特定提供方的字段。

### 展示与草稿

AI 配置统一解析为连接编号、服务名称、模型编号及名称、配置版本和不可用原因。标题栏、表单初始值和提问准备共用该结果。

聊天气泡草稿属于该次打开的表单，记录编辑对象和起始 `revision`。确认框保存待执行操作的数据，取消时不应用修改；再次打开根据已保存会话配置重新建立草稿。机器人页面在当前窗口按机器人编号保留名称和角色等未提交输入，不将表单内容保存为历史草稿。

已保存数据被其他窗口修改时，提交操作检查版本并提示重新读取。旧草稿不能覆盖新配置；保存失败保留输入并显示原因，不标记为成功。

## 9. 哪份记录决定实际值

| 数据                         | 当前存储与目标写入归属                 | 其他位置如何使用                                       |
| ---------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 连接配置、默认连接与模型目录 | 本机服务；连接业务操作写入             | 浏览器读取版本化结果，草稿不直接覆盖它                 |
| 机器人与会话当前配置 | 当前用户数据目录的 `app.sqlite3`；统一业务操作写入 | 浏览器缓存并统一解析，本机 AI 服务接收经校验的当轮快照 |
| 原生绑定                     | 本机服务；适配器返回原生编号后登记     | 浏览器缓存已确认结果，不能独立修改原生编号             |
| 单轮执行结果                 | 本机服务保存真实状态、正文和版本       | 浏览器按执行编号合并展示与离线记录，冲突时核对本机结果 |
| 社区发布信息                 | 社区发布工具与内容服务                 | 客户端保存固定清单和安装记录，不改写发布内容           |
| 阅读位置和偏好 | 当前用户数据目录的 `app.sqlite3`；公共存储接口写入 | 浏览器缓存；当前页面、菜单和弹窗仍由各窗口管理 |
| 用户原件与派生文件 | 当前用户数据目录的 `uploads/`；资料服务写入 | 页面与 AI 模块通过稳定编号及版本读取 |
| 教研工具与当前选择 | 当前用户数据目录中 `app.sqlite3` 的 `questionResearch` | 工具目录决定当前配置，消息和执行保留发送时的内容 |

浏览器数据库与本机数据库之间不能假定有共同事务。发起问题时，客户端先通过本机记录服务保存问题、引用和待提交执行编号，再提交到本机 AI 执行接口；本机按同一编号校验、保存并返回接受结果。应答丢失时先查询该编号，不能直接再次调用模型。流程需区分待提交、服务已接受和提交结果不明，避免仅用运行状态表达全部情况。

迁移保存位置时保留对象编号和上述归属约束，通过正式迁移完成；不能让两份副本独立决定同一字段。

## 10. 操作、事务与异常

界面通过明确的业务操作修改记录，不在多处直接赋值。操作携带对象编号、期望版本和必要输入，返回已保存对象或具体失败结果。下表说明需集中实现的操作，不预先规定 HTTP 路由。

| 操作               | 必须一起处理的内容                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| 保存 AI 选择       | 校验已连接服务、模型和推理等级；保存机器人默认及指定的当前对话；保留其他角色草稿               |
| 确认切换机器人或服务 | 校验待切换对象仍有效；机器人切换建立新对话，服务切换保留当前对话及各服务绑定；取消不产生正式变更 |
| 提交问题           | 检查归档、删除与并行执行；固定配置和引用；保存稳定执行编号；本机再次校验绑定和能力             |
| 重命名、归档或删除 | 校验状态；区分本地结果与 Harness 确认结果，不支持或失败时不能宣称已同步                        |
| 导入或更新资料     | 保存原件与处理状态；完整内容可用后切换版本；失败保留可用旧内容                                 |
| 继续或恢复会话     | 核对本地、连接和原生编号；明确找不到时由用户确认是否新建；其他恢复失败保留原编号并说明原因     |

同一存储中的相关字段以一个事务提交。外部操作与本地写入分步记录状态，收到相应结果后才显示完成。操作已发出但结果不明时提供查询与恢复，不能静默换服务、换模型或新建会话。

配置可用性在显示时检查，执行时再次检查。目录变化、配置被外部修改、原件丢失和空间不足都应有具体错误，保留旧记录、草稿及已完成结果。

## 11. 实施顺序与验收

先整理 AI 配置与会话，随后让资料导入和阅读使用相同约定。知识维护在现有课程发布约定上扩展，不为尚无实际需求的对象预建空模块。

1. 核对现有字段与目标对象的对应关系，列出有歧义或无法安全迁移的旧记录。
2. 在共享包落实首批 Schema、类型、边界校验与迁移，保留有效编号和历史会话。
3. 集中实现配置解析和保存操作，替换页面中的零散合并逻辑，按相应特性验证。
4. 实现上传资料、固定版本、阅读位置与引用，让同一引用贯穿阅读、问题和执行记录。
5. 按发布与扩展特性补充模板、Skill、RAG 和学习记忆，只有描述的资源不视为已接入能力。

首批验收检查：

- 标题栏、选择框和请求使用同一会话配置；取消、关闭、刷新和返回旧会话后保持一致。
- 不同连接中的模型不会串用；模型被移除时保留原选择并显示不可用原因。
- 切换后新旧对话保留正确身份、配置和绑定，历史模型与机器人快照不变。
- 保存冲突与失败不覆盖较新记录、不丢失草稿，也不显示成功。
- 事件与请求应答乱序、重复或中断时，执行不会重复发起，旧状态不会覆盖新状态。
- 迁移能解释每项字段的来源，无法确认的绑定或模型不被默认值替代。
- 后续资料验收覆盖版本、阅读位置、引用快照与实际交付内容的对应关系。

实施按全局特性管理。本文维护共用对象与约束；需求、迁移范围、测试结果和完成状态记录在相应特性中。

## 007 的资料实现范围

共享 Schema 已定义 `Material`、`MaterialVersion`、`MaterialLocation` 和扩展后的 `ReadingReference`。资料记录包含原件及阅读文件编号、校验值、处理状态、页数与错误；文件编号在资料固定版本内解析。当前采用原子替换的 JSON 记录与文件目录，不将已有浏览器数据库或 AI SQLite 合并。独立的通用文件索引和多版本派生内容管理按后续需求实施。

会话的 `material` 保存最近一次提问时的 `MaterialLocation`；`selection` 只在旧记录读取和社区包转换边界使用，新记录统一写入 `material`。新消息与执行通过 `readingContext` 保存本轮当前页正文，或保存用户明确选择的 `pageNumbers`；后者在发送时由本机服务解析固定版本的 PDF 路径，路径不持久化。`references` 数组保存最多四条手动补充片段，各条保留自己的原位置；旧记录的单条 `reference` 只在读取时转换。选区本身仅属于阅读器，确认添加后才写入应用层草稿，提问时固定并保存引用数组。

当前引用统一保存资料编号、固定版本和页码或题号，对话选段保存对话与消息编号。缺少必要位置时提示不支持；资料缺失不阻止读取其余记录。

## 008 的学科分类

`Subject` 以稳定编号关联资料并保存名称及删除标记；`AppData.subjects` 与个人记录一起保存。未指定目录的旧记录沿用社区分类，新下载内容补入未登记的编号。重命名只修改显示名称，资料编号、内容版本、文件与历史引用保持不变。

学科分类与社区内容包分别管理；新建学科不生成内容包。学科页面、上传选择及资料归类共用同一目录。删除学科时以 `materialsDeleted` 标记一并移除其上传资料条目，原件及历史记录继续保留。未设置该字段的旧删除记录及缺失分类的资料仍按原规则显示在未分类中。具体规则见 [008](../features/008-subject-management/design.md)。

学科与资料的界面联动使用 `SubjectDirectory`，由同一份学科记录派生完整目录、可用选项和编号索引，不分别保存各个页面的选项。资料归属统一区分已归类、未分类和已移除；上传返回逐文件结果。请求顺序、保存顺序及失败处理见 [008 技术设计](../features/008-subject-management/design.md)。

## 社区 PDF 阅读位置

社区与上传资料的新记录统一使用 `MaterialLocation`。当前 PDF 引用必须包含资料编号、固定版本和页码，题目引用必须包含资料编号、固定版本和题号；其他记录方式提示“当前版本已不支持该引用方式”，不推断或补全。逐页文字、页码和 PDF 路径来自同一个已校验的资料版本。默认引用保存实际页码与内容快照；指定页码保存页码集合并在发送时解析受管理的 PDF；历史记录继续定位原版本。

## 社区资料采用的版本

每份社区资料的元数据包含独立的 `version` 和 `updatedAt`。稳定编号与学科归属不随更新变化；下载同一课程包不会把其他条目切换到新版。版本字段缺省的旧记录在首次相关下载前保留原版本，显式的 `null` 表示尚未添加。阅读、日期、按钮状态和历史版本判断都使用该条目的版本，更新提示比较该资料对应文件的校验值。

## PDF 阅读模式

`readingProgress.documents` 按资料和固定版本保存 `zoom`、可选的 `continuous` 及最后位置。`continuous` 缺省时使用连续阅读，显式 `false` 使用单页模式。页内滚动仍保存在原位置表中，坐标相对页面记录；模式切换、缩放和滚动不维护第二份阅读位置。PDF 阅读器的滚动事件与页码导航通过相同的位置回调保存。
