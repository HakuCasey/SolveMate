# 模块元数据与数据结构设计

## 1. 目标与范围

SolveMate 的资料阅读、AI 管理、知识维护与数据管理使用统一的数据定义。界面从这些对象读取内容和状态，业务逻辑校验对象关系并执行操作，数据管理负责保存与读取。各模块不再为同一业务对象分别定义一套含义不同的字段。

元数据描述对象的身份、来源、版本、关联、配置与处理状态。教材正文、PDF 原件、图片和回复正文按各自内容类型保存，通过明确引用与元数据关联。文件无需全部转换成同一种格式，也不将所有数据装入一个任意扩展的 JSON 字段。页面布局与样式继续由组件实现，业务字段、状态和可用操作依据共享定义计算。

AI 配置与对话部分已通过 [006 特性](../features/006-ai-conversation-metadata/spec.md)实现共享定义、前后端校验和旧数据迁移。007 已增加用户资料、版本、页码位置和文字引用，扩展资源等对象继续按特性逐步实施。四个模块、工程目录、`data/` 与 `user/` 的职责保持现有安排，不在本次迁移存储或增加账户隔离。

## 2. 共用定义与更新规则

### 定义放在哪里

跨模块、跨前后端使用的数据定义由现有 `packages/contracts/` 承载。AI 配置与对话以 `ai-metadata.schema.json` 定义共享字段、类型、必填条件和结构版本。`npm run contracts:generate` 生成 TypeScript 类型和 Python 包使用的 Schema 副本，`npm run check` 检查同步；浏览器使用 Ajv，Python 使用 jsonschema 校验相同定义。

FastAPI 继续生成 HTTP 接口的 OpenAPI，本机 AI 接口直接引用上述共享对象。数据库行、HTTP 请求、页面展示结果可以有各自的结构，但转换关系必须明确，不能分别改变同一字段的含义。仅在模块内部使用的进程句柄、组件状态等对象保留在实现内部。

JSON Schema 支持结构定义与引用，不能代替跨记录关联校验、权限判断或业务事务。基础机制参考 [JSON Schema 结构与引用](https://json-schema.org/understanding-json-schema/structuring)及 [OpenAPI 3.1.1 Schema Object](https://spec.openapis.org/oas/v3.1.1.html#schema-object)。

### 标识、版本与空值

| 字段或规则               | 含义                                                                  |
| ------------------------ | --------------------------------------------------------------------- |
| `id`                     | 稳定编号。名称、路径和排序变化不改变编号；现有有效编号继续保留        |
| `schemaVersion`          | 数据格式版本，用于判断是否需要迁移                                    |
| `revision`               | 可修改记录的保存版本，用于检查并发冲突；写入携带期望的旧版本          |
| `contentVersion`         | 资料或发布内容的固定版本；与普通记录的保存版本分开                    |
| `createdAt`、`updatedAt` | 使用 UTC Unix 毫秒时间戳；只在需要这些时间的对象上定义                |
| 外部编号                 | 与 `connectionId` 一起保存，不同 Harness 的原生编号不能直接比较或互换 |
| `null`                   | 已知没有值，例如普通对话没有阅读关联；必填可空字段使用 `null`         |
| 缺少字段                 | 用于明确允许的可选项或旧格式迁移，不能同时表示继承、未配置和读取失败  |

继承配置使用带 `kind` 的明确类型，避免通过空字符串猜测。内部共享结构使用现有 TypeScript 的 camelCase；官方内容服务现有的 snake_case 协议由边界转换保留，不批量改名。

### 数据的几种用途

| 用途       | 示例                                   | 修改原则                                         |
| ---------- | -------------------------------------- | ------------------------------------------------ |
| 已保存记录 | 教师配置、会话配置、资料目录           | 通过所属业务模块的操作校验和保存                 |
| 编辑草稿   | 尚未确认的服务、未保存的角色指令       | 不参与实际请求；取消或关闭按该编辑流程的规则处理 |
| 历史快照   | 一轮提问使用的模型、教师指令、资料引用 | 发起后不随当前配置改变                           |
| 运行状态   | 检测结果、回复阶段、下载进度           | 明确来源、更新时间与失败原因，不等同于已保存配置 |
| 展示结果   | 服务与模型标签、按钮是否可用、禁用原因 | 统一计算，不作为另一份可编辑配置保存             |

例如，对话标题栏、AI 选择气泡和提问请求使用同一份当前会话配置解析结果。展示名称来自该连接的模型目录，发送给 Harness 的仍是原始模型编号。

## 3. 模块与主要对象

业务模块负责字段的含义、约束和操作规则，数据管理提供相应的存取接口。数据管理的共享职责不意味着它统一决定所有业务行为。

| 模块     | 主要对象                                                                   | 提供给其他模块的内容                                     |
| -------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 数据管理 | 资料、资料版本、文件、派生内容、处理任务                                   | 资料查询、固定版本读取、文件访问、引用内容读取及记录保存 |
| 资料阅读 | 阅读状态、内容位置、提问引用                                               | 当前阅读对象、位置与用户确认的引用内容                   |
| AI 管理  | 服务描述、连接、模型目录、教师、会话、原生绑定、消息、执行、工具及权限请求 | 可用配置、会话操作、真实执行结果和状态                   |
| 知识维护 | 内容目录、发布版本、安装记录、教师模板、Skill 与 RAG 资源描述              | 可发现、校验、安装和更新的公开内容                       |

对象之间通过稳定编号关联。可发布内容与个人配置分别建模；安装教师模板后产生独立的本地教师编号，不能把远程模板直接作为用户的可编辑教师对象。

## 4. 数据管理

### 资料、版本与文件

| 对象                       | 关键字段                                                                                 | 约束                                                                         |
| -------------------------- | ---------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `Material` 资料            | `id`、`title`、`courseId`、`source`、`currentVersion`、`revision`                        | 课程关联可空；改名不影响引用；切换当前版本不改写历史版本                     |
| `MaterialVersion` 资料版本 | `materialId`、`contentVersion`、`mediaType`、`originalAssetId`、`createdAt`              | 资料编号与版本组合唯一；版本指向的原始内容固定                               |
| `Asset` 文件记录           | `id`、`storageRef`、`mediaType`、`sizeBytes`、`sha256`                                   | 路径由存储实现解释，界面通过接口读取；编号与文件名分开                       |
| `DerivedContent` 派生内容  | `id`、`materialId`、`contentVersion`、`assetId`、`kind`、`processor`、`processorVersion` | 文本提取、页面图片等结果能追溯原版本和处理方式，重新处理不覆盖历史引用的结果 |
| `ProcessingJob` 处理任务   | `id`、`materialId`、`contentVersion`、`operation`、`status`、`resultIds`、`error`        | 区分等待、处理、成功、失败和取消；成功需要实际结果，重试范围明确             |

`source` 记录 `personal`、`official` 或 `community`，并按来源保存发布者和来源内容编号。随应用提供、下载和导入属于取得方式，另记为 `bundled`、`downloaded`、`imported`，不与内容来源混用。用户导入资料不会自动变成社区开源资料。

导入时先保存原件与待处理记录。解析失败可以保留已保存的原件，分别显示“原件已保存”和“解析失败”；只有原件保存失败时才提示未保存。哪些格式必须解析、采用何种处理工具，由文件类型验证确定。

已有课程、教材、章节、题目和课程记忆继续使用相应结构，不将一道题强制转换成文件。资料读取接口将现有课程版本与内容编号解析为可引用对象。`M001` 之类的条目编号以课程和版本为范围，不能直接当作全局唯一编号。

### 个人记录与存储

会话、教师和阅读记录的业务含义由所属模块定义，存取接口统一处理结构校验、事务与冲突。存储位置由实现决定，业务代码不拼接文件目录。

现有浏览器个人数据库、浏览器内容数据库和 `user/ai/state.sqlite3` 不在本次合并。007 将用户原件、阅读文件、按页文字与处理状态保存到 `user/materials/`，网页以接口访问并另存阅读缓存；官方源文件继续在 `data/`。发版前的数据目录分离仍按 `PLANS.md` 单独安排。

## 5. 资料阅读

### 位置与阅读状态

`ContentLocator` 用带 `kind` 的类型表达位置。具体支持项随资料类型实施，新增枚举不表示已经具备相应阅读能力。

| `kind`       | 关键字段                                   | 适用对象                                               |
| ------------ | ------------------------------------------ | ------------------------------------------------------ |
| `chapter`    | `chapterId`、可选的段落编号                | 现有教材章节                                           |
| `question`   | `questionId`                               | 现有题目                                               |
| `page`       | `pageNumber`、可选的页内滚动比例           | PDF 等分页内容                                         |
| `text-range` | 基础位置、文本表示编号、起止偏移与原文摘录 | 可选中文字；偏移为固定文本表示的 UTF-16 编码单元       |
| `region`     | 基础位置、`x`、`y`、`width`、`height`      | 页面或图片区域；左上角为原点的归一化坐标，记录旋转角度 |

页码从 1 开始；页码标签可另存，例如课本印刷页码“iii”。文本偏移不能跨不同解析结果直接复用，Python 与浏览器采用相同的偏移约定，并验证中文和补充平面字符。图片区域指向固定版本与具体页面，坐标范围需校验。

网页的 `reading/state.ts` 使用 `ReadingState` 在应用层统一保存当前打开期间的阅读现场：`documents` 按资料及固定版本保存缩放与最后位置，`positions` 按题目、章节或页码保存双向滚动、答案展开和引用草稿。阅读器只读取和更新该状态；从学科打开和返回对话共用恢复规则。现有 `AppData.selection`、`materialSelection` 和会话关联继续保存内容身份，不复制整份现场。关闭或完整刷新后仍保留显示参数的持久化方案尚未实施；届时需明确版本校验、修订号和更新时间。

### 提问引用

`ContentReference` 以 `id` 标识一次固定引用，至少保存 `materialId`、`contentVersion`、`locator`，并关联提问时确定的以下信息：

- 资料编号、固定版本、内容位置，以及当时的标题或页码标签。
- 选中的文字或区域，并关联实际使用的文本表示或派生文件。
- 可交给 AI 的内容快照或固定文件引用；正文和大文件通过内容记录关联。

提问前的选区是临时状态；随消息保存的引用是历史快照。引用进入正式消息后，翻页、资料改名或更新版本都不能改变其内容。

阅读器说明用户选中了什么，AI 管理确认服务实际收到了什么。每轮执行记录交付方式、引用编号及成功或失败结果；AI 无法访问的路径、未完成的 OCR 或转换不能标记为已交付。007 已验证有文字层 PDF 和 PPTX 的当前页、选段文字引用；图片和文件附件的传递仍需另行验证。

## 6. AI 管理

### 服务、连接与模型目录

| 对象                           | 关键字段                                                                        | 约束                                                       |
| ------------------------------ | ------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `ServiceDescriptor` 服务描述   | `providerId`、`name`、`shortName`、`adapterId`                                  | 由适配器注册，不由页面拼接判断                             |
| `Connection` 本机连接          | `id`、`providerId`、程序或端点配置、默认模型、`enabled`、`check`、`revision`    | 编号与服务名称分开；已有连接编号保留                       |
| `ConnectionDetection` 检测结果 | `connectionId`、被检测配置版本、`detectedAt`、`status`、`capabilities`、`error` | 对应明确的一版配置；程序或配置改变后需重新确认             |
| `ModelCatalog` 模型目录        | `connectionId`、`catalogRevision`、模型条目、获取时间                           | 模型编号只在对应连接内解释，名称仅用于显示                 |
| `ModelDescriptor` 模型条目     | `id`、`name`、分组、可选参数及支持值                                            | 来自实际运行时；不能补造推理选项等支持值                   |
| `GlobalAiPreference` 全局偏好  | `defaultConnectionId`、`revision`                                               | 默认连接使用引用，不复制整份连接配置；连接启用状态独立保存 |

模型、恢复、流式、重命名和归档等能力分别记录 `supported`、`unsupported`、`unknown`。未知不等于支持，协议未暴露也不直接等于整个产品不支持。界面据此说明可用操作，后端执行时再次校验实际条件。

连接元数据可以描述程序位置和必要配置引用；凭据不进入普通共享对象、日志或导出。Harness 继续管理其已有凭据；后续接入 API 时单独设计密钥存储，不通过通用扩展字段传递密钥。

### 外部连接与内部选择

左下角“设置 → AI 配置”负责外部系统接入：查看支持目录、检测程序、取得模型目录、保存连接、启用或停用连接，以及单独指定全局默认。保存某项连接不改变已有全局默认；首次配置可将该连接设为默认。停用默认连接时保留其默认身份并显示不可用，不自动改用其他服务。

机器人与对话只从已保存、启用且没有检测失败的连接中选择服务与模型，不使用接入目录，也不提供安装和检测操作。已选择的连接失效时保留编号和模型，显示具体原因；恢复、重新检测或重新选择由用户明确操作。检测失败保留已保存配置与模型目录。确认删除连接后，移除其配置；默认引用若指向该连接则清空，不自动换成其他连接。教师和对话保留原引用并显示已删除，消息与原生绑定不删除。仅保留删除编号、版本和时间，重新配置时继续递增版本，拒绝旧窗口覆盖或删除新配置。

`AiConnection.enabled` 表示用户是否启用这项连接，`check` 保存最近一次检测的状态、时间和原因。`ready` 只表示连接及目录查询通过，不承诺账号额度或模型实际响应。`AiSettings.enabled` 是“是否有启用连接”的兼容投影，不作为教师与对话的全局开关。

### 教师默认与会话配置

教师沿用代码中的 `Robot` 名称。当前格式为 3：

```typescript
interface AiSelection {
  connectionId: string | null;
  modelId: string | null;
}

type RobotAiDefaults = AiSelection | null;
type ConversationAiConfig = AiSelection;
```

- `Robot.aiDefaults` 为 `null` 时使用当前全局默认；有值时保存独立的连接和模型，不分别继承两部分。用户直接选择服务与模型，界面不再提供“模型来源”等中间选项。
- 即使独立选择与全局当前值相同，也保留其独立身份。点击“使用全局配置”并保存才清除独立选择。
- `Conversation.aiConfig` 保存当前对话确定的连接与模型。新对话从教师配置取得明确值，全局默认改变不重写已有对话。
- 尚未配置的对话可以没有连接或模型。迁移无法确定的旧默认模型保留 `modelId: null`，待原连接的模型目录可用后解析，在实际提问前保存明确编号；不能用当前模型补造历史执行信息。
- 自选模型只在所属连接中解释。旧记录无法确认连接时保留模型编号并提示重新选择，不能匹配另一服务的同名模型。
- 同一服务内变更模型保留原生会话；切换教师或服务经确认后建立新对话。

聊天气泡与机器人页面共用字段和解析规则。保存教师同服务的模型变更时，由同一个业务操作更新教师默认与该教师同服务的会话配置；历史执行不变。切换服务时保留原会话的配置和绑定，确认后保存教师默认并创建新对话。确认与取消规则见 [003 规格](../features/003-ai-harness-connection/spec.md#多服务接入中的对话切换规则)。

`ModelSelection` 仅用于兼容已保存的执行快照，不再作为教师和会话当前选择的数据结构。

### 会话、绑定与执行

对话自身的身份、管理信息、服务与模型、单轮调用依据及运行版本详见[对话元数据设计](conversation-metadata.md)。本节说明主要对象与共同约束。

| 对象                | 关键字段                                                                                       | 数据含义                                           |
| ------------------- | ---------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `Conversation`      | `id`、`robotId`、`aiConfig`、标题、标题来源、标签、归档或删除状态、`revision`                  | 本地对话及后续提问配置，阅读关联可空               |
| `SessionBinding`    | `conversationId`、`connectionId`、协议、原生会话编号、`state`、`revision`                      | 一条对话的一份正式外部绑定，首次实际提问时建立     |
| `Message`           | `id`、`conversationId`、`turnId`、角色、正文或内容引用、`referenceIds`、创建时间               | 问题或回复；助手消息保留当时的作者和模型信息       |
| `Turn`              | `id`、`conversationId`、问题编号、回复编号、配置快照、状态、阶段、结果、错误、时间、`revision` | 一轮执行；重试新问题使用新编号，结果恢复沿用原编号 |
| `ToolExecution`     | `id`、`turnId`、工具名称、状态、结果摘要                                                       | 工具过程，不冒充教师正文                           |
| `PermissionRequest` | `id`、`turnId`、操作内容、可选决定、有效状态                                                   | 限定本次操作或本轮，过期与已处理请求不能再次批准   |
| `ProbeBinding`      | 连接编号、被检测配置标识、专用会话编号、创建状态                                               | 检测专用；无需检测会话的服务不产生记录             |

正式绑定的 `state` 区分待建立、建立中、已绑定、创建结果不明和恢复失败。创建结果不明时不能自动再建；恢复失败不能用新编号替代旧编号。一条对话固定一项服务，目标结构只保存一份正式绑定；当前 `bindings[]` 中若有互相冲突的绑定，迁移时报告冲突，不能任选第一项。

程序路径和 Harness 配置目录不参与会话身份判断。适配器使用原生编号恢复会话；删除后重新配置同一服务，仍尝试恢复原编号。未找到会话、原生恢复条件不满足和连接故障分别报错，保留历史记录。专用连接测试会话丢失只影响该次检测，不将其他正式会话标为不可用。

未创建原生 session 时，已选择的连接仍属于会话配置，不能通过是否存在 session 决定显示哪个服务。会话业务操作校验归档和删除状态，界面据此限制输入。本机执行入口独立校验绑定、教师、并行执行和请求快照。若要由本机接口直接管理或限制归档后的提问，需同时接入会话状态的读取与更新，不能仅增加前端字段就认定本机已完成校验。

`Turn` 配置快照至少包含连接编号与配置版本、服务与协议、请求模型与提交参数、教师编号及当时名称和指令、会话配置版本、本次交付的资料引用。Harness 返回的实际模型信息单独记录，未返回时保持未知。创建后请求信息固定，正文与执行状态继续按本轮结果更新。

执行状态沿用 `running`、`completed`、`failed`、`cancelled`、`interrupted`；连接中、等待、正文接收、工具与权限等属于阶段。停止请求不会直接伪造“已取消”；收到适配器确认或进程中断、错误结果后才记录实际状态。

统一事件携带本地执行编号、适用时的原生执行编号，以及单调增加的事件序号或结果版本。历史事件不能把已结束执行改回运行中，也不能覆盖较新的正文。原生通知由适配器转换，页面不解析特定提供方的字段。

### 展示与草稿

AI 配置统一解析为连接编号、服务名称、模型编号及名称、配置版本和不可用原因。标题栏、表单初始值和提问准备共用该结果。

聊天气泡草稿属于该次打开的表单，记录编辑对象和起始 `revision`。确认框保存待执行操作的数据，取消时不应用修改；再次打开根据已保存会话配置重新建立草稿。机器人页面的完整草稿按教师保存，保留名称和角色等未保存输入。

已保存数据被其他窗口修改时，提交操作检查版本并提示重新读取。旧草稿不能覆盖新配置；保存失败保留输入并显示原因，不标记为成功。

## 7. 知识维护

| 对象                        | 关键字段                                                               | 约束                                                   |
| --------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------ |
| `CatalogEntry` 内容目录项   | 编号、类型、标题、发布者、来源、课程关联、授权信息、最新发布版本       | 官方与社区分别记录来源；公开可访问不等于允许再发布     |
| `ContentRelease` 发布版本   | 编号、固定版本、格式版本、文件清单、校验值、兼容要求、发布时间         | 已发布版本不可覆盖；不同发布者的相同编号需要来源限定   |
| `InstalledContent` 安装记录 | 本地编号、来源内容编号、版本、取得方式、安装时间、状态                 | 记录已完整校验的版本，下载进度与当前可用版本分开       |
| `RobotTemplate` 教师模板    | 模板编号与版本、名称、角色指令、资源依赖                               | 安装产生独立教师并保留来源；模板更新不直接覆盖用户修改 |
| `SkillDescriptor` 能力资源  | 编号、版本、说明、兼容适配器、必要权限、入口描述                       | 安装描述不表示已经可以执行，调用需验证对应能力接口     |
| `RagCollection` 知识库      | 编号、来源资料及版本、索引版本、检索配置、处理状态                     | 索引与原始资料分别记录；旧索引不能标记为已经更新       |
| `LearningMemory` 学习记忆   | 编号、作用范围、内容、来源引用或执行编号、生成方式、采用状态、替代关系 | 课程与个人记忆分开；AI 生成内容保留依据和纠正记录      |

现有教材、题目、记忆点与讨论点继续作为课程内容发布。Skill、RAG、模板和自动学习记忆在此定义必要关联，具体发布格式、调用接口和采用流程按后续特性细化，不表示能力已实现。

安装先下载、校验并保存完整版本，再以事务切换当前可用版本。失败时当前版本不变，失败原因属于本次安装任务。历史对话使用固定版本引用，不随最新内容更新。

## 9. 哪份记录决定实际值

| 数据                         | 当前存储与目标写入归属                 | 其他位置如何使用                                       |
| ---------------------------- | -------------------------------------- | ------------------------------------------------------ |
| 连接配置、默认连接与模型目录 | 本机服务；连接业务操作写入             | 浏览器读取版本化结果，草稿不直接覆盖它                 |
| 教师与会话当前配置           | 当前浏览器个人数据库；统一业务操作写入 | 页面统一解析，本机接收经校验的当轮快照                 |
| 原生绑定                     | 本机服务；适配器返回原生编号后登记     | 浏览器缓存已确认结果，不能独立修改原生编号             |
| 单轮执行结果                 | 本机服务保存真实状态、正文和版本       | 浏览器按执行编号合并展示与离线记录，冲突时核对本机结果 |
| 官方发布信息                 | 官方发布工具与内容服务                 | 客户端保存固定清单和安装记录，不改写发布内容           |
| 阅读位置和偏好               | 当前浏览器存取接口                     | 本机服务不另存一份可独立修改的相同设置                 |
| 用户原件与派生文件           | 后续用户资料存取实现                   | 页面与 AI 模块通过文件、资料引用读取                   |

浏览器数据库与本机数据库之间不能假定有共同事务。发起问题时，浏览器先保存问题、引用和待提交执行编号，再提交到本机服务；本机按同一编号校验、保存并返回接受结果。应答丢失时先查询该编号，不能直接再次调用模型。流程需区分待提交、服务已接受和提交结果不明，避免仅用运行状态表达全部情况。

迁移保存位置时保留对象编号和上述归属约束，通过正式迁移完成；不能让两份副本独立决定同一字段。

## 10. 操作、事务与异常

界面通过明确的业务操作修改记录，不在多处直接赋值。操作携带对象编号、期望版本和必要输入，返回已保存对象或具体失败结果。下表说明需集中实现的操作，不预先规定 HTTP 路由。

| 操作               | 必须一起处理的内容                                                                   |
| ------------------ | ------------------------------------------------------------------------------------ |
| 保存教师 AI 配置   | 校验连接和模型；保存教师默认；按规则更新同一服务的会话配置；保留其他角色草稿         |
| 确认切换教师或服务 | 校验待切换对象仍有效；保存必要配置并建立新对话；旧记录和绑定不变；取消不产生正式变更 |
| 提交问题           | 检查归档、删除与并行执行；固定配置和引用；保存稳定执行编号；本机再次校验绑定和能力   |
| 重命名、归档或删除 | 校验状态；区分本地结果与 Harness 确认结果，不支持或失败时不能宣称已同步              |
| 导入或更新资料     | 保存原件与处理状态；完整内容可用后切换版本；失败保留可用旧内容                       |
| 继续或恢复会话     | 核对本地、连接和原生编号；恢复失败报错，不能用新 session 替代                        |

同一存储中的相关字段以一个事务提交。外部操作与本地写入分步记录状态，收到相应结果后才显示完成。操作已发出但结果不明时提供查询与恢复，不能静默换服务、换模型或新建会话。

配置可用性在显示时检查，执行时再次检查。目录变化、配置被外部修改、原件丢失和空间不足都应有具体错误，保留旧记录、草稿及已完成结果。

## 11. 实施顺序与验收

先整理 AI 配置与会话，随后让资料导入和阅读使用相同约定。知识维护在现有课程发布约定上扩展，不为尚无实际需求的对象预建空模块。

1. 核对现有字段与目标对象的对应关系，列出有歧义或无法安全迁移的旧记录。
2. 在共享包落实首批 Schema、类型、边界校验与迁移，保留有效编号和历史会话。
3. 集中实现配置解析和保存操作，替换页面中的零散合并逻辑，按相应特性验证。
4. 实现用户资料、固定版本、阅读位置与引用，让同一引用贯穿阅读、问题和执行记录。
5. 按发布与扩展特性补充模板、Skill、RAG 和学习记忆，只有描述的资源不视为已接入能力。

首批验收检查：

- 标题栏、选择框和请求使用同一会话配置；取消、关闭、刷新和返回旧会话后保持一致。
- 不同连接中的模型不会串用；模型被移除时保留原选择并显示不可用原因。
- 切换后新旧对话保留正确身份、配置和绑定，历史模型与教师快照不变。
- 保存冲突与失败不覆盖较新记录、不丢失草稿，也不显示成功。
- 事件与请求应答乱序、重复或中断时，执行不会重复发起，旧状态不会覆盖新状态。
- 迁移能解释每项字段的来源，无法确认的绑定或模型不被默认值替代。
- 后续资料验收覆盖版本、阅读位置、引用快照与实际交付内容的对应关系。

实施按全局特性管理。本文维护共用对象与约束；需求、迁移范围、测试结果和完成状态记录在相应特性中。

## 007 的资料实现范围

共享 Schema 已定义 `Material`、`MaterialVersion`、`MaterialLocation` 和扩展后的 `ReadingReference`。资料记录包含原件及阅读文件编号、校验值、处理状态、页数与错误；文件编号在资料固定版本内解析。当前采用原子替换的 JSON 记录与文件目录，不将已有浏览器数据库或 AI SQLite 合并。独立的通用文件索引和多版本派生内容管理按后续需求实施。

会话可选的 `material` 保存最近一次提问时的资料版本和页码；现有 `selection` 仍用于课程教材、题目，两者不混用。用户文件的消息引用使用 `selection: null` 和固定的 `material` 位置，正文是提问时的文字快照。新消息与执行通过 `references` 数组保存多个片段，各条保留自己的原位置；旧记录的单条 `reference` 继续读取。选区本身仅属于阅读器，确认添加后才写入应用层草稿，提问时固定并保存引用数组。

## 008 的学科分类

`Subject` 以稳定编号关联用户资料和课程入口，保存名称及删除标记；`AppData.subjects` 与个人记录一起保存。未指定目录的旧记录沿用官方分类，新下载课程补入未登记的编号。重命名只修改显示名称，资料编号、课程内容版本、文件与历史引用保持不变。

学科分类与官方课程包分别管理；新建学科不生成课程包。侧栏、列表标题、上传选择及资料归类共用同一目录。删除学科时以 `materialsDeleted` 标记一并移除其上传资料条目，原件及历史记录继续保留。未设置该字段的旧删除记录及缺失分类的资料仍按原规则显示在未分类中。具体规则见 [008](../features/008-subject-management/design.md)。

学科与资料的界面联动使用 `SubjectDirectory`，由同一份学科记录派生完整目录、可用选项和编号索引，不分别保存各个页面的选项。资料归属统一区分已归类、未分类和已移除；上传返回逐文件结果。请求顺序、保存顺序及失败处理见 [008 技术设计](../features/008-subject-management/design.md)。
